    First program: connect, read position, disconnect¶

    • You need the simulator or a controller
    • Read first Installation, Simulator
    • You will have a program that connects, reads the position and disconnects

    This page follows sample 01-connect. It does four things: initialize, connect, read axis A's position, disconnect. Each language's complete project is under samples/ and builds and runs as is:

    Language Project Run
    C# samples/csharp/01-Connect 01-Connect.exe 172.1.1.101
    C++ samples/cpp/01-connect sample01_connect 172.1.1.101
    Python samples/python/01_connect.py python 01_connect.py 172.1.1.101

    The argument is a controller IP or the absolute path of firmware_sim.exe — anything ending in .exe connects to the simulator.

    Step 1: initialize¶

    Initialization does two things: it creates the controller object for your controller model, and it makes sure AACommServer is running. It also attaches the error hook, called whenever the controller refuses a command.

    LocaleProvider.Instance.Locale = "zh-CN";
MotionController c = AAMotionAPI.Initialize(type);
c.ErrorOccurred += (code, sent, text) =>
    Console.WriteLine($"[ERR {code}] {sent} | {text.Replace("\n", " | ")}");

    static void on_error(int code, const char* message, const char* exception, void* user)
{
    std::fprintf(stderr, "[ERR %d] %s | %s\n", code, message ? message : "", exception ? exception : "");
}

if (aamotion_abi_version() != AAMOTION_ABI_VERSION)
{
    std::fprintf(stderr, "aamotion.h and the aamotion library come from different SDK versions\n");
    return 1;
}
aamotion_controller h = aamotion_initialize(AAMOTION_CONTROLLER_TYPE_AGM800);
if (!h)
{
    std::fprintf(stderr, "initialize failed: is AACommServerNative beside the library?\n");
    return 1;
}
aamotion_set_error_occurred_handler(h, on_error, nullptr);

    @am.ERROR_CB
def on_error(code, message, exception, user):
    print(f"[ERR {code}] {(message or b'').decode()} | {(exception or b'').decode()}")

h = am.initialize(am.CONTROLLER_AGM800)
if not h:
    sys.exit("initialize failed: is AACommServerNative beside the library?")
am.lib.aamotion_set_error_occurred_handler(h, on_error, None)  # keep on_error referenced

    Line by line:

    • LocaleProvider.Instance.Locale = "zh-CN" (C# only): error descriptions in Chinese. The C interface always reports them in English.
    • The controller model must match the real controller (AGM800, AGD301, …). The SDK checks it on connect and fails on a mismatch.
    • The ABI check (C++): aamotion.h and aamotion.dll must come from the same SDK version, or function arguments may not line up.
    • The error hook gets the error code, the command that was sent and the formatted description. In C the two strings are valid only during the callback; copy them to keep them.

    Python: keep the callback referenced

    on_error is a ctypes function pointer. If Python collects it, the next controller error calls into freed memory and the process crashes. The sample keeps it as a module-level variable for the whole run.

    Where the server is found¶

    During initialization the SDK looks for AACommServer in this order and starts the first one it finds. Pick a deployment to see where the search ends:

    Why Python switches the working directory¶

    For Python the "application folder" is python.exe's folder, which has no server. So the samples' aamotion.py switches the working directory to aamotion.dll's folder for the moment of initialization, letting the SDK find the server there in step 3, then switches back:

    def initialize(controller_type):
    """aamotion_initialize, run from the library's folder.

    The SDK starts AACommServerNative from the application folder or the current working
    directory. A Python process's application folder is the interpreter's, so the server is
    found through the working directory, switched to the library's folder for this call.
    Returns the handle, or None when the server could not be started or reached.
    """
    here = os.getcwd()
    os.chdir(os.path.dirname(_path))
    try:
        return lib.aamotion_initialize(controller_type)
    finally:
        os.chdir(here)

    Step 2: connect¶

    bool ok;
if (target.EndsWith(".exe", StringComparison.OrdinalIgnoreCase))
{
    if (!Path.IsPathRooted(target) || !File.Exists(target))
    {
        Console.WriteLine("The simulator path must be an absolute path to firmware_sim.exe");
        return 2;
    }
    c.Init();
    ok = AAMotionAPI.ConnectSimulation(c, target);
}
else
{
    ok = AAMotionAPI.Connect(c, target);
}
Console.WriteLine($"Connect {target}: {ok}");
if (!ok)
    return 1;

    bool ok = ends_with_exe(target)
    ? aamotion_connect_simulation(h, target.c_str(), "AGM800", nullptr, nullptr)
    : aamotion_connect(h, target.c_str(), false, false);
std::printf("Connect %s: %s\n", target.c_str(), ok ? "true" : "false");

    if target.lower().endswith(".exe"):
    ok = am.lib.aamotion_connect_simulation(h, target.encode(), b"AGM800", None, None)
else:
    ok = am.lib.aamotion_connect(h, target.encode(), False, False)
print(f"Connect {target}: {ok}")
    • Hardware: Connect(c, ip). The C function's third argument fastArk really means "do not enable PC-side TCP immediate ACK": pass false to enable it. With many commands and large replies it speeds things up markedly; see Connecting.
    • Simulator: ConnectSimulation needs the absolute path of firmware_sim.exe — the server starts the simulator from its own folder, so a relative path is not found. In C#, call c.Init() first so the server is up.
    • A failed connect returns false, it does not throw. The reason is in the error hook and the logs.

    The SDK does a lot during connect: handshake, controller identity, message table… The first connect to new firmware is slower; see Connecting.

    Step 3: read the position¶

    Console.WriteLine("Firmware: " + c.CommAPI.IdentityContainer.Versions.FirmwareVersionStr);
ISingleAxis a = c.GetAxis(AxisRef.A);
Console.WriteLine($"APos = {a.Pos}");

    double pos = 0;
if (aamotion_get_value(h, AAMOTION_AXIS_REF_A, AAMOTION_KEYWORD_POS, 0, &pos))
    std::printf("APos = %.3f\n", pos);

    print("APos =", am.get_value(h, am.AXIS_A, am.KEYWORD_POS))

    In C#, a.Pos is a property: each read sends one APos to the controller. The C interface uses the generic aamotion_get_value: axis + keyword constant + array index. The SDK talks to the controller by keyword name; the number behind a constant like AAMOTION_KEYWORD_POS is an SDK-internal identifier, not the controller's CAN code. Every keyword is in the Keyword reference.

    With User Units enabled on the axis the value comes back converted (millimetres, say); otherwise it is in encoder counts.

    Step 4: disconnect¶

    AAMotionAPI.Disconnect(c);

    aamotion_disconnect(h);

    am.lib.aamotion_disconnect(h)

    The C# sample disconnects in finally, so it disconnects even if the read throws. In C, aamotion_disconnect also frees the handle: to connect again, call aamotion_initialize again.

    Disconnecting does not close AACommServer: another program (PCSuite, say) may still use it. The server exits by itself after its last client leaves.

    Output¶

    Example output (your firmware version will differ):

    > 01-Connect.exe 172.1.1.101
Connect 172.1.1.101: True
Firmware: 5.3.0
APos = 0

    When it cannot connect:

    > 01-Connect.exe 172.1.1.199
Connect 172.1.1.199: False
    Symptom Check first
    Initialize fails / returns NULL the server is not on the lookup path; for C/C++/Python, is AACommServerNative beside the library
    Connect returns false after ~10 s IP, subnet, cable, firewall; the dial lines in AACommServer_DebugLogs
    Network fine but connect returns false the controller model differs from the one given to Initialize: the SDK reads the model and compares
    Python OSError loading the library 32-bit Python; AAMOTION_SDK_DIR
