    ConfigureDataLogger¶

    string ConfigureDataLogger(MotionController.DataLoggerConfiguration config)

    先用 ConfigureDataLogger 配置，再用 StartDataRecording 启动。用 GetDataRecordingStatus 查看记录状态，或用 WaitForDataRecordingToEnd 等待记录结束。拿到完整记录后再上传。

    见 PCSuite DataLogger 控件与参数对照。

    状态值 含义
    0 无有效记录
    1 正在填充预触发数据
    2 预触发区已填满，等待触发
    3 已触发，正在采集
    4 完整采集，正常结束
    5 采集中被停止
    6 触发前被停止
    C# 上传接口 何时使用
    UploadDataLoggerData 一次性上传，期间占用通信。适合数据量小或固件不支持分包时。
    UploadDataLoggerDataNonblocking 分包上传，其他命令可在包之间穿插。调用方仍会等到上传结束或超时。
    StartUploadDataLoggerDataNonblocking 后台分包上传，通过回调收结果。适合调用方需要立即继续工作的场合。

    采集过程中可用 GetDataLoggerTotalDataCount 查询总量，用 ReadDataLoggerIncrementalData(out int dataCount) 查询控制器报告的增量计数。该重载只返回计数和错误文本，波形值由上传接口提供。

    分步记录与上传

    SDK 说明： Configures a data recording session; MotionController.StartDataRecording starts it.

    参数 类型 方向 默认值 说明
    config MotionController.DataLoggerConfiguration 输入（值传递） 必传 记录配置

    返回类型： string

    返回说明： Error string if failed, empty string on success

    返回字符串的方法成功时返回空字符串，失败时返回错误说明；StartUploadDataLoggerDataNonblocking 启动成功返回 true。

    GetValue¶

    double GetValue(AxisRef axis, eKeyword keyword, int index = 0)

    按关键字读一个轴上的数值，按这个轴的用户单位换算后返回（没有启用用户单位时是计数）。每次调用都向控制器读一次，不使用快速读缓存。TryGetValue 失败时返回 false 而不抛异常。

    按关键字读数值

    SDK 说明： The value keyword holds on axis, read through the controller, in the units that axis reads it in — MotionController.GetUserUnits says which, and answers counts when nothing scales it. index 0 reads a scalar parameter; 1 and up read one element of an array parameter, in the parameter's own indexing — an array parameter has no reading at 0, and a scalar one none at 1. Keyed by keyword so a caller can read a parameter it knows only by name, rather than through the member that happens to expose it. axis names one axis; a combined mask is an System.ArgumentException, and so is a keyword the message table flags as a controller command — reading one would SEND it. An index the parameter does not have throws.     GetUserUnits¶

    CheckConnection¶

    bool CheckConnection()

    两种检测，回答的问题不同：

    • CheckConnection / aamotion_check_connection 用 ICMP ping 控制器的网络地址，判断网络上能不能到达它。仿真、串口、CAN 连接没有 IP 地址，不发 ping，返回 SDK 记录的连接状态。
    • ProbeConnection / aamotion_probe_connection 发一条命令（实时读取控制器的 Time，不经过快速读缓存）并等待回复，证明控制器本身此刻在应答。它走和所有读写相同的通道，适用于以太网、串口、CAN 和仿真。结果包括往返时间、没有应答的原因（枚举：连接探测失败原因），以及控制器自上一次成功探测以来是否重启过（Time 变小）。

    两者都只报告结果，不会自动重连。IsConnected 只说明 SDK 是否还持有这条连接，不能代替它们。

    检测控制器是否可达、是否在应答

    SDK 说明： Actively probes physical reachability via ICMP ping and returns the result. Unlike MotionController.IsConnected, this always sends a probe and can block for up to ~1 second — call it deliberately (a background timer, a manual health check), never from a binding or a property-style hot path. Two independent probes are sent; either succeeding counts as reachable, so a single blocked or rate-limited ICMP packet is not mistaken for a dead link. For a connection made over a non-IP channel (Simulation, serial, CAN), or before any address is known, ICMP has nothing to probe and this reports the logical state instead — the same value MotionController.IsConnected would return. This never disconnects or reconnects anything by itself. Call MotionController.TryReconnect to recover a link this reports as down. A reachable address does not prove the controller answers commands; MotionController.ProbeConnection does.

    参数： 无。

    返回类型： bool

    CheckConnection：可达返回 true；未连接或 ping 不通返回 false。

    C# ProbeConnection：一个 ConnectionProbeResult，包含 IsAlive、Failure、RoundTripMs、Message、ControllerTime、ControllerRestarted 和 Timestamp（UTC）。除了 timeoutMs 越界，它不抛异常；AAMotionAPI.ProbeConnection 传入 null 控制器时返回 NotConnected。

    C aamotion_probe_connection：探测已执行返回 true，结果读 *failure；句柄无效、timeoutMs 越界或 failure 为 NULL 时返回 false，且不写任何输出。

This method does not tear down a link it finds open, and the connect short-circuits on one, so calling it alone on a wedged session returns false without reopening anything — though MotionController.LastKnownAddress and MotionController.AutoReconnectEnabled are recorded before the attempt, so a failed call still updates them.

    ProbeConnection¶

    ConnectionProbeResult ProbeConnection(int? timeoutMs = null)

    两种检测，回答的问题不同：

    • CheckConnection / aamotion_check_connection 用 ICMP ping 控制器的网络地址，判断网络上能不能到达它。仿真、串口、CAN 连接没有 IP 地址，不发 ping，返回 SDK 记录的连接状态。
    • ProbeConnection / aamotion_probe_connection 发一条命令（实时读取控制器的 Time，不经过快速读缓存）并等待回复，证明控制器本身此刻在应答。它走和所有读写相同的通道，适用于以太网、串口、CAN 和仿真。结果包括往返时间、没有应答的原因（枚举：连接探测失败原因），以及控制器自上一次成功探测以来是否重启过（Time 变小）。

    两者都只报告结果，不会自动重连。IsConnected 只说明 SDK 是否还持有这条连接，不能代替它们。

    检测控制器是否可达、是否在应答

    SDK 说明： Sends one command to the controller and waits for its reply, to tell whether the controller is answering right now — the same path every read and write takes. The command reads Time (seconds since power-on) live, never through the fast read cache, and works on every channel: Ethernet, serial, CAN and simulation. Use it from a dedicated thread, as a heartbeat or before deciding to reconnect. Unlike MotionController.IsConnected, which only reports whether the SDK still holds the connection, and MotionController.CheckConnection, which pings the network address, this proves the controller itself answers, says why it did not, and notices a controller restart. A timeout on the wire tears the connection down , as any command timeout does: the server closes the controller's channel for every client on it. Keep timeoutMs above the longest reply the controller can take while busy. A probe that times out still queued behind other commands was never sent and leaves the connection up; MotionController.IsConnected tells the two apart. The probe never reconnects: when it reports the link down, call MotionController.TryReconnect on Ethernet, or MotionController.Disconnect and ConnectSimulation on a simulation. A probe that is sent and fails raises MotionController.ErrorOccurred and MotionController.ErrorReported like any other command; one refused because the link is already down raises neither. Concurrent probes on one controller run one at a time.

    参数 类型 方向 默认值 说明
    timeoutMs int? 输入（值传递） null 等待回复的毫秒数，10–60000。C#：null（默认）使用当前默认超时，超出范围抛 ArgumentOutOfRangeException；C：0 使用默认超时，超出范围返回 false。

    返回类型： ConnectionProbeResult

    返回说明： Whether the controller answered, the round-trip time, the controller's Time, whether it restarted since the previous successful probe, and the reason for a failure.

    UseUserUnits¶

    bool UseUserUnits { get; set; }

    SDK 说明： Gets or sets whether this controller expresses values in the connected controller's Global User Units. Set it to false to keep every read and write in raw controller counts — the escape hatch for an integration written against a counts-based API. Default true. The setting survives connect and reconnect, so it can be configured before connecting: the communication layer clears its own opt-out on every successful connect, and this controller re-applies the value last assigned here once the connect succeeds. Instance-wide, not call-wide — it forwards to AAComm.CommAPI.SkipUserUnits, so two controllers sharing one AAComm.CommAPI share the setting. To bypass the scaling for a single message, use AAComm.Services.AACommMessage.SkipUserUnits instead. What is read back is what the communication layer will actually do, so a direct write to AAComm.CommAPI.SkipUserUnits is visible here — but only a value assigned through this property is remembered, and only that is re-applied at the next connect. Opting out does not unlock raw User Units configuration writes: a direct assignment to a *UnitFct or *UnitUnt parameter stays rejected either way.

    访问： get; set;
