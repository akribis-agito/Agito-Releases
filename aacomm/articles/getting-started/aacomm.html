AAComm

AAComm is a C# .NET API for PC-to-Controller communications, supporting a wide range of .NET targets and Windows platforms.

  • 📚 API documentation: https://akribis-agito.github.io/Agito-Releases/aacomm/
  • 🌐 Vendor: https://agito-akribis.com

Overview

AAComm provides a robust interface for communicating with motion controllers from .NET applications. It is designed for both high-level and low-level control, supporting multiple communication channels and controller types.

  • Supported platforms: Windows 7 or later
  • Supported frameworks: .NET Framework 4.8, .NET 8.0
  • Required files: AAComm.dll plus the bundled server matching your framework — .NET Framework 4.8: the aacommserver\ folder (the AACommServer.exe WPF host with its full closure); .NET 8.0: AACommServerNative.exe (self-contained native host, win-x64). The NuGet package copies the right one to your output automatically — do not hand-assemble a partial server file set (a net48 server under a net8 consumer crashes on launch). No Linux/macOS sidecar ships yet: a non-Windows .NET 8 consumer must supply its own host-native AACS build and pass its full path to StartAACommServer — the copied AACommServerNative.exe is the Windows artifact, not a host-native server.
  • Documentation: API documentation is available via IntelliSense (XML doc comments included with the package).

System Requirements

  • Microsoft Windows 7 or later
  • .NET Framework 4.8 or .NET 8.0
  • Visual Studio 2019 or later (other IDEs may be used, but are not officially supported)

Installation

Install the NuGet package from nuget.org: .dotnet add package Agito.AAComm Or via the NuGet Package Manager in Visual Studio.

Note:
The bundled server is copied to your output directory automatically by the NuGet package — the aacommserver\ folder for .NET Framework consumers, AACommServerNative.exe for .NET 8.0 consumers. For a manual (non-NuGet) deployment, copy that complete server payload as-is; never mix the net48 server into a net8 output.

Getting Started

  1. Create a new C# project.
  2. Add the Agito.AAComm NuGet package.
  3. For Windows: build — the bundled server lands in your output directory and CommAPI.StartAACommServer() resolves it from there; or pass an explicit executable path.
  4. For non-Windows: Specify the full path to a host-native AACommServer build when starting the server (no non-Windows sidecar is packaged — the copied AACommServerNative.exe is win-x64 only).

Usage Example

Below is a minimal example demonstrating how to start the AAComm server, connect to a controller, and send/receive messages:

using AAComm;
using AAComm.Services;
using AAComm.Shared;

ConnectResult aacs = CommAPI.StartAACommServer();
Console.WriteLine($"AACommServer start: {aacs}");

var api = new CommAPI();
var cd = new ConnectionData
{
    CommChannelType = ChannelType.Ethernet,
    ET_IP_1 = 172, ET_IP_2 = 1, ET_IP_3 = 1, ET_IP_4 = 101,
};

var res = api.Connect(cd);
Console.WriteLine($"Connect Result: {res}");

if (res != ConnectResult.Success)
{
    res = api.Connect(cd, true);
    Console.WriteLine($"FORCE Connect Result: {res}");

    if (res != ConnectResult.Success)
    {
        OnExit();
        return;
    }
}

var msgRes = api.SendReceive(new AACommMessage("APos"));
Console.WriteLine($"SYNC: APos = {msgRes.MsgReceived}");

api.Send(new AACommMessage(OnReceive, "APos"));
//wait for async response at OnReceive callback

OnExit();
api.Disconnect();

void OnExit()
{
    Console.WriteLine("press any key to exit");
    Console.ReadKey();
    api.CloseAACommServer();
}

void OnReceive(object sender, AACommEventArgs e)
{
    Console.WriteLine($"ASYNC: APos = {e.MsgReceived}");
}
