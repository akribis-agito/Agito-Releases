    CNC interpolation¶

    CNC moves 2–3 axes together along a path of lines and arcs. The program writes the path piece by piece (segments) into the controller's buffer, then Begin starts it; the controller runs the segments back to back, and each segment's end speed decides whether the axes stop between segments.

    Concept Meaning
    Group CNC group A (c.GetGroup(AxisRef.A)) or group B; the static AAMotionAPI and C functions use group A
    Coordinates X, Y and Z are the group's axes A, B and C
    Units Segment positions and speeds are integer counts, never converted by User Units
    Speed each segment has a cruise speed velCruise and an end speed velEnd; velEnd = 0 stops at the segment end
    Buffer segments can be added while moving; ClearBuffer empties it

    Segment types are in Enums: CNC segment type; the controller side is described under keyword CNC overview.

    Verify firmware CNC support first¶

    Having SDK CNC methods does not prove firmware support. In PCSuite CNC, configure the same axis group, complete commutation and motor-on, and run one short straight line at low speed within permitted travel. Verify download, execution, directions and endpoint. If PCSuite refuses it or reports unsupported commands, check model, firmware and CNC capability before the demos of this chapter. Working point-to-point motion is not evidence of CNC support.

    From one line to a continuous path¶

    1. Confirm commutation before motor-on for every axis, actual start position, group mapping and units. SetStartPositions defines the path start; it does not move the axes there.
    2. End the old task before clearing its buffer. Set the start and SetMotionProfile override, acceleration, deceleration and smoothing.
    3. Download one short LinearAbsoluteXY with zero end speed. Check endpoint, velCruise and velEnd and each send result/exception; do not Begin a partially failed download.
    4. Begin starts the downloaded path; successful writes and start do not prove completion. Poll IsCNCCompleted with a timeout and error reporting; request group Stop and inspect actual state on failure.
    5. Add arcs and continuous segments only after the line passes. Check endpoint, absolute centre, plane and direction. Nonzero end speed connects segments; finish the last segment at zero. Corner behavior still follows firmware trajectory rules.

    CNC coordinates axes along a path, unlike multi-axis point-to-point bulk start. Host polling observes results and does not perform interpolation. See the demos of this chapter.

    First-segment rules and arc troubleshooting¶

    How segments are pushed¶

    Every segment builder pushes a segment as plain commands, the form PCSuite sends: CNCAPushType with the header, then one CNCAPushParam per field (CNCBPush… on group B). The arguments are not scaled by User Units. A refused command ends the push, raises the error hook and the builder returns false; the segment is then left open, and later pushes are refused until ClearBuffer.

    Check the motion mode before starting¶

    Set the participating axes to the mode for their group. Use MotionMode = 11 for CNCA and 17 for CNCB. The SDK's CNC Begin sends a Begin command and the controller uses its current mode. Stop the previous motion before changing modes.

    Queue the first segment¶

    • When using SetStartPositions, put it first in an empty queue, before SetMotionProfile. It declares the path start. For an XY path, select X and Y and use their actual current coordinates.
    • Without SetStartPositions, the first motion segment must be linear. Starting with an arc can produce ERR 139. Give the line a target at a different position from the start.
    • ERR 140 points to a misplaced start definition. For ERR 141, check that the selected axes match the motion group. For ERR 142, check that the axes are already at the declared start. Complete any positioning move and verify settling before queueing the path.

    Calculate the arc centre¶

    This example uses an absolute endpoint and an absolute centre. The arc starts at the previous segment's endpoint.

    Item XY coordinates (counts)
    Line endpoint and arc start (50 000, 0)
    Intended centre (50 000, 50 000)
    Arc endpoint (100 000, 50 000)
    iPos and jPos for ArcXY (50 000, 50 000)

    The start lies directly below the centre and the endpoint lies directly to its right. Both radii are 50 000 counts. PCSuite uses dir = 0 for this counter-clockwise quarter turn. For a G-code conversion, add I and J to the segment start to get the absolute centre. A radius mismatch can produce ERR 143.

    Recover from a rejected segment¶

    • Under the default continuity rules, use velEnd = 0 before a Delay or an input wait. Changing the participating axes can also require zero end speed in the previous segment. The controller can otherwise reject the next segment with ERR 204.
    • Radius, distance, or speed validation may fail after the firmware has written part of a segment. When queueing an entire path ahead of time, stop sending on the first failure. Confirm the group has stopped, clear the queue, and rebuild from the first segment.
    • If Begin succeeds and the axes stay still, check the CNC status word. Group A's CNCAStatus[10] bit 13 means it is waiting for the first motion segment. Confirm that a complete, executable motion segment is queued, then check the axis group, motor enable, and controller errors.

    Begin, pause, stop and clear¶

    Begin runs the buffered segments (the AAMotionAPI.Begin(c) overload without an axis is the CNC start); Pause decelerates along the path and holds on it, Resume continues from there; GroupStop / Stop stop the CNC motion; ClearBuffer drops the segments not yet run. Clear the buffer before writing a new path.

    Profile, corners and start¶

    These are segments in the buffer too, applied when the path reaches them, so settings can change along the way:

    • 'SetMotionProfile: speed percentage, acceleration, deceleration, smoothing factor.'
    • 'SetCornerParams / AutoCorner: how corners are handled (corner radius or allowed error, minimum angle, acceleration limit); AutoCorner inserts a smoothing arc between the current two-axis line and the next segment.'
    • 'SetStartPositions: the path''s start coordinates; SetCurrPositions: assigns coordinates to the current position.'
    • 'SetMaxVelJumpParams / SetMaxAccelParams: each axis''s largest allowed velocity jump and acceleration, limiting the shock at corners.'

    When to use it

    Tuning the speed and corners of a path, reducing shock and overshoot at corners.

    Notes

    • These are buffered segments; the call returning only means the segment was written, and the action happens when the path reaches it.
    • GroupDOutSetBit / ClearBit / ToggleBit read the current DOutPort when the segment is written, compute the whole port value and store it in the segment; when the path reaches it, the whole port is written. Other outputs changed elsewhere between writing and running the segment are therefore overwritten.

    Example

    IGroupAxis g = c.GetGroup(AxisRef.A);
g.LinearAbsoluteXY(50000, 0, 40000, 0);
g.GroupDOutSetBit(AxisRef.A, 1);      // output 1 on when the path reaches here (a 1-based output number)
g.Delay(100);
g.GroupDOutClearBit(AxisRef.A, 1);
g.WriteGenData(5, 1);                 // tell the user program "segment 2 reached"
g.LinearAbsoluteXY(100000, 0, 40000, 0);
g.Begin();

    Run a CNC program file¶

    RunCNCProgramFromFile reads the file generated by the PCSuite CNC tool and sends commands in file order. IsCNCCompleted reads the live CNC status word and returns true when motion bit 0 is clear. This can occur before startup, after normal completion, or after a stop or interruption. Confirm the download result, runtime errors, and final position to verify that the full path succeeded.

    Standalone demo: Run a CNC program file

    When to use it

    Running a CNC program made in PCSuite; waiting for a path to finish.
