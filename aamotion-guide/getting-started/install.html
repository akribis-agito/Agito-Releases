    安装¶

    • 需要 Windows 电脑；C/C++ 需要 x64 编译器，Python 需要 64 位 Python
    • 先读 —
    • 完成后 装好 SDK，知道服务器从哪里来

    按你用的语言选一个标签。三种用法都需要 AACommServer：它是一个本机的小程序，你的程序启动时由 SDK 自动拉起，不需要手动打开。下面会说清楚每种用法里它从哪里来。

    在 Visual Studio 里打开“管理 NuGet 程序包”，搜索 Agito.AAMotion，安装 API 索引中写明的版本。也可以直接在项目文件里写，把 <version> 换成这个版本号：

    <PackageReference Include="Agito.AAMotion" Version="<version>" />

    它会自动带上 Agito.AAComm（通信层）和 Google.Protobuf 等依赖。支持的目标框架：

    目标框架 编译后服务器在哪里 服务器是什么
    .NET Framework 4.8 输出目录下的 aacommserver\AACommServer.exe 带窗口的 AACommServer（可以看通信日志、抓包）
    .NET 8 / .NET 10 输出目录下的 AACommServerNative.exe，在你的 exe 旁边 无窗口的原生服务器，不需要 .NET 运行时，Windows x64

    服务器由 NuGet 包在编译时自动拷到输出目录，什么都不用配置。服务器版本跟着包走，所以发布你的程序时把整个输出目录一起拷走即可。

    要看通信日志就用 .NET Framework 4.8

    .NET Framework 项目带的是有窗口的 AACommServer，能直接看到每条命令和回复。调试阶段推荐用它；.NET 8 的无窗口服务器只写日志文件（见日志）。

    从 Agito-Releases 的发布页 下载 agito-aamotion-native-sdk-<version>.zip，解压：

    agito-aamotion-native-sdk-<version>/
├─ include/
│   ├─ aamotion.h          函数声明
│   └─ aamotion_enums.h    枚举和关键字常量
├─ win-x64/
│   ├─ aamotion.dll  aamotion.lib
│   └─ AACommServerNative.exe
├─ linux-x64/
│   ├─ libaamotion.so
│   └─ AACommServerNative
├─ osx-x64/   osx-arm64/

    规则只有两条：

    1. 只有 64 位。Visual Studio 里平台选 x64；32 位程序加载不了这个库。
    2. AACommServerNative 必须和 aamotion.dll 放在同一个目录（也就是你的 exe 旁边）。找不到它，aamotion_initialize 会返回 NULL。

    示例工程用 CMake，构建时设置 AAMOTION_SDK_DIR 指向解压目录，编译完成后会自动把库和服务器拷到 exe 旁边：

    cmake -S samples/cpp/01-connect -B build -A x64 -DAAMOTION_SDK_DIR=D:/sdk/agito-aamotion-native-sdk-<version>
cmake --build build --config Release

    Linux 上去掉 -A x64；库通过 $ORIGIN 的 rpath 从 exe 目录加载。

    Python 使用和 C++ 相同的原生 SDK，通过标准库 ctypes 调用，不需要安装额外的包。

    1. 安装 64 位 Python 3.8 或更高版本。
    2. 下载并解压原生 SDK（见 C / C++ 标签）。
    3. 设置环境变量 AAMOTION_SDK_DIR 指向解压目录，或者把 win-x64（Linux 上是 linux-x64）里的文件拷到 aamotion.py 旁边。
    set AAMOTION_SDK_DIR=D:\sdk\agito-aamotion-native-sdk-<version>
python samples/python/01_connect.py 172.1.1.101

    示例里的 aamotion.py 是一层很薄的 ctypes 封装：声明函数的参数和返回类型，并在初始化时处理服务器的查找（原因见第一个程序）。

    仿真器¶

    没有控制器时，用固件仿真器 firmware_sim.exe。从 Agito-Releases 的 Firmware 发布里下载对应产品的仿真包，解压到任意目录，记下 firmware_sim.exe 的绝对路径。用法见仿真器。

    网络¶

    连接 端口 说明
    你的程序 → AACommServer 本机 TCP 127.0.0.1:399（Linux / macOS 是 1024） 只在本机，不出网卡
    AACommServer → 控制器 TCP 50000；仅 AGM800 的推送数据使用 50010 控制器出厂 IP 一般是 172.1.1.101

    电脑网卡要和控制器在同一网段（例如 172.1.1.x），防火墙要允许 AACommServer 访问网络。

    日志在哪里¶

    出问题时，先看这三个目录，都在 %LOCALAPPDATA%\PCSuite\ 下：

    目录 谁写的 里面有什么
    AAComm_DebugLogs 你的程序里的 AAComm 连接、超时、重连
    AACommServer_DebugLogs AACommServer 拨号、每条命令的收发；Sniffer 子目录是抓包
    PCSuite_DebugLogs PCSuite 只有 PCSuite 才写

    检查安装¶

    做完上面几步，运行第一个程序。看到 Connect …: True 就说明 SDK、服务器和网络都没问题。
