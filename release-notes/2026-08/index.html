Highlights

Statuses, redesigned

The Statuses window and every tool-page status strip now speak one visual language: a full-height health card that names the active alert, per-axis cards that wrap to the window, mode chips instead of blinking text, alert-count badges on the status-bit tabs, and copy-from-context-menu on any value. A Ci master names the remote unit on each port.

Terminal, rebuilt

Colored output by message kind, Ctrl+F search, fold markers on huge replies, slash commands with completion (/help, /save, /theme, /axis …), a dedicated input line with history and ghost-text suggestions, live validation in the status bar, color themes, and /save exporting a full session support report as text or HTML.

Data Rec expressions

Typed math over controller parameters — plus _time, user-program globals, other expressions by name, and FFT / PSD / CPS / SqrtCPS frequency-domain functions — evaluated after each recording and charted as named vectors. Legend tooltips explain every line; undefined samples raise a notification instead of leaving silent gaps.

Firmware from the release catalog

Manage/FW fetches certified firmware straight from the Akribis-Agito release catalog, verified against published SHA256 checksums, with that release's notes readable before flashing. A connected controller pre-selects its product; EC Core 1 downloads can verify current ratings.

Simulation connection

Manage Connection → Simulation launches a bundled PC firmware simulation — a real plant with motion — over loopback, with a firmware version picker and a motor/encoder/load editor backed by the motor catalog. Every tool works against it without hardware.

User Units

Per-axis custom unit names and factors for Position, Velocity, Acceleration and Force, configured under Config → User Units and applied throughout PCSuite — and, in AAComm 14, transparently on every parameter read and write.

Documentation, side by side

Help → Documentation puts the controller-keyword reference — with the connected controller's live parameter ranges — next to a synced cloud knowledge base. The terminal's /doc <keyword> opens the same article.

Scope: auto-scale and markers

An Auto Scale Y switch follows each signal with 5 % headroom while recording and snaps to an exact fit when the run ends; the new Markers tab reads every signal at both markers with the difference, span and frequency. Any signal can be drawn as a scatter plot.

Support built in

Every run writes a session debug log; an unexpected error closes the application naming that file. Preferences gains an "Open logs folder" button and a card listing every "don't show again" message. The terminal's /save bundles PCSuite and controller identity, counters and the full scrollback into one report.

Safer keys

Keyboard shortcuts keep working with the focus in a chart, the program editor, a table or an embedded documentation page; Panic mode (five or more keys at once) stops the motors from any window; F4 is no longer an emergency-stop key.

Breaking changes 13

  • AAComm.dll is now strong-named (PublicKeyToken=043a10799a9b732b), so strong-named consumers can reference it — previously they compiled with warning CS8002 and failed at load with FileLoadException 0x80131044: A strongly-named assembly is required. Adding the strong name changes the assembly identity: .NET Framework consumers must recompile against 14.0.0 (a binary built against a 13.x AAComm, PublicKeyToken=null reference does not bind to the signed assembly, and no binding redirect bridges an identity change); .NET 8/10 consumers see no difference. The AssemblyVersion is pinned to 14.0.0.0 for the whole 14.x line (package and file version keep the full number), so a consumer built against 14.0.0 binds to any 14.x without redirects. Persisted assembly-qualified type names that spell PublicKeyToken=null (e.g. BinaryFormatter payloads, Type.GetType full-name strings) stop resolving — simple names (AAComm.CommAPI, AAComm) are unaffected. AACommServerCore.dll (bundled with the server) is signed too; the AACommServer.exe process itself is not — see docs/strong-naming.md in the repo for the assembly-by-assembly map and the reason.
  • The C++/CLI AACommNative wrapper has been retired (with its AACommNativeTester/AACommNativeTesterCLI projects). The NuGet no longer ships the lib/cppCLI/net48/ slot (IAACommNative.h, AACommNative.lib/.dll, shared sources). Native (C/C++) consumers move to the new C-ABI SDK — project AACommNative (reclaiming the name) → aacomm.h + aacomm.dll/libaacomm.so/libaacomm.dylib.
  • OnResetProgress replaced by two events — OnLongOperationStarted(LongOperationType) and OnLongOperationEnded(LongOperationType, int errorCode) — now firing for Reset, Save, Load, SaveUser, and EventCorrect. The ended edge's errorCode is 0 on success or the controller error code (e.g. 22 = "motor on") on failure, so subscribers can suppress a "complete" message on a failed long operation (issue #85). For the non-Reset types, a reply that arrives within a short start-grace window (100 ms) raises neither edge — an immediately-rejected operation (e.g. ERR 22 declining a flash Save while the motor is on) is not long-running, so no transient "started" notification can race and overwrite the error the reply itself reports. Subscribers must update their handler signatures. The native C-ABI SDK mirrors this with aacomm_set_longop_started_callback / aacomm_set_longop_ended_callback.
  • Binary IPC dialect v3 — typed payloads: binary requests now carry a typed message kind plus the raw payload bytes instead of ASCII-rendered, prefix-tagged strings, removing a redundant render/parse on both ends of every message. Measured on AGM800 and AGD301, binary round-trips now match or beat the ASCII protocol (previously ~15 % slower) with materially tighter tail latencies. The dialect is negotiated at connect: a version-skewed binary peer — old client on a new server, or new client on an old server — degrades to the ASCII compat protocol; the previous binary dialect is removed. The AACommServer comm log keeps showing the readable command text (carried alongside the binary payload for display); FW/UP download payloads log masked as binary, as before.
  • CommAPI now negotiates the wire protocol with AACommServer at connect time — binary by default, falling back to the legacy ASCII protocol when the server is an old ASCII-only build. The fallback is no longer silent: CommAPI.ServerCompat (see Added) reports the attached server's classification, so hosts can warn the user. The consumer does not select the protocol — new CommAPI() remains the only construction, and the negotiated mode is reported by CommAPI.Protocol (see Added). The ASCII client pipeline is deprecated and frozen — kept solely for compat with servers started by older SDK applications.
  • IChannelSnifferHook.OnChannelClosed(bool) is now OnChannelClosed(SnifferConnectionInfo connectionInfo, bool isError) — the close notification carries the controller endpoint so a host capturing several controllers at once can route the snapshot to the right NIC. Host sniffer integrations must update the signature.
  • AACommAxisHelper is merged into the new AAComm.Services.AACommMnemonicHelper (see Added) and removed. AAxis, PAxis, ToAxis, ToAxisIdx(char) and ToAxisChar are unchanged and live in the same namespace, so their extension call sites recompile as-is; direct class-name references (AACommAxisHelper.AAxis → AACommMnemonicHelper.AAxis) need updating. Two redundant members are dropped: ToAxisStr(int) (use ToAxis(idx).ToString()) and the ToAxisIdx(string) overload (use s.ToAxisChar().ToAxisIdx() — makes the first-char truncation explicit).
  • AACommMessage.StartsWithPAxis(string) removed — use msg.ToAxisChar() == AACommMnemonicHelper.PAxis (identical semantics, including null/empty → false).
  • LoggerDataContainer / ScopeDataContainer constructors take a new required char[] parameter (paramAxes / signalAxes — the per-vector axis letters, needed to resolve User-Units scaling per axis) in addition to the CommAPI→ICommService narrowing. Existing call sites must supply the axis array.
  • TriggerContainer construction is reshaped into three overloads: by source CCC code (ICommService, int trigType, int trigSrcCCC, …), by source mnemonic (ICommService, int trigType, string trigParam, …), or source-less (int trigType, double trigVal, …) for triggers that carry no parameter source. The previous single-constructor call sites must pick the matching overload.
  • MessageData.DefaultValueStr (deprecated in 11.1.0 with its Min/Max siblings) is removed with the rest of that property group; its replacement lives on MessageDataValueExtensions like the others (see Added).
  • The native C-ABI SDK (aacomm.*) adopts a uniform status convention: every aacomm_* function now returns int32_t aacomm_status (AACOMM_OK=0 / AACOMM_NULL_ARG=-1 / AACOMM_BAD_HANDLE=-2 / AACOMM_EXCEPTION=-3), and domain results (the ConnectResult, the connected flag, reply/error byte sizes) move to out_* parameters. So aacomm_create, aacomm_destroy, aacomm_is_connected, aacomm_last_error, aacomm_start_server, aacomm_test_connection, aacomm_connect/_silent, aacomm_send_receive, and aacomm_last_reply all change signature (e.g. aacomm_create(aacomm_handle* out), aacomm_is_connected(h, int32_t* out_connected)) — this removes the old ambiguity where aacomm_is_connected returned 0 for both "not connected" and a bad handle. Handles now come from a table that rejects forged/stale/double-freed handles with AACOMM_BAD_HANDLE instead of risking undefined behavior. Adds aacomm_close_server(h, force) to shut down a spawned AACS. ABI generation resets to 1 at first ship under the soname policy (the ABI number now bumps only on breaking changes; additive growth never bumps it — see the AACommNative README); native consumers rebuild against the shipped aacomm.h.
  • XmlHandler.SaveXml() is removed in favour of TrySaveXml(out Exception) (see Added). It returned nothing and reported a failed write only through a Debug.Assert — a no-op in Release, so a document that never reached disk passed silently.

Added 25

  • Always-on client diagnostic log — AAComm.Services.Diagnostics.AACommDebugLog, the client-side counterpart of AACommServer's debug log. Session-lifecycle events (construction, connect/test outcomes, sync-timeout expiries — including the phase-1 queue-abandon vs phase-2 teardown distinction — server FATALs, disconnects with their reason) accumulate in an in-memory ring with zero configuration and zero steady-state file IO; a severe event (sync phase-2 teardown, FATAL, comms error) snapshots the ring to %LocalAppData%\PCSuite\AAComm_DebugLogs\{timestamp}_{process}_{pid}_{trigger}.log (debounced, pruned at 200 files). Every line carries an identity tag (api#N/conn#M); the connect line logs the endpoint and the socket's local port, which joins against the UserId ↔ client-endpoint line AACommServer now writes on each Open. Public surface: AACommDebugLog.Sink (an Action<string,string> bridge so hosts can forward the lines into their own log) and AACommDebugLog.Flush() (on-demand snapshot). Full spec: docs/diagnostics-srs.md.
  • User Units — per-axis engineering-unit scaling, applied transparently to parameter values on both send and receive. At connect, the API reads the controller's units configuration (the *UnitGroup/*UnitFct/*UnitUnt parameter families, grouped per UUGroups: Pos/PosAux/PosPD/Vel/VelAux/VelPD/Acc/Frc) and the per-axis UserUnitsEn enables; from then on values of parameters in an enabled group are scaled by the axis factor in both directions. The new AAComm.Services.UserUnits namespace carries the model (UserUnitGroup, UserUnitAxis, UserUnitsData, UUGroups, UUErrors, UUMnemonics). The surface:
  • CommAPI: GetUserUnitsEnabled(char) / SetUserUnitsEnabled(char, bool) (per-axis query/enable — the setter is controller-ack-authoritative), RefreshUserUnits() (re-read the configuration), OnUserUnitsEnabledChanged (raised on a confirmed per-axis transition), and SkipUserUnits (consumer-wide bypass, reset to false at Connect).
  • AACommMessage: SkipUserUnits (per-message bypass) and AllowUserUnitsConfig (sanctions a raw write of the units-config parameters themselves — without it such writes are rejected with ERR 4023; set units through TrySetUnitsSync instead), plus constructor overloads taking skipUserUnits.
  • ControllerMessagesContainer: UserUnitsSupported, MaxUserUnitNameLen(UUGroups), TryGetUserUnitAxis/TryGetUserUnitsGroup (read-only lookups, also on IMessagesContainer — implementors must add them), and TrySetUnitsSync(ICommService, UUGroups, char, string, double) — the sanctioned, synchronous write of a group's units name + factor.
  • MessageData: UserUnits (the parameter's group, read-only), GetUserUnitsData(char) returning a UserUnitsData struct (Min/Max/Default scaled for the axis + Factor/Units), and GetDescription(char) (the parameter description with per-axis units resolved).
  • FloatHelper: ApplyUserUnits/RemoveUserUnits — the Rx/Tx scaling primitives, for consumers formatting values outside a message flow.
  • ICommService exposes GetUserUnitsEnabled(char). The native C-ABI SDK mirrors the per-axis enable/query as aacomm_get_user_units_enabled/aacomm_set_user_units_enabled.
  • AAComm.Services.AACommMnemonicHelper — the SDK home for controller-message string manipulation, consolidating helpers previously spread across host-side libraries. Covers axis-letter conversions (absorbed from AACommAxisHelper), the '?' active-axis / '*' all-axes sentinels, mnemonic extraction (Mnemonic, SplitMessage), array-index handling (ArrayIndex, SeparateArrayIndex, RemoveArrayIndex), assignment/equality location that skips comparison operators (IndexOfEquality, IndexOfAssignment, IndexOfMnemonicEnd). IsAxisInRange(char, IIdentityContainer) validates an axis letter against the connected controller's actual axis count (the dynamic 'P' axis is always valid; disconnected falls back to the theoretical 12-axis 'A'–'L' range).
  • MessageData value accessors (MinValueStr/MaxValueStr/DefaultValueStr, MinValueInt/MaxValueInt/DefaultValueInt, MinValueLong/MaxValueLong/DefaultValueLong) — extension methods on MessageDataValueExtensions formatting Min/Max/Default per the parameter type (no User-Units scaling), replacing the host-side equivalents that backed the properties deprecated in 11.1.0.
  • IIdentityContainer exposes Features_02, CurrentLoopSampleRate, MaxNumOfRecVectors, MaxDataRecordingPoints, NumOfMotorAxes — needed by Core consumers of the recording pipeline and the User Units API. IMessagesContainer exposes Contains(string), CanCodeToData, IsInitialized; ICommService exposes MessagesInBulk. Implementors of these interfaces must add the members.
  • Recording-pipeline command builders are now public API: TriggersDataContainer.GetDownloadCommands(RecParamsResolver) / TriggerContainer.GetDownloadCommands(RecParamsResolver, int) (the trigger setup commands a recording download sends) and RecParamsResolver.GetTriggerIndex / GetTriggerLogicIndex (slot resolution for trigger sources) — needed by host recording tools driving the pipeline through the abstractions.
  • Binary IPC protocol v2 (additive, version-safe both directions): every request carries a correlation id the server echoes on its reply, and the client routes replies by identity instead of arrival order — eliminating a class of cross-flow reply misrouting when Send and SendReceive run concurrently (server-internal queries could previously overtake a pending controller reply and each caller received the other's answer). Legacy servers/clients interoperate unchanged (id 0 keeps arrival-order routing). A new CHANNEL_EVENT reply kind — sent only to clients that declare support on Open — notifies a passive client when its channel dies; it surfaces via OnCommsError.
  • The bundled AACommServer packet sniffer now captures every connected controller simultaneously — one capture session, ring buffer, and snapshot tree per controller endpoint (under per-NIC ip_port subfolders) — instead of only the most-recently-opened channel's NIC. The server window lists a live status/packet row per controller with per-NIC Mark and Export.
  • CommAPI and AACommServerModel now implement IDisposable — Dispose() delegates to Disconnect() / Shutdown() respectively, so consumers can use using blocks. CommAPI.Dispose() does not shut down the shared AACommServer process (call CloseAACommServer() for that); both are idempotent.
  • CommAPI.FlushDebugLog() — asks the attached AACommServer to write its in-memory debug log to disk now, instead of only at server shutdown, so a support snapshot taken while the problem is happening captures the *current* session rather than the previous one. Works whether or not the caller is connected, does not clear the server's log or disturb a running session, and is a no-op when no server is running. It is fire-and-forget — there is no acknowledgement: the result is the newest {yyyy_MM_dd_HH-mm-ss}_Flush.log under %LocalAppData%\PCSuite\AACommServer_DebugLogs. Available on both the binary and legacy ASCII wire protocols; against an older AACommServer the request is ignored.

  • CommAPI.ServerCompat (new ServerCompat enum: Unknown/Current/LegacyBinary/LegacyAscii) — classification of the AACommServer the client attached to, valid after Connect. The version floor classifies, it never rejects: an old server started by an older SDK application still serves this client in compat mode (it owns the shared port; a client never shuts down a server it did not spawn), but the degraded mode — arrival-order routing on ASCII, missing channel events, skipped version-gated features — is now queryable instead of silent. Fixed 33

  • Connect and TestConnection no longer fail on a busy machine while the controller is healthy. Both steps of the connect handshake were budgeted as if they measured controller response time, but each depended on ThreadPool scheduling, so CPU pressure — a build, a test run, another application — could produce AACommServerNotRunning against a server that was listening, or FailControllerType against a controller answering in under a millisecond. Three changes: the server-liveness probe completes its loopback check on the calling thread instead of waiting on a pool-dispatched completion; a message waiting to reach the wire is no longer charged that wait against its own TimeoutMs when nothing else is on the wire, since only client-side scheduling can delay it there; and a dispatched request is no longer torn down for delays that are not the controller's — client-side completion scheduling, or server-side queueing behind another client — the synchronous wait grants starvation headroom above TimeoutMs + 100 before implicating the link, because the server itself polices controller silence at TimeoutMs and reports it as a FATAL. A genuinely unresponsive server is still detected and disconnected, a few seconds later than before. A message queued behind a live one keeps its caller's budget and stays as responsive as before, and TimeoutMs still means what it always did to the server — the controller's reply budget — so a wedged controller is still detected promptly. Measured against a live controller on a 12-core host: the first two changes took connect failures under load from reproducible to rare cold-start-only cases, and the third targets that remainder; idle-path latency unchanged.
  • AACommFwInfo now reads the identity block (product, version, current ratings, identity text) of v5.x AGD301/AGD200 hex images. It located the block by counting records after the last 0x0014 segment record; those images fill that segment with code ahead of the block, so DataValid came back false, VerifyCurrents threw "selected FW file doesn't contain 'currents' information", and ValidateFwFiles skipped its product/version cross-checks. The block is now found by its record addresses; v3.x images and AGD155 read exactly as before.
  • AACommServer no longer keeps a phantom channel user when a client's connection is reset while the server is still processing that client's request (an aborted connect, or a peer that dropped mid-request). The dead client stayed registered on its channel for the server's lifetime, so a later client on the same controller could be reported as one of several users and have its FW/FPGA download exclusivity check (NonSingleErr) refused until the server restarted.
  • A push message whose payload legitimately ends in \r or > is no longer corrupted on the ASCII client path — the classifier used to strip all trailing framing characters instead of the single >\r framing pair, eating those payload bytes.
  • The AACommServer's post-reset Ethernet reconnect now retries on a 30-second time budget instead of 5 fixed attempts. A controller that recovers slowly from AReset (11–17+ s observed on AGM800, during which the host link is also down) previously exhausted the attempts and fatally closed the channel ("Post-reset reconnect failed"); it now reconnects as soon as the controller returns. A controller still unreachable when the budget expires triggers the fatal teardown as before.
  • AACommServer connect failures (including the post-reset reconnect FATAL) now report the concrete reason — e.g. Comms: EthernetFailARP (28) - Failed sending an ARP request to the controller IP — instead of the generic "Exception of type 'AACommServerCore.Comms.ConnectException' was thrown." text, in both the client-facing error and the server debug log.
  • Ethernet discovery and connect now work on hosts with multiple NICs: ARP requests are sent from every local NIC whose subnet matches the target (previously SendARP used the OS "best-metric" interface only, so controllers behind other NICs were invisible to Discover, and a direct connect with an empty ARP table failed). Covers subnet discovery, the connect-path reachability check, and the FW/FPGA download ARP warm-ups. (issue #25)
  • A controller reply over Ethernet consisting of only the RS232 terminator (>) with no value — a malformed/incomplete answer to a value query — now surfaces immediately as ERR 4024 instead of stalling until the channel times out and drops the connection. The server can tell it apart from a legitimate OK at the wire frame (a valid reply is [type-byte, …, '>']; the malformed one is a lone '>'), so no genuine reply is affected. (issue #45)
  • 64-bit integer parameter assignments now transmit byte-exact. Every assignment was parsed through double (which carries only 2^53 of integer precision), so an int64 value above ~9·10^15 — e.g. one written verbatim to a .par file by a parameters upload — was silently rounded to a neighboring value on download/write. Plain-integer text now bypasses the double path when user units don't transform the value.
  • AACommServer now honors Message and Close requests only from a socket whose open record names that channel (the membership gate). Previously a misbehaving client that never opened the channel — or sent a duplicate/stale Close — could latch exclusive comms on another client's channel (locking its members out and blocking ShutDownForce) or close the channel under its remaining users.
  • UserProgVarsAdapter.AdaptUserProgMessage no longer drops the per-message User Units flags (SkipUserUnits, AllowUserUnitsConfig) when duplicating the message with adapted task/global-var names — a raw-units message routed through the adapter (e.g. every AAMotion synchronous command) was silently re-scaled, and a sanctioned UU-config write was self-blocked by the Tx-build gate.
  • Spawning the bundled server is now robust across hosts and deployments:
  • A spawned server is always started headless (--headless + redirected stdin) — a net8/native console consumer no longer gets the sidecar's Terminal.Gui monitoring TUI taking over its terminal (GUI apps no longer pop a console either). Started manually, the native host still opens its TUI; a second manual start now exits with a clear "port already in use" message instead of aborting.
  • The spawn wait is a real deadline (15 s, sized to a cold-starting net48 WPF server) polling the port and detecting a child that died during startup — previously a fixed 500 ms grace made a slow cold start fail spuriously and leave an orphaned zero-client server behind.
  • Server resolution probes the application base directory (where the package places the sidecar) before the working directory — a Windows-service host (cwd = System32) now finds its own sidecar. A .NET-Core client prefers AACommServerNative.exe, so a stale net48 AACommServer.exe left behind by an overlay upgrade can no longer be spawned into the old runtime-mismatch crash.
  • The PCSuite-installation registry fallback reads the 32-bit registry view the installer actually writes — 64-bit net48 consumers previously missed an installed PCSuite entirely — and a present key with a missing InstallPath value reports the missing-installation result instead of an exception result.
  • AACommServer's implicit last-client self-shutdown now also covers a client whose channel died under it: when a controller-link FATAL evicts a channel and its last client then disconnects, the server terminates as it does for any last-client death. Previously the fatal path erased the client's record first, so its death went unnoticed and a zero-client server lingered indefinitely — silently attached (whatever its version) by the next client to connect. A graceful Close still deliberately leaves the server running for reconnect flows.
  • AACommServer: a repeated Open on the same client socket is now transactional — a re-Open that fails (unreachable target, disabled channel type) leaves the client's previous channel attachment fully intact. Previously the failure path released the previous membership and erased the client's open record up-front, orphaning the socket so the server's implicit last-client shutdown never triggered. A sole client re-Opening the same channel also no longer bounces the controller link through a momentarily-userless channel.
  • A SendReceive whose timeout expires while the message is still queued behind a slower call no longer disconnects the whole API — it returns ERR Sync: Timeout and the message is never sent (previously a short-timeout call queued behind e.g. a 20 s MotorOn deterministically tore down the connection). The wire-timeout clock now starts when the message is dispatched, matching the server-enforced TimeoutMs; a timeout after the message reached the wire still disconnects, as before.
  • An asynchronous Send callback now fires exactly once, even when the connection tears down (disconnect, controller-link FATAL) before the reply arrives — the in-flight message's callback gets ERR Sync: Session terminated and still-queued messages get PC Suite: ERR 4020, both with IsError set. Previously those callbacks were silently dropped, so a consumer waiting on the callback (e.g. a native-SDK / Python future) waited forever.
  • One AAComm client can no longer stall or corrupt other clients sharing the AACommServer. The server's channel lifecycle was reworked so that slow operations — opening a channel to an unreachable controller, the post-Reset recovery wait, a reply to a client that stopped reading its socket — never block message routing for other clients or channels. Previously, one application connecting to a wrong IP could time out (and force-disconnect) another application's live session, a close during another client's Reset stalled the whole server for the recovery window, and a hung client could wedge its channel indefinitely. Each client socket also gets a dedicated ordered writer, so concurrent replies/pushes can never interleave frame bytes.
  • When a hardware channel dies (controller link lost, timeout), every client of that channel is now notified — including passive clients with no request in flight, which previously discovered the death only when their next command failed.
  • COMTools.GetFTDI_COMs() now lists the vendor-filtered (FTDI / Z-TEK / Prolific) USB-serial ports on net8.0 and native consumers — previously the WMI body was compiled out there (#if !NETCOREAPP), so those consumers got an empty list. Enumeration moved off WMI to the Windows registry (and udev /dev/serial/by-id on Linux), removing AAComm's last System.Management dependency.
  • A failed or partial connection — or a channel FATAL racing an explicit Disconnect — is now reported as a proper ConnectResult instead of being masked by a NullReferenceException thrown from the connection-cleanup path while tearing down a not-yet-fully-open connection.
  • A controller-link FATAL or sync-timeout that tears the connection down *while a Connect/TestConnection is still mid-flight* (reading controller identity) no longer NREs the in-flight connect. Connection teardown is now serialized on the connect lock, so the receive-thread FATAL handler can't dispose the handler out from under the connecting thread. Surfaced by connect/close churn against a saturated server.
  • Rapidly closing a connection (tool-navigation churn) no longer emits a spurious comms error / debug assert from the binary-IPC receive loop racing the socket close — the disposed-socket teardown is now handled as the normal close it is.
  • AACommServer no longer deadlocks when a client disconnects at the same moment one of its channels hits a FATAL timeout. A lock-order inversion between the channel registry and a channel's queue could wedge the server (hanging any connected client) until the process was killed.
  • About-data parsing no longer overflows on ScalingFact values emitted as unsigned float bit patterns.
  • Socket teardown no longer crashes the process on macOS/Linux hosts: connection-reset/abort detection now uses platform-normalized SocketErrorCode instead of the Windows-only raw error 10054 (affected both the binary and ASCII IPC clients). Connection-aborted, network-reset, and shutdown errors now also report the connection as lost instead of a generic error.
  • A reply that fails inbound post-processing (e.g. a malformed ParamAbout answer) no longer tears down the whole session — conversion degrades to the raw reply string. Previously the exception unwound through the binary-IPC frame dispatch and every subsequent call failed with "PC Suite: ERR 4020".
  • A controller link that dies mid-session (reset, cable pull, or clean remote close) now reliably surfaces as a connection-loss error and the API recovers with a plain reconnect. Previously a clean remote close left the channel half-dead (every command timing out individually), and the racing teardown paths could crash the host process.
  • net8.0 / .NET-Core consumers received the net48 AACommServer.exe as their bundled server and crashed it on launch (a System.Runtime version mismatch when the net48 process loaded the consumer's net8.0 assemblies). Each consumer now gets a server matching its own runtime (see Changed). The net48 sidecar additionally ships its full runtime closure (it had been missing Google.Protobuf.dll).
  • net8.0 / .NET-Core (and native C-ABI) clients could not connect over CAN — a client-side WMI Kvaser-presence pre-check was compiled out on .NET Core (#if !NETCOREAPP) and always reported "no device", so the connect failed with RequiredConnectionUnavailable before the (working) CAN transport was reached. The presence check now runs server-side via canlib (cross-platform, excluding virtual channels), so CAN connects succeed from net8.0 / native clients; when the host has no physical Kvaser interface the connect returns the new ConnectResult.CANDeviceNotConnected (see Added).

Fixed 15

  • Connect no longer returns false on a busy machine while the server is running. It gates on CommAPI.IsAACommServerRunning, whose loopback probe used to depend on ThreadPool scheduling and so reported a listening server as absent under CPU pressure — reported only through a Debug.WriteLine, making it look like a silent connect failure. Fixed in AAComm; see its changelog.
  • AAMotionAPI.AutoCorner: the cornerAxes argument was incorrectly passed to GetGroup(), whose dictionary keys are only AxisRef.A (or AxisRef.B on AGM800). Every call path was broken — GetGroup(axis) with axis = AxisRef.A resolved to a 1-axis group (rejected by the controller as CNC_FIFO_WRONG_NUM_OF_INVOLVED_AXES), and axis = AxisRef.A | AxisRef.B caused a KeyNotFoundException on the unguarded indexer. Now resolves the group via GetGroup(AxisRef.A) like all other CNC facade methods, and forwards the full mask to the wire segment. Source- and binary-compatible; no signature or ABI change.
  • AAMotionAPI.OpenAACommServer(string) and CommAPIInterface.OpenAACommServer(string) now spawn the server through the AAComm spawn contract (headless + redirected stdin, correct working directory, socket-ready polling with a child-death probe) instead of a bare Process.Start + fixed 1.5 s sleep — a slow cold start, a lost bind race, or an interactive native host no longer yields a false "started" (or a TUI taking over the consumer's terminal). AAMotionAPI.OpenAACommServer() no longer latches "started" after a FAILED start: the first failure (missing sidecar, blocked port) previously made every later call a silent no-op even after the environment was fixed.
  • The *AndWait motion waits (MoveAbsAndWait, MoveRelAndWait, the two-speed and repetitive variants) now poll the controller's in-target status live, never through the FastReadCache. With FastReadEnabled, a cached pre-move InTargetStat=4 (the axis parked on its previous target) — or a value stranded by a link failure, which never invalidates cache entries — could satisfy the wait instantly, reporting "target reached" for a move that never happened.
  • MotionController.TryReconnect no longer trusts the raw socket alone: a logically-connected link is verified by ping (where the address is a real IP) before the call short-circuits to success, so a pulled cable / network partition now triggers a real disconnect-and-reconnect instead of "reconnected" with a dead link — this also makes IsConnected's auto-reconnect path honest. With no requested address and no last known address the call now fails instead of silently targeting a hardcoded default IP (a reachable but unintended controller could be connected). A successful reconnect to an explicit new address now updates the last known address, so reachability probes and later reconnects track the live link, not the device the controller left behind.
  • SendBulkCommandString no longer reports success when an error rides in a non-first segment of the bulk reply (e.g. OK>OK>ERR 4010) — the whole-reply error flag misses embedded segments, so classification is now per-segment against the full reply taxonomy (ERR / BOOT ERR / PC Suite: ERR).
  • Controller replies carrying int/long values are now parsed culture-invariantly, matching the float/double path. On a machine whose culture uses a non-ASCII negative sign (several ICU cultures on modern .NET), a negative reply like -123 failed to parse and read as 0; parameter values written to the controller now also format invariantly on every path.
  • MotionController.IsConnected no longer reports false for healthy non-IP connections: the ICMP reachability probe now runs only when the controller was connected via a real IP address — a Simulator / serial / CAN connection reports the logical connection state (previously the unparseable address failed the ping and the property was permanently false), and when no address is known the property no longer pings a hardcoded default IP (another device's reachability was reported as this controller's).
  • Bulk parameter upload/download keeps request↔reply alignment: an empty reply segment no longer shifts every later reply onto the previous command's slot (misattributed values in the .par file / on the controller), and a short bulk reply pads the unanswered tail with the no-reply error filler instead of re-sending the boundary commands (a re-send could execute a parameter write twice).
  • BulkCommandParser(index, response) now honors its documented 1-based contract: index 1 returns the first segment (previously the second), the last index returns the last segment (previously threw IndexOutOfRangeException), and out-of-range indexes return null.
  • Tearing down one MotionController no longer harms the others in the process. A garbage-collected (undisposed) controller's finalizer called Shutdown() — which could take down the shared AACommServer — and its disconnect cleared the process-wide parameter-metadata cache under live sibling controllers, silently degrading their float parameter reads/writes to int handling until their next connect. The finalizer now only disconnects its own controller, Dispose() suppresses the finalizer, disconnect no longer clears the shared cache (each connect atomically rebuilds it), and only an explicit Shutdown() touches the server. The native aamotion SDK's Release/Disconnect likewise no longer shut the server down — the explicit Shutdown export is the only path that may.
  • Enabling the fast-read cache no longer risks tearing down the connection when any call slower than ~200 ms is in flight — the background cache refresh used a hardcoded 100 ms timeout, tighter than any other command's wire budget; it now uses the default message timeout (a slow reply just delays the next refresh while readers serve the cached value).
  • FastReadCache reads now honor validity: a registered-but-never-refreshed entry is a cache miss (falls back to a live read) instead of a fabricated 0, and a value whose refresh failed is not served stale. Disconnect invalidates all entries (no unbounded-stale values while no refresh can run) and the background refresh no-ops while disconnected instead of spamming an error event per interval — throttled to an idle poll (500 ms) so a 1 ms-interval cache no longer burns ~1000 no-op tasks per second while disconnected; it resumes the configured cadence by itself after a reconnect.
  • FastReadCache.Dispose() no longer throws ObjectDisposedException on any cache that was ever used (its own disposed-guard fired mid-dispose) — on .NET Framework a garbage-collected undisposed cache could take the process down from the finalizer thread.
  • UploadParameters() / DownloadParameters() summaries no longer count API-synthesized error replies (PC Suite: ERR …, BOOT … ERR, e.g. from a connection lost mid-transfer) as successes — error classification now matches the full AAComm reply taxonomy instead of only controller ERR … replies.

  • Messaging — Client.query (synchronous), Client.send (returns a concurrent.futures.Future[Reply]), the get / set parameter conveniences, and Client.identity.
  • Callbacks surfaced from the native session — Client.on_push, on_error, on_longop_started, on_longop_ended.
  • User units — Client.get_user_units_enabled / set_user_units_enabled.
  • Client.record(...) -> Recording — controller data recording with trigger configuration and a bounded wait-for-completion poll.
  • Downloads — Client.download_firmware, Client.download_fpga and user-program download, each with an optional on_progress callback.
  • An exception hierarchy in errors.py — AACommError and the ServerError / ConnectionError / Timeout / ControllerError specialisations.
  • py.typed — the package ships inline type information.
  • _enums.py and _abi.py are generated from the AAComm C# surface (LF-pinned, CI diff-gated), so the Python enum and export surfaces cannot drift from the controller's.
  • Two independent ABI guards. aacommpy/tests/test_abi_contract.py is pure Python: it asserts the hand-maintained _native.py ctypes binding against the generated _abi.py export surface, so an untracked C-ABI change fails without a native library or hardware. aacommpy/tests/test_native_smoke.py is the runtime half, loading the packed library and checking its real aacomm_abi_version(). Publish-AACommPy.ps1 runs the contract test before the long NativeAOT build and the smoke test after it, against the bundle it just packed.
