AAMotion Native SDK

A native C ABI over the high-level AAMotion client — drive an Agito motion controller from C, C++, Python, or any language with a C FFI, with no .NET runtime on the target. The library is NativeAOT-compiled per platform and ships as a single shared library plus two headers. It replaces the retired Windows-only C++/CLI AAMotionCPP + AGAAMotion.

Platform Library Link with
Windows x64 aamotion.dll aamotion.lib (import lib)
Linux x64 libaamotion.so -laamotion
macOS x64 / arm64 libaamotion.dylib -laamotion

Every platform ships the same two headers: aamotion.h (the API) and aamotion_enums.h (aamotion_controller_type_t / aamotion_axis_ref_t and the status/descriptor enums, generated from the AAMotion C# enums — the single source of truth). aamotion.h is the authoritative per-function reference; this guide is the conceptual overview.

Status: validated on win-x64 against a live AGM800 (connect, reads, motor on/off, relative / absolute / jog motion, GenData read/write, IO, and the enum/error description getters all exercised under NativeAOT). linux-x64 builds and packs in CI; macOS builds are pending a build runner.

Getting the library

  • .NET (P/Invoke): add the Agito.AAMotion.Native NuGet — aamotion.dll / libaamotion.so lands next to your build output automatically; [DllImport("aamotion")].
  • C / C++: take the C/C++ archive (the include/ headers + per-RID native libs, the AACommServerNative AACS daemon, and a sample). The session opens a server implicitly on first connect, so keep the daemon beside the library; no .NET runtime is required on the target.
  • Python / other FFI: drop the platform library beside your script and ctypes.CDLL it (it is inside both artifacts above). A ctypes-over-native AAMotionPy wheel is a possible future consumer of this channel — not built yet.
  • From source: build each RID on its own OS (NativeAOT cannot cross-compile) with dotnet publish -r <rid>.

Distribution note: the Agito.AAMotion.Native NuGet and the C/C++ archive (win-x64 + linux-x64) ship on the public Software/AAMotion-Native release line at https://github.com/akribis-agito/Agito-Releases/releases, alongside each managed Agito.AAMotion release. They are not on nuget.org — the C ABI is exact-match gated pre-1.0 and the package carries only the RIDs above. The package version is locked to the managed Agito.AAMotion.

Architecture in one paragraph

The SDK is a client, exactly like the AAComm native SDK. It wraps the managed net8 AAMotion client, which in turn talks to AACS (the AAComm server) — a separate, shared process that owns the actual controller connection. aamotion_initialize brings up / attaches to a local AACS automatically (the managed connect path spawns or locates it), then aamotion_connect opens a controller channel through it. AACS is not embedded in the SDK; it is resolved/launched as its own process. AAMotion is the motion layer (motor on/off, point-to-point and interpolated moves, homing, IO, force, vector, PEG, CNC groups, program control); for raw controller-message traffic the AAComm native SDK is the lower layer.

Quick start — C / C++

#include "aamotion.h"
#include <stdio.h>

int main(void)
{
    /* aamotion_initialize brings up / attaches to AACS and builds a controller of the given type.
       AAMOTION_CONTROLLER_TYPE_AGM800 == 10 (the ProductTypes ID, from aamotion_enums.h). */
    aamotion_controller c = aamotion_initialize(AAMOTION_CONTROLLER_TYPE_AGM800);
    if (!c) return 1;

    /* aamotion_connect to the controller through AACS. fastArk / enableAutoReconnect are 0/1 flags. */
    if (aamotion_connect(c, "172.1.1.101", 0, 0))                     /* factory-default address */
    {
        aamotion_motor_on(c, AAMOTION_AXIS_REF_A);                       /* AAMOTION_AXIS_REF_A == 1 */
        aamotion_move_relative(c, AAMOTION_AXIS_REF_A, 10000, 5000, 100000, 100000); /* dist, speed, accel, decel */

        char reply[256];
        if (aamotion_send_command_string(c, "APos", reply, (int)sizeof(reply)))
            printf("APos -> %s\n", reply);

        aamotion_motor_off(c, AAMOTION_AXIS_REF_A);
    }

    aamotion_disconnect(c);   /* closes the link AND frees the handle */
    aamotion_release(c);      /* safe even after aamotion_disconnect — Free is null/double-free tolerant */
    return 0;
}

Build (Windows, from a x64 Native Tools prompt or after vcvars64):

cl /nologo sample.c /I path\to\include /link path\to\aamotion.lib
:: aamotion.dll must sit next to the .exe or on PATH at run time

Build (Linux / macOS):

cc sample.c -I path/to/include -L path/to/lib -laamotion -o sample
LD_LIBRARY_PATH=path/to/lib ./sample        # macOS: DYLD_LIBRARY_PATH

Quick start — Python (ctypes)

No bindings package required — load the shared library directly. Set restype / argtypes so the opaque handle and the bool/buffer arguments marshal correctly. At the ABI a C bool is a 1-byte 0/1, so declare it ctypes.c_bool.

import ctypes

lib = ctypes.CDLL("./libaamotion.so")          # "aamotion.dll" on Windows, "libaamotion.dylib" on macOS

# Opaque handle is void*. aamotion_initialize takes a aamotion_controller_type_t int and returns the handle.
lib.aamotion_initialize.restype  = ctypes.c_void_p
lib.aamotion_initialize.argtypes = [ctypes.c_int]
lib.aamotion_connect.restype  = ctypes.c_bool
lib.aamotion_connect.argtypes = [ctypes.c_void_p, ctypes.c_char_p, ctypes.c_bool, ctypes.c_bool]
lib.aamotion_motor_on.argtypes      = [ctypes.c_void_p, ctypes.c_int]
lib.aamotion_motor_on.restype       = ctypes.c_bool
lib.aamotion_move_relative.argtypes = [ctypes.c_void_p, ctypes.c_int, ctypes.c_int, ctypes.c_int, ctypes.c_int, ctypes.c_int]
lib.aamotion_move_relative.restype  = ctypes.c_bool
lib.aamotion_send_command_string.argtypes = [ctypes.c_void_p, ctypes.c_char_p, ctypes.c_char_p, ctypes.c_int]
lib.aamotion_send_command_string.restype  = ctypes.c_bool

AGM800 = 10        # AAMOTION_CONTROLLER_TYPE_AGM800
AXIS_A = 1         # AAMOTION_AXIS_REF_A

c = lib.aamotion_initialize(AGM800)
if c and lib.aamotion_connect(c, b"172.1.1.101", False, False):   # factory-default address
    lib.aamotion_motor_on(c, AXIS_A)
    lib.aamotion_move_relative(c, AXIS_A, 10000, 5000, 100000, 100000)   # dist, speed, accel, decel

    buf = ctypes.create_string_buffer(256)
    if lib.aamotion_send_command_string(c, b"APos", buf, 256):
        print("APos ->", buf.value.decode())

    lib.aamotion_motor_off(c, AXIS_A)

lib.aamotion_disconnect(c)      # closes the link AND frees the handle
lib.aamotion_release(c)         # safe after aamotion_disconnect

To receive controller error events, declare the matching CFUNCTYPE and register it. Keep a Python reference to the CFUNCTYPE instance for as long as it can fire — if it is garbage-collected the library calls a freed trampoline:

ERROR_CB = ctypes.CFUNCTYPE(None, ctypes.c_int, ctypes.c_char_p, ctypes.c_char_p)

def _on_error(code, message, exception):
    print("error", code,
          message.decode() if message else "",
          exception.decode() if exception else "")

error_cb = ERROR_CB(_on_error)          # keep this alive for the session

lib.aamotion_set_error_occurred_handler.argtypes = [ctypes.c_void_p, ERROR_CB]
lib.aamotion_set_error_occurred_handler(c, error_cb)

Core contracts

Handle lifecycle

aamotion_initialize(controllerType) returns an opaque aamotion_controller handle (a token from an internal handle table mapping to a managed AAMotion aamotion_controller — never a raw pointer, so a stale or forged handle resolves to nothing instead of undefined behavior), or NULL on failure — including an unknown controller type and an AACS that could not be spawned/reached. One handle owns at most one controller connection. Free it with aamotion_release(h) — or aamotion_disconnect(h), which closes the link and frees the handle. The teardown is null- and double-free-tolerant: the C++/CLI predecessor's contract of calling both aamotion_disconnect (which frees) and a later aamotion_release is safe, and a NULL/stale handle degrades gracefully (every export returns false/0 rather than crashing). For concurrent controllers, create multiple handles.

The optical-coupling API adds a second opaque handle, aamotion_optical_coupling, built from a controller handle with aamotion_optical_coupling_create(h) and freed with aamotion_optical_coupling_release(oc). It does not own the controller connection — release it before releasing the controller handle it was created from.

The connect sequence

  1. aamotion_initialize(controllerType) — builds the controller and brings up / attaches to AACS. Pass a aamotion_controller_type_t value from aamotion_enums.h (e.g. AAMOTION_CONTROLLER_TYPE_AGM800 = 10) — these are the product-type IDs, not ordinals.
  2. aamotion_connect(h, deviceAddress, fastArk, enableAutoReconnect) — opens the controller channel through AACS (e.g. the factory-default Ethernet IP "172.1.1.101"). fastArk / enableAutoReconnect are bool. Returns true on success.
  3. aamotion_is_connected(h) — true while the channel is open and (for IP-connected controllers) the device answers an ICMP ping the call performs synchronously; with auto-reconnect enabled a failed probe runs a full reconnect attempt inline (seconds to tens of seconds worst case, 5 s cooldown). Not a cheap flag read — budget polling accordingly.
  4. aamotion_disconnect(h) — closes the channel and frees the handle; or aamotion_release(h) to free without a prior disconnect.

bool and result conventions

Most exports return a C bool — true on success, false on failure (a 1-byte 0/1 at the ABI). A NULL handle, a NULL string argument, an unresolvable/stale handle, or an internal exception all map to false/0 — exceptions never cross the boundary. This bool-return convention is deliberately different from aacomm.*'s uniform aacomm_status return: aamotion.* keeps the success/failure contract of the retired AGAAMotion wrapper it replaces, so the two SDKs are each internally consistent rather than mutually identical.

int-returning getters (aamotion_read_gen_data, aamotion_get_d_out_port, aamotion_get_d_in_port, and the whole Slow-Logger and optical-coupling read families) return the controller value directly — and return 0 on any failure (bad handle, not connected, controller ERR), indistinguishable from a legitimate 0. When that matters, read via aamotion_send_command_string and check its bool instead.

void fire-and-forget setters (the aamotion_force_curr_set_* family, the PEG/lock setters, aamotion_set_vector_param, the two-speed aamotion_move_*_two_speed non-wait variants, …) give no success feedback at all — mirroring AGAAMotion's void contract. Failures still surface through the error callback; use it (or a follow-up read) when you need confirmation of a setter.

Per-axis int axis arguments take an aamotion_axis_ref_t bit value (AAMOTION_AXIS_REF_A = 1, AAMOTION_AXIS_REF_B = 2, … combinable). A plain int speed/accel/decel is passed verbatim — 0 is a literal 0, not "use default".

Strings: the fixed-buffer contract

Output strings are UTF-8. The string functions — aamotion_send_command_string / aamotion_send_bulk_command_string, the Get*Des enum-description getters, and aamotion_get_error_description_by_code — take a caller-supplied writable buffer plus its size (char* buf, int size): the result is written truncated to fit and always NUL-terminated. The Get* description getters return true when a non-empty description was written, false (writing nothing) on an unknown value, empty result, or NULL/zero buffer. aamotion_send_bulk_command_string is Ethernet-only.

The error callback

Register a session-level error handler with:

typedef void (*aamotion_error_occurred_cb)(int errorCode, const char* message, const char* exception);
void aamotion_set_error_occurred_handler(aamotion_controller h, aamotion_error_occurred_cb cb);
void aamotion_clear_error_occurred_handler(aamotion_controller h);

The callback fires on AAMotion's firing thread, never on your calling thread — keep it short and thread-safe; marshal real work to your own thread/queue. The const char* arguments (message, exception) are owned by the library and valid only for the duration of the call — copy them if you need them later; do not free them. Only one handler is held per handle; a later aamotion_set_error_occurred_handler replaces the earlier one, and aamotion_clear_error_occurred_handler removes it.

Enum and error descriptions

The Get*Des(int value, char* buf, int size) family maps an integer value of the matching enum in aamotion_enums.h to its human-readable description (e.g. aamotion_get_con_flt_des(1003, …) → "Encoder disconnected"). aamotion_get_error_description_by_code(int errorCode, …) resolves a controller error code. Both follow the fixed-buffer contract above.

ABI versioning & stability

int32_t aamotion_abi_version(void);

The SDK carries two version numbers, for two different purposes:

  • Package version — the SemVer of the aamotion.* library / Agito.AAMotion.Native NuGet, version-locked to the managed Agito.AAMotion ($(AAMotionVersion); the native package ships on its own release line off the back of each managed release — see AAComm/docs/native-aot-sdk.md). This is what you pin in a package reference.
  • aamotion_abi_version() — a soname-style breaking-generation number, the C-ABI contract. It is bumped only on a breaking change: a changed or removed export signature, a callback-signature change, or changed semantics. Additive changes — new exports, new enum values — never bump it (they cannot break a compiled consumer). It returns its value directly (it cannot fail) and takes no handle; the same value is the AAMOTION_ABI_VERSION macro in the generated aamotion_enums.h. Generation 1 is the first shipped ABI (pre-release increments carried no compatibility meaning and were reset).

Consumer rule — exact-match gate. Call aamotion_abi_version() once at load and reject a library whose value does not equal AAMOTION_ABI_VERSION from the headers your binding was built against — coherent with the bump policy, because the number only moves when your binary genuinely cannot run. The committed include/aamotion.abi.txt records the exact export surface for the generation; aamotion_enums.h and the manifest are generated from the C# source and CI diff-gated, while aamotion.h is hand-maintained — the manifest diff is what forces it to be updated in review. Always build against the aamotion.h that ships with the library you load.
