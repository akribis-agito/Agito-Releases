DownloadParameters(MotionController, string, bool, Action<int>, Action<ParamHandlingSummary, string>) 

Asynchronously writes controller parameters from a .par file (local file -> controller disk).


Follows the PCSuite "Parameters Download" convention: reads the .par file, validates parameters against
the connected controller, then sends each as a SET command. Ethernet connections use bulk messages
(up to 50 per packet); other channels send one by one.


After a successful download, optionally sends "ASave" plus per-axis "CalcFilters" to persist parameters to flash.


The call is non-blocking; subscribe to the callbacks to be notified of progress and completion.

public static void DownloadParameters(MotionController controller, string filePath, bool calcAndSave = true, Action<int> onProgress = null, Action<ParamHandlingSummary, string> onDone = null)

Parameters

controller MotionController

Connected motion controller.

filePath string

Full path of the source .par file.

calcAndSave bool

If true (default), sends "ASave" + per-axis "CalcFilters" after a download that ended without error, persisting parameters to flash; a download that stopped partway is never saved. Set to false to leave parameters in RAM only.

onProgress Action<int>

Optional callback invoked with progress percentage (0-100). A throw from it is reported in onDone's error. A throw while replies are still arriving aborts the transfer.

onDone Action<ParamHandlingSummary, string>

Optional callback invoked on completion. Argument 1 is a ParamHandlingSummary with statistics (null on early failure); argument 2 is an error description (empty string on success).

Examples

AAMotionAPI.DownloadParameters(controller, @"C:\Params\backup.par",
    calcAndSave: true,
    onProgress: pct => Console.WriteLine($"Download progress: {pct}%"),
    onDone: (summary, err) => {
        if (string.IsNullOrEmpty(err))
            Console.WriteLine($"Download OK: {summary.SuccessCount}/{summary.TotalCount} parameters");
        else
            Console.WriteLine($"Download failed: {err}");
    });

Remarks

All the axes must share their Global User Units. A single speed and accel are applied to the vector distance over every axis, so the axes' positions must be commensurable and their velocities and accelerations must share a unit: every axis must carry the same unit NAME in the position, velocity and acceleration groups. Different scaling factors under one name are fine — two encoder resolutions on one gantry still measure millimetres. An axis with User Units off is on controller counts, which does not match a scaled axis; where a group carries no unit name, the axes must share its factor instead.

Each axis's units are read from the axis itself — from the communication API it was built on, not from controller, which is only the channel the failure is reported on. The axes must therefore be the SDK's own, from GetAxis(AxisRef) or AxisList; a consumer's own ISingleAxis wrapper, decorator or mock carries no axis identity, its units cannot be read, and the call is refused rather than waved through.

Axes that disagree make the call return false and command nothing — the refusal happens before any parameter is read from or written to the controller — and raise ErrorOccurred with code -1, the name of the method called, and a message naming the axes and the group. With a null controller the refusal is silent: the call still returns false, there is just nowhere to report it. Setting UseUserUnits to false puts every axis back on controller counts, which always matches.

Array of relative distances for each axis

Returns true if send is successful; false when the axes disagree on their User Units, when the two arrays differ in length, or when an axis is not motor-on

Remarks

All the axes must share their Global User Units. A single speed and accel are applied to the vector distance over every axis, so the axes' distances must be commensurable and their velocities and accelerations must share a unit: every axis must carry the same unit NAME in the position, velocity and acceleration groups. Different scaling factors under one name are fine — two encoder resolutions on one gantry still measure millimetres. An axis with User Units off is on controller counts, which does not match a scaled axis; where a group carries no unit name, the axes must share its factor instead.

Each axis's units are read from the axis itself — from the communication API it was built on, not from controller, which is only the channel the failure is reported on. The axes must therefore be the SDK's own, from GetAxis(AxisRef) or AxisList; a consumer's own ISingleAxis wrapper, decorator or mock carries no axis identity, its units cannot be read, and the call is refused rather than waved through.

Axes that disagree make the call return false and command nothing — the refusal happens before any parameter is read from or written to the controller — and raise ErrorOccurred with code -1, the name of the method called, and a message naming the axes and the group. With a null controller the refusal is silent: the call still returns false, there is just nowhere to report it. Setting UseUserUnits to false puts every axis back on controller counts, which always matches.

UploadParameters(MotionController, string, Action<int>, Action<ParamHandlingSummary, string>) 

Asynchronously reads all controller parameters and saves them to a .par file (controller disk -> local file).


Follows the PCSuite "Parameters Upload" convention: queries every supported parameter, writes them with
header (product type, firmware/FPGA version, date, file checksum) to a plain ASCII .par file.


Ethernet connections use bulk messages (up to 50 per packet); other channels send one by one.


The call is non-blocking; subscribe to the callbacks to be notified of progress and completion.

public static void UploadParameters(MotionController controller, string filePath, Action<int> onProgress = null, Action<ParamHandlingSummary, string> onDone = null)

Parameters

controller MotionController

Connected motion controller.

filePath string

Full path of the destination .par file. Will be created or overwritten.

onProgress Action<int>

Optional callback invoked with progress percentage (0-100). A throw from it is reported in onDone's error. A throw while replies are still arriving aborts the transfer; a throw on the final 100% call comes after the .par file is written and does not undo it.

onDone Action<ParamHandlingSummary, string>

Optional callback invoked on completion. Argument 1 is a ParamHandlingSummary with statistics (null on early failure); argument 2 is an error description (empty string on success).

Examples

AAMotionAPI.UploadParameters(controller, @"C:\Params\backup.par",
    onProgress: pct => Console.WriteLine($"Upload progress: {pct}%"),
    onDone: (summary, err) => {
        if (string.IsNullOrEmpty(err))
            Console.WriteLine($"Upload OK: {summary.SuccessCount} parameters, checksum 0x{summary.Checksum:X}");
        else
            Console.WriteLine($"Upload failed: {err}");
    });
