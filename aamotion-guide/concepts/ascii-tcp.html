    直连 TCP 读写 ASCII 关键字¶

    上位机用自己的 TCP 客户端连接控制器。客户示例端口为 50000，实际值以控制器配置为准。使用控制器地址，不需要启动 AACommServer。同一条连接内按发送、收完响应、发送下一条的顺序工作。

    操作 发送的 ASCII 字符及结尾 回复
    单条查询 AASpeed + 00 00 00 00 03 E8 3E 表示 1000。首字节保留，接下来四字节为有符号大端整数。
    单条赋值 AAGenData[800]=799 + 00 实测成功应答 00 3E。
    批量查询 LASpeed;BSpeed;CSpeed + 00 1000>2000>3000>，结果顺序与请求相同。
    批量赋值 LAGenData[800]=1;AGenData[801]=2 + 00 示例台架返回 OK>OK>。逐项判断并查询读回。

    AASpeed 中第一个 A 是单条模式，第二个 A 属于轴关键字 ASpeed。批量模式前缀是 L，中间用分号，最后一个命令后直接放字节 0x00。表中的 00 是一个字节。

    TCP 可能拆分回复。整数查询收满六字节再解析，整数内部也可能出现 0x3E。控制器二进制错误的格式是保留字节、两字节大端错误码、0x3E。示例在读取短错误帧后等到超时或断开才报告错误，随后关闭连接，避免把回复残片留给下一条请求。这里只用整数关键字，其他数据类型按对应关键字定义解码。

    批量响应按 > 收齐每一项。当前通信实现将 L 定义为出错后继续，I 定义为遇错停止。写入批次可能部分生效，超时后重新连接并读回，避免直接重发。写操作示例仅使用独占的 GenData 下标，按固件映射选择，避开正在运行的脚本和设备工艺数据。

    三语言 Demo¶

    源码位于 samples/app/ascii。默认只读 ASpeed、AMotorOn 和 AMotionStat。追加下标和数值后执行读旧值、写入、读回；例如使用测试台确认空闲的 800 号槽。

    python keyword_tcp.py HOST --port 50000
python keyword_tcp.py HOST --port 50000 --write 800 799

dotnet run --project KeywordTcp.csproj -- HOST 50000
dotnet run --project KeywordTcp.csproj -- HOST 50000 800 799

cl /EHsc /std:c++17 keyword_tcp.cpp
keyword_tcp.exe IPV4 50000
keyword_tcp.exe IPV4 50000 800 799

    C# 需要 .NET 8，C++ 需要 Windows 的 Visual Studio 开发者命令行。用实际控制器地址替换 HOST 或 IPV4。位操作、轴启动和 I/O 逻辑可在读写通信验证后按应用配置实现。
