    SlowLogger（慢速记录器）¶

    慢速记录器适合长时间记录：控制器按 LoggerGap 的间隔把选定的参数放进 FIFO，上位机定期上传。和高速记录器相比，它采样慢，但可以一直运行（例如记录一整天的温度、跟随误差）。FIFO 满时的处理方式由 LoggerFullMod 决定，丢失的数据包计入 LoggerLostPackets。各关键字的详细说明见 LoggerParams。

    配置与上传¶

    ConfigureSlowLogger 一次设置采样间隔、FIFO 满时的处理方式和要记录的参数；SDK 自动把参数名转换成控制器需要的 CAN 编号写入 LoggerParams[]。LoggerUpload() 返回控制器的原始回复文本；LoggerUpload(同样的参数) 按配置的参数解析并按用户单位换算，返回 LoggerDataContainer。

    独立小 Demo：慢速记录 2 秒

    什么时候用

    长时间监测（数小时到数天）：温度、电流、跟随误差的趋势。

    函数原型

    // MotionController
// Convenience helper to configure slow logger parameters in one call.
// loggerGap: 采样间隔（`LoggerGap`），必须大于 0
// loggerFullMode: FIFO 满时的处理（`LoggerFullMod`），默认 0
// parameterSpecifications: 要记录的参数，如 `"APos"`、`"AVel[1]"`，也可以是 `SlowLoggerParameter` 或 CAN 编号。数组参数必须带下标，标量不能带
void ConfigureSlowLogger(int loggerGap, int loggerFullMode = 0, params object[] parameterSpecifications);

// Uploads slow logger data from the controller.
// 返回值: Response string from log upload containing the data packets.
string LoggerUpload();

// Uploads the logger data and resolves it against the parameters the caller configured — the same specifications `MotionController.ConfigureSlowLogger` took, in the same order — so every value comes back resolved and scaled the way every other read does. AAMotion keeps no record of the configuration; the caller supplies it. A `null` specification is skipped, as `MotionController.ConfigureSlowLogger` skips it. An error reply raises `MotionController.ErrorOccurred` and yields no packets.
// parameterSpecifications: 要记录的参数，如 `"APos"`、`"AVel[1]"`，也可以是 `SlowLoggerParameter` 或 CAN 编号。数组参数必须带下标，标量不能带
LoggerDataContainer LoggerUpload(params object[] parameterSpecifications);

    // Samples chosen parameters continuously and pushes packets to the PC without a trigger. Upload often enough to keep the controller's FIFO from filling. The int getters return 0 on ANY failure. Configures the logger in one call. @param gap Sampling gap (ALoggerGap), > 0. @param fullMode What a full FIFO does (ALoggerFullMod): 0 pause, 1 overwrite the oldest data. @param paramNames paramCount names to record, e.g. "APos", "AVel[2]". NULL or paramCount 0 sets gap and fullMode only and leaves the recorded parameters alone.
// controller: 控制器对象 / 句柄
// gap: 采样间隔
// fullMode: FIFO 满时的处理
// paramNames: C：参数名数组；NULL 表示只设置间隔和模式
// paramCount: 参数个数
bool aamotion_configure_slow_logger(aamotion_controller controller, int gap, int fullMode, const char** paramNames, int paramCount);

// Fetches the packets waiting on the controller into response: "count,t1,p1,p2,...,t2,p1,p2,...,0" - the packet count, then per packet its timestamp and one value per configured parameter in configured order, then a 0 end marker. @return false for a controller error (the error callback has it) or an empty reply.
// controller: 控制器对象 / 句柄
// response: C：接收原始数据的缓冲区
// responseSize: 缓冲区字节数
bool aamotion_logger_upload(aamotion_controller controller, char* response, int responseSize);

    参数

    参数 类型 说明
    loggerGap int 采样间隔（LoggerGap），必须大于 0
    loggerFullMode int FIFO 满时的处理（LoggerFullMod），默认 0
    parameterSpecifications object[] 要记录的参数，如 "APos"、"AVel[1]"，也可以是 SlowLoggerParameter 或 CAN 编号。数组参数必须带下标，标量不能带
    controller aamotion_controller 控制器对象 / 句柄
    gap int 采样间隔
    fullMode int FIFO 满时的处理
    paramNames const char** C：参数名数组；NULL 表示只设置间隔和模式
    paramCount int 参数个数
    response char* C：接收原始数据的缓冲区
    responseSize int 缓冲区字节数

    返回值

    C# LoggerUpload() 返回原始文本，带参数的重载返回解析后的数据；C 版本成功返回 true。

    注意

    • C# 调用 ConfigureSlowLogger 会停用记录器并重写通道表。通道下标从 1 开始，最多 40 个，每 5 个槽位一组。确认 PCSuite 或其他程序没有在使用记录器，再修改配置。
    • 每次 LoggerUpload 只取出已经完整、能放入本次回复的数据包，并释放它们占用的 FIFO 空间。只让一个客户端负责上传。一次返回 0 包也可能是暂时的空回复。
    • 置 LoggerOn = 0 停止采样，已经缓存在 FIFO 中的数据仍可上传。需要完整尾段时，停止后继续按固件行为读取剩余包。
    • 解析时传入与配置完全相同的参数、轴、数组下标及顺序。发生通讯错误时解析重载可能给出空结果，配合 ErrorOccurred 判断。

    示例

    c.ConfigureSlowLogger(10, 0, "APos", "AVel[1]", "BPos");
try
{
    c.LoggerOn = 1;
    System.Threading.Thread.Sleep(100);
    Console.WriteLine(c.LoggerUpload());
}
finally
{
    c.LoggerOn = 0;
}

    const char* params[] = { "APos", "AVel[1]", "BPos" };
aamotion_configure_slow_logger(h, 100, 0, params, 3);
aamotion_set_logger_on(h, 1);
/* ... */
char* reply = malloc(1 << 20);
if (aamotion_logger_upload(h, reply, 1 << 20))
    printf("%zu bytes of raw logger data\n", strlen(reply));
printf("lost packets: %d\n", aamotion_get_logger_lost_packets(h));
aamotion_set_logger_on(h, 0);
free(reply);
    SDK 原文注释（英文）
    • ConfigureSlowLogger(int, int, object[]) — Convenience helper to configure slow logger parameters in one call.
    • LoggerUpload() — Uploads slow logger data from the controller. Returns: Response string from log upload containing the data packets. Raw: the controller's reply text exactly as received — no float resolution and no User Units scaling. For resolved, scaled values call MotionController.LoggerUpload with the specifications given to MotionController.ConfigureSlowLogger. Data Format: The response string contains comma-separated integer values with the following structure: First value: Number of data packets in this upload response For each data packet (repeated): Controller timestamp (in units of loggerGap * 16) Parameter values (in the order configured by LoggerParams) Last value: Always 0 (indicates end of data) Timestamp Calculation: The timestamp represents the sample time relative to when logging started. Formula: timestamp = packetIndex * loggerGap * 16 Examples: If loggerGap = 1: packet 0 = 0116 = 0, packet 1 = 1116 = 16, packet 2 = 2116 = 32 If loggerGap = 10: packet 0 = 01016 = 0, packet 1 = 11016 = 160, packet 2 = 21016 = 320 Example Response (loggerGap = 10, 4 parameters configured): "3,160,62149,80,10,10240,320,62246,76,20,10240,480,62344,76,24,10240,0" This means: 3 data packets Packet 1: timestamp=160, params=[62149, 80, 10, 10240] Packet 2: timestamp=320, params=[62246, 76, 20, 10240] Packet 3: timestamp=480, params=[62344, 76, 24, 10240] End marker: 0

AAMotion keeps no record of the configuration; the caller supplies it. A null specification is skipped, as MotionController.ConfigureSlowLogger skips it. An error reply raises MotionController.ErrorOccurred and yields no packets.
    • aamotion_configure_slow_logger — Samples chosen parameters continuously and pushes packets to the PC without a trigger. Upload often enough to keep the controller's FIFO from filling. The int getters return 0 on ANY failure. Configures the logger in one call. @param gap Sampling gap (ALoggerGap), > 0. @param fullMode What a full FIFO does (ALoggerFullMod): 0 pause, 1 overwrite the oldest data. @param paramNames paramCount names to record, e.g. "APos", "AVel[2]". NULL or paramCount 0 sets gap and fullMode only and leaves the recorded parameters alone.

    开关与状态¶

    C 接口中每个慢速记录器关键字都有对应的读写函数；C# 中直接使用控制器对象的属性：c.LoggerOn、c.LoggerGap、c.LoggerFullMod、c.LoggerParams[i]、c.LoggerStatus[i]、c.LoggerAbout[i]、c.LoggerFreeSpace、c.LoggerState、c.LoggerPushedPackets、c.LoggerLostPackets。

    独立小 Demo：读记录器状态

    什么时候用

    C 程序中控制慢速记录器、读状态；C# 中用对应的属性。

    函数原型

    // Starts (1) or stops (0) the logger (ALoggerOn).
// controller: 控制器句柄
// on: 1 开始记录，0 停止
bool aamotion_set_logger_on(aamotion_controller controller, int on);

// Reads ALoggerOn. Returns 0 on ANY failure, which a real 0 cannot be told apart from.
// controller: 控制器句柄
int aamotion_get_logger_on(aamotion_controller controller);

// Writes the sampling gap (ALoggerGap).
// controller: 控制器句柄
// gap: 采样间隔
bool aamotion_set_logger_gap(aamotion_controller controller, int gap);

// Reads ALoggerGap. Returns 0 on ANY failure, which a real 0 cannot be told apart from.
// controller: 控制器句柄
int aamotion_get_logger_gap(aamotion_controller controller);

// Writes what a full FIFO does (ALoggerFullMod): 0 pause, 1 overwrite.
// controller: 控制器句柄
// mode: FIFO 满时的处理
bool aamotion_set_logger_full_mode(aamotion_controller controller, int mode);

// Reads ALoggerFullMod. Returns 0 on ANY failure, which a real 0 cannot be told apart from.
// controller: 控制器句柄
int aamotion_get_logger_full_mode(aamotion_controller controller);

// Reads ALoggerStatus[index]. Returns 0 on ANY failure, which a real 0 cannot be told apart from.
// controller: 控制器句柄
// index: 数组下标，从 1 开始
int aamotion_get_logger_status(aamotion_controller controller, int index);

// Reads ALoggerAbout[index]. Returns 0 on ANY failure, which a real 0 cannot be told apart from.
// controller: 控制器句柄
// index: 数组下标，从 1 开始
int aamotion_get_logger_about(aamotion_controller controller, int index);

// Reads ALoggerParams[index]. Returns 0 on ANY failure, which a real 0 cannot be told apart from.
// controller: 控制器句柄
// index: 数组下标，从 1 开始
int aamotion_get_logger_params(aamotion_controller controller, int index);

// Writes ALoggerParams[index], one recorded-parameter slot.
// controller: 控制器句柄
// index: 数组下标，从 1 开始
// value: 写入的值
bool aamotion_set_logger_params(aamotion_controller controller, int index, int value);

// Free space left in the controller's FIFO. Returns 0 on ANY failure, which a real 0 cannot be told apart from.
// controller: 控制器句柄
int aamotion_get_logger_free_space(aamotion_controller controller);

// The logger state. Returns 0 on ANY failure, which a real 0 cannot be told apart from.
// controller: 控制器句柄
int aamotion_get_logger_state(aamotion_controller controller);

// Packets pushed to the PC so far. Returns 0 on ANY failure, which a real 0 cannot be told apart from.
// controller: 控制器句柄
int aamotion_get_logger_pushed_packets(aamotion_controller controller);

// Packets lost. Returns 0 on ANY failure, which a real 0 cannot be told apart from.
// controller: 控制器句柄
int aamotion_get_logger_lost_packets(aamotion_controller controller);

    参数

    参数 类型 说明
    controller aamotion_controller 控制器句柄
    on int 1 开始记录，0 停止
    gap int 采样间隔
    mode int FIFO 满时的处理
    index int 数组下标，从 1 开始
    value int 写入的值

    返回值

    读取函数返回数值，失败时返回 0（与真实的 0 无法区分）；写入函数成功返回 true。

    注意

    • LoggerState 为 0 表示未记录，1 表示记录中，2 表示因 FIFO 满而暂停。
    • LoggerFreeSpace 的单位是槽位。与 LoggerStatus[1] 的单包槽位数比较，即可判断是否够存下一个包。
    • LoggerLostPackets 持续增加时，缩短上传间隔、增大 LoggerGap 或减少通道。用 LoggerLostPackets 检查丢包，用包头判断包与包之间的间隔。

    Console.WriteLine($"State: {c.LoggerState}");
Console.WriteLine($"Free slots: {c.LoggerFreeSpace}");
Console.WriteLine($"Pushed: {c.LoggerPushedPackets}");
Console.WriteLine($"Lost: {c.LoggerLostPackets}");

    多种配置与持续上传示例¶

    以下片段使用已连接的 MotionController c。每种配置方式单独使用。配置完成后置 LoggerOn = 1 才开始采样。

    采样间隔与 FIFO¶

    LoggerGap 的一个单位对应 16 个控制器采样周期。若控制器采样周期约 61 µs，LoggerGap = 1 约为 1 ms，LoggerGap = 10 约为 9.76 ms，LoggerGap = 100 约为 97.6 ms。上位机的上传间隔与控制器的采样间隔分别设置。

    LoggerFullMod FIFO 满时 数据影响
    0 暂停写入，上传腾出空间后继续 保留已排队数据，暂停期间的样本可能丢失
    1 循环覆盖最旧数据 优先保留近期样本

    用 CAN 编号配置¶

    通过 GetKeywordCANCode 取得带轴号和数组下标的编号。

    int aPos = c.GetKeywordCANCode(eKeyword.Pos, AxisRef.A);
int aVel = c.GetKeywordCANCode(eKeyword.Vel, AxisRef.A, 1);
c.ConfigureSlowLogger(10, 0, aPos, aVel);

    用强类型参数配置¶

    给定轴、关键字和必要的数组下标，可避免手写关键字字符串。

    var aPos = new MotionController.SlowLoggerParameter(
    AxisRef.A, eKeyword.Pos);
var bVel = new MotionController.SlowLoggerParameter(
    AxisRef.B, eKeyword.Vel, 1);
c.ConfigureSlowLogger(10, 0, aPos, bVel);

    定期上传解析结果并保存 CSV¶

    示例每 50 ms 取一次数据，共 40 次。实际轮询间隔按通道数、采样率和通信速度选择。检查丢包计数和剩余空间，再调整间隔。此示例展示周期上传，结束时停止采集。

    object[] channels = { "APos", "AVel[1]", "BPos" };
c.ConfigureSlowLogger(10, 0, channels);
using (var csv = System.IO.File.CreateText("slow-logger.csv"))
{
    csv.WriteLine("packet_id,APos,AVel[1],BPos");
    try
    {
        c.LoggerOn = 1;
        int previousLost = c.LoggerLostPackets;
        for (int i = 0; i < 40; i++)
        {
            System.Threading.Thread.Sleep(50);
            var data = c.LoggerUpload(channels);
            foreach (var packet in data.Packets)
                csv.WriteLine(FormattableString.Invariant(
                    $"{packet.Id},{packet.Values[0]},{packet.Values[1]},{packet.Values[2]}"));
            int lost = c.LoggerLostPackets;
            if (lost != previousLost)
                Console.WriteLine($"Lost packets: {lost}");
            previousLost = lost;
        }
    }
    finally
    {
        c.LoggerOn = 0;
    }
}

    如何读包头¶

    例如记录两个通道时，原始回复 2,160,1200,35,320,1250,37,0 表示读到了两包数据。第一个包的包头为 160，两个通道值为 1200、35；第二个包的包头为 320，通道值为 1250、37。末尾的 0 是结束标记。

    SDK 解析器的 PacketCount、Packets、LastPacketId 可直接使用。包头可能是包 ID 或采样周期计数，取决于控制器是否支持 DataLoggerByTime。包 ID 的正常增量为 1。以控制器采样周期计数时，LoggerGap = 10 的相邻包相隔 160 个周期，约 9.76 ms（周期为 61 µs 时）。
