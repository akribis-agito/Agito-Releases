    GetHomingDefStep¶

    HomingDefStep GetHomingDefStep(int step)

    Every 10 elements of HomingDef[] are one step. a.GetHomingDefStep(n) returns a view of step n (from 1, up to 20): Type is the step type and Param1…Param9 its parameters; reading and writing them reads and writes the matching HomingDef elements, so you never compute indexes.

    Read and write the homing table by step

    SDK summary: A step-addressed view over ISingleAxis.HomingDef, naming the step type and its nine parameters instead of leaving the caller to compute slot indices.

    Parameter Type Direction Default Description
    step int input by value required The step, from 1, up to 20

    Return type: HomingDefStep

    A HomingDefStep object.

    TryRead¶

    bool TryRead(eKeyword keyword, out double value)

    Reads a keyword on one axis, converted by that axis's User Units (counts when none apply). Every call reads from the controller; the FastReadCache is not used. TryGetValue returns false instead of throwing on failure.

    Read a value by keyword

    SDK summary: Reads keyword from the controller and reports whether the read succeeded, instead of throwing the way the typed properties do on a failure. Always a controller round trip, never the FastReadCache, in the units the axis reads in. False — with value 0 — when the controller replied with an error or with something that is not a number; MotionController.LastReadError then names the failure and MotionController.ReadFailures is incremented. A keyword the SDK knows as a controller command is an System.ArgumentException: reading one would send it.

    Parameter Type Direction Default Description
    keyword eKeyword input by value required The keyword (eKeyword.Pos / AAMOTION_KEYWORD_POS). Command keywords are refused, since reading one would run it
    value double out required The value read (a C# out parameter / a C pointer)

    Return type: bool

    GetValue returns the value and throws ControllerCommandException on failure. TryGetValue / the C version return true on success and false on failure; in C# the reason is in LastReadError.

    bool TryReadArray(eKeyword keyword, int index, out double value)

    Reads a keyword on one axis, converted by that axis's User Units (counts when none apply). Every call reads from the controller; the FastReadCache is not used. TryGetValue returns false instead of throwing on failure.

    Read a value by keyword

    SDK summary: Array-element twin of ISingleAxis.TryRead: reads element index (1 and up) of an array parameter.

    EventCorrect¶

    bool EventCorrect()

    A standard table event (EventType = 2) triggers at unevenly spaced part features. Disarm first, then write EventTable positions in travel order. Set each output selection, pulse width, and the first and last indexes. Arm before the first trigger position. Use EventCorrect when the setup calls for corrected coordinates.

    Central-i verified tables¶

    The AAMotion .NET factory c.CreateEventTableClient('A') binds to the current connection and axis. Check verified-table support (Identity[62] mask 0x200), a compatible remote drive image, a commissioned encoder and event source, and LockEventStat = 1.

    1. LoadAsync uploads and reads back the definition and waits for controller-confirmed Ready. Then call ArmAsync. If it returns Armed, call WaitForCompletionAsync to confirm completion. Short sequences can complete before the host sees Running.
    2. After normal completion, call AbortAsync and confirm Aborted, then acknowledge the release to Empty. If the controller has retained an error, inspect that occurrence and use the corresponding AcknowledgeAsync overload.
    3. Cancellation or disposal ends the host operation. Confirm the controller state separately. Disconnect invalidates the old Ready result. RecoverAsync can confirm an abort only on the original live connection when takeover is allowed. Reconnecting requires checking the controller state before further action.

    Table events

    SDK summary: Calibrate the event table. Performs calibration operation on the event table.

    Parameters: none.

    Return type: bool

    Returns: Returns true if calibration is successful, otherwise false.

    true on success.

    SetPosition¶

    bool SetPosition(double value)

    Assigns a value to the current position (SetPosition) without moving. Common for defining zero without homing, or redefining coordinates after a force step.

    Set the current position

    SDK summary: Set the current position. Resets the current position to the specified value. ISingleAxis.Pos

    Parameter Type Direction Default Description
    value double input by value required The new position, in counts, never User Units

    Return type: bool

    Returns: Returns true if the position is set successfully, otherwise false.

    true on success.

    SDK remarks: The actual command sequence sent to the back end: {Axis}SetPosition={value} The controller lists this parameter in its position User Units group, so the argument is scaled exactly like ISingleAxis.Pos: SetPosition(Pos) is a round trip, and a value finer than one count is rounded to the nearest count. With MotionController.UseUserUnits set to false, both are in counts.

    Home¶

    void Home()

    Three overloads:

    • 'Home(c, axis) starts the sequence already configured in the controller (AHomingOn=1).'
    • 'Home(c, axis, isHomeToLimit, isHomeToIndex, …) builds the sequence from its arguments: a limit only, the index only, or a limit then the index; the position found plus homeoffset becomes zero.'
    • 'Home(c, axis, filePath) writes the HomingDef[n]=value lines of a text file to the controller and starts. Lines starting with // are comments.'

    The axis must be motor-on (and commutated, for a synchronous motor) before homing.

    Home with the configured sequence

    SDK summary: Start homing operation.

    Parameters: none.

    Return type: void

    C# returns nothing (throws ControllerCommandException when starting is refused); the C version returns true when started. true does not mean homing is done.

    SDK remarks: The actual command sequence sent to the back end: {Axis}HomingOn=1

    HomeToHardStop¶

    void HomeToHardStop(double threshold, double velocity, double acceleration, double emergencydeceleration, double homeoffset, uint timeOut)

    Without limit switches, the axis moves slowly until it presses against the mechanical end stop; a position error above threshold marks the stop, and that position plus homeoffset becomes zero.

    Home to a hard stop

    SDK summary: JOG until a hard stop is detected by position error. Assign home position at this point. Every value goes into HomingDef, which the controller reads in controller units: User Units do not apply to homing.

    Parameter Type Direction Default Description

    velocity double input by value required The search speed; keep it low
    acceleration double input by value required The acceleration
    emergencydeceleration double input by value required The emergency deceleration
    homeoffset double input by value required The zero offset
    timeOut uint input by value required The timeout in ms

    Return type: void

    HomeToIndex¶

    void HomeToIndex(int lockSource, int direction, double slowSpeed, double accel, uint timeoutMs = 15000)

    Use a latch signal, normally the encoder index, as zero, optionally after a fast coarse search and before a slow latch search:

    Function First stage
    HomeToIndex none: a slow latch search straight away
    HomeToLimitThenIndex a fast search for the limit switch
    HomeToHardStopThenIndex a fast move into the mechanical stop, detected by a position error above hardStopThreshold
    HomeToHardStopByStuckThenIndex a fast move into the mechanical stop, detected by motor stuck: velocity below stuckVel with current above stuckCurr for stuckTimeMs

    Each fills HomingDef[], starts the controller's homing sequence and returns; poll IsHomed for completion (see the chapter introduction). lockSource 0 selects the main encoder index (it needs LockSrcZeroSupported to return true; otherwise C# throws NotSupportedException).

    See the PCSuite homing controls and parameters.

    Index homing

    SDK summary: Simplified homing via hardware index signal: Motor On (30 s) → Configure Lock (30 s) → Jog to Index → Move to Lock → Disable Lock (30 s) → Wait (3 s dwell) → Set Position (30 s) → End. Direction logic: - direction = 1 (Positive): Jog to index at +slowSpeed, move to lock at +slowSpeed. - direction = -1 (Negative): Jog to index at -slowSpeed, move to lock at -slowSpeed. Emergency deceleration = accel × 10. Motion step timeouts are user-defined via timeoutMs (default 15000 ms). The motor-on, configure-lock, disable-lock and set-position steps carry a fixed 30 s step timeout, written as 30 × CurrentLoopSampleRate servo samples: it bounds how long the controller's homing state machine waits for motor-on phasing, for the Lock hardware configuration, and for the background loop to apply the new position. The wait step is a fixed 3 s dwell (3 × CurrentLoopSampleRate samples), a step duration rather than a timeout.

    Parameter Type Direction Default Description
    lockSource int input by value required The lock input: 0 the main encoder index with normal polarity (needs LockSrcZeroSupported); a non-zero magnitude selects the lock input, and a negative sign inverts its polarity
    direction int input by value required The initial search direction: 1 forward, -1 reverse
    slowSpeed double input by value required The slow speed of the latch search, counts/s, positive
    accel double input by value required The acceleration, counts/s², positive
    timeoutMs uint input by value 15000 The timeout of each motion step in ms, not of the whole sequence. 15000 by default in C#

    Return type: void

    The C# homing calls return nothing and throw on a bad argument (an ArgumentOutOfRangeException, for example, or NotSupportedException for lockSource 0 on a controller without it). The C homing calls return true when the sequence was written and started without error, and false for a bad argument or a refused write.

    LockSrcZeroSupported returns true when the controller can latch on the main encoder index (from its feature bit, Identity[62] mask 0x10).

    T:System.ArgumentOutOfRangeException: direction is not 1 or -1, or a magnitude argument is not positive. The profile is checked before the first HomingDef slot is written, so a refused call leaves the slots as they were.

    CommitMotion¶

    bool CommitMotion()

    Write the new Sine PTP parameters to each axis first, then one CommitMotion(A | B …). The controller validates and recalculates every axis's profile in the same control cycle, so they all change together. If any axis in the mask is not in a Sine PTP motion, the whole commit is refused. It sends ACommitMotion=<axis mask>.

    Change several axes in one step

    SDK summary: Commit the Sine PTP parameters currently written to the axis so the controller splices them onto the motion already running (an on-the-fly change). The controller validates the new profile within 16 control cycles (about 1 ms) and then joins the two profiles; position and velocity stay continuous across the splice, acceleration does not. Every kinematic parameter is read as one complete set describing the new motion, so write PreCruiseSpd = 0 to drop a pre-cruise phase the new motion no longer needs. A non-zero RelTrgt is measured from where the axis is at the splice, not from where the motion began. The controller's command names the axes it commits by mask, so this sends ACommitMotion=<this axis's bit>; MotionController.CommitMotion(AxisRef) commits several axes in one synchronised step.

    Parameters: none.

    Return type: bool

    Returns: Returns true if the controller accepted the commit, otherwise false. A rejection is reported through MotionController.ErrorOccurred, for example error 48 (the axis is not in a Sine PTP motion), 387 (the motion ends before the splice could happen) or 388 (the recalculation did not finish in time).

    true when the commit was accepted.
