AAComm Native SDK

A native C ABI over the AAComm client — talk to an Agito motion controller from C, C++, Python, or any language with a C FFI, with no .NET runtime on the target. The library is NativeAOT-compiled per platform and ships as a single shared library plus one header.

Platform Library Link with
Windows x64 aacomm.dll aacomm.lib (import lib)
Linux x64 libaacomm.so -laacomm
macOS x64 / arm64 libaacomm.dylib -laacomm

Every platform ships the same two headers: aacomm.h (the API) and aacomm_enums.h (channel/result/long-operation codes, generated from the C# source of truth). aacomm.h is the authoritative per-function reference — its comments document every parameter and contract; this guide is the conceptual overview.

Status: validated on win-x64 (pure C, against live hardware) and linux-x64 (Python ctypes). macOS builds are pending a CI runner.

Getting the library

  • .NET (P/Invoke): add the Agito.AAComm.Native NuGet — aacomm.dll / libaacomm.so lands next to your build output automatically; [DllImport("aacomm")].
  • C / C++: take the agito-aacomm-native-sdk-<version>.zip archive (the include/ headers + per-RID native libs + sample.c).
  • Python / other FFI: drop the platform library beside your script and dlopen/ctypes.CDLL it (it is inside both artifacts above).
  • From source: see packaging/README.md in the repo (NativeAOT can't cross-compile — build each RID on its own OS).

Distribution note: the Agito.AAComm.Native NuGet and the sdk zip are currently produced as internal build artifacts (win-x64 + linux-x64) and are not yet published to nuget.org — obtain them from Agito. The package version is locked to the managed Agito.AAComm.

Architecture in one paragraph

The SDK is a client. It talks to AACS (the AAComm server) — a separate, shared process that owns the actual controller connection and can serve multiple clients. Your program either spawns a local AACS (aacomm_start_server) or connects to one that is already running, then opens a controller channel through it. AACS is not embedded in the SDK; it is resolved/launched as its own process.

The status convention

Every export returns int32_t aacomm_status: 0 (AACOMM_OK) on success, negative on an ABI fault — AACOMM_NULL_ARG (-1), AACOMM_BAD_HANDLE (-2), AACOMM_EXCEPTION (-3). A domain result — a ConnectResult, the connected flag, a reply/error byte size — is not the return value; it is written to an out_* parameter you pass. So a connect looks like:

int32_t result = 0;
int32_t status = aacomm_connect(h, &conn, &result);   /* status = ABI ok/fault; result = ConnectResult */
if (status == AACOMM_OK && result == AACOMM_RESULT_SUCCESS) { /* connected */ }

This keeps "the call could not run" (a NULL arg, a stale handle, a managed exception) cleanly distinct from "the call ran and the controller said X" — the two never alias on one integer.

Check the status before reading an out-param. The ConnectResult in out_result is meaningful only when the status is AACOMM_OK — on a negative status it is left untouched (there is no "neutral" ConnectResult; 0 already means success). The other out-params get a safe default on every path: aacomm_create zeroes *out_handle, aacomm_is_connected writes 0, and aacomm_send_receive sets *is_error = 1 / *out_required = 0 before any early return.

Quick start — C / C++

#include "aacomm.h"
#include <stdio.h>
#include <string.h>

int main(void)
{
    /* Optionally spawn a local AACS; pass "" to use the default resolution / an already-running one. */
    int32_t sres = 0;
    aacomm_start_server("", &sres);

    aacomm_handle h = NULL;
    if (aacomm_create(&h) != AACOMM_OK) return 1;

    aacomm_connection conn;
    memset(&conn, 0, sizeof(conn));          /* zero-init, then set your channel's fields */
    conn.channel_type = AACOMM_CHANNEL_ETHERNET;
    conn.ip1 = 172; conn.ip2 = 1; conn.ip3 = 1; conn.ip4 = 102;

    /* test_connection detects the controller type and writes it back into conn for connect. */
    int32_t result = 0;
    aacomm_test_connection(h, &conn, 0, &result);
    if (aacomm_connect(h, &conn, &result) == AACOMM_OK && result == AACOMM_RESULT_SUCCESS)
    {
        char reply[256];
        int32_t is_error = 0, size = 0;
        aacomm_send_receive(h, "APos", 2000, reply, (int32_t)sizeof(reply), &is_error, &size);
        printf("APos -> %s (is_error=%d)\n", reply, is_error);
    }

    aacomm_disconnect(h);
    aacomm_destroy(h);
    return 0;
}

Build (Windows, from a x64 Native Tools prompt or after vcvars64):

cl /nologo sample.c /I path\to\include /link path\to\aacomm.lib
:: aacomm.dll must sit next to the .exe or on PATH at run time

Build (Linux / macOS):

Quick start — Python (ctypes)

No bindings package required — load the shared library directly. Mirror the struct layout and set restype/argtypes so values marshal correctly.

import ctypes, sys

lib = ctypes.CDLL("./libaacomm.so")          # "aacomm.dll" on Windows, "libaacomm.dylib" on macOS

class AacommConnection(ctypes.Structure):
    _fields_ = [
        ("channel_type", ctypes.c_int32), ("controller_type", ctypes.c_int32),
        ("ip1", ctypes.c_int32), ("ip2", ctypes.c_int32),
        ("ip3", ctypes.c_int32), ("ip4", ctypes.c_int32),
        ("port", ctypes.c_int32), ("can_channel", ctypes.c_int32),
        ("can_baud_rate", ctypes.c_int32), ("can_send_address", ctypes.c_int32),
        ("can_receive_address", ctypes.c_int32), ("rs232_baud_rate", ctypes.c_int32),
        ("rs232_port_name", ctypes.c_char * 32),
    ]

lib.aacomm_create.argtypes = [ctypes.POINTER(ctypes.c_void_p)]
lib.aacomm_send_receive.argtypes = [ctypes.c_void_p, ctypes.c_char_p, ctypes.c_int32,
                                    ctypes.c_char_p, ctypes.c_int32,
                                    ctypes.POINTER(ctypes.c_int32), ctypes.POINTER(ctypes.c_int32)]

result = ctypes.c_int32(0)
lib.aacomm_start_server(b"", ctypes.byref(result))
h = ctypes.c_void_p()
lib.aacomm_create(ctypes.byref(h))

conn = AacommConnection()
conn.channel_type = 2                          # AACOMM_CHANNEL_ETHERNET
conn.ip1, conn.ip2, conn.ip3, conn.ip4 = 172, 1, 1, 102

lib.aacomm_test_connection(h, ctypes.byref(conn), 0, ctypes.byref(result))
if lib.aacomm_connect(h, ctypes.byref(conn), ctypes.byref(result)) == 0 and result.value == 0:
    buf = ctypes.create_string_buffer(256)
    is_error, size = ctypes.c_int32(0), ctypes.c_int32(0)
    lib.aacomm_send_receive(h, b"APos", 2000, buf, 256, ctypes.byref(is_error), ctypes.byref(size))
    print("APos ->", buf.value.decode(), "is_error", is_error.value)

lib.aacomm_disconnect(h)
lib.aacomm_destroy(h)

To receive async replies, push messages, or error/long-operation events, declare the matching CFUNCTYPE and register it. Keep a Python reference to the CFUNCTYPE instance for as long as it can fire — if it is garbage-collected the library calls a freed trampoline:

REPLY_CB = ctypes.CFUNCTYPE(None, ctypes.c_char_p, ctypes.c_int32, ctypes.c_void_p)
ERROR_CB = ctypes.CFUNCTYPE(None, ctypes.c_char_p, ctypes.c_void_p)

def _on_reply(reply, is_error, user):
    print("reply", reply.decode() if reply else "", "is_error", is_error)

def _on_error(error, user):
    print("error", error.decode() if error else "")

reply_cb, error_cb = REPLY_CB(_on_reply), ERROR_CB(_on_error)   # keep these alive

lib.aacomm_set_error_callback.argtypes = [ctypes.c_void_p, ERROR_CB, ctypes.c_void_p]
lib.aacomm_send.argtypes = [ctypes.c_void_p, ctypes.c_char_p, ctypes.c_int32, REPLY_CB, ctypes.c_void_p]

lib.aacomm_set_error_callback(h, error_cb, None)
lib.aacomm_send(h, b"APos", 2000, reply_cb, None)

Core contracts

Handle lifecycle

aacomm_create(&h) writes an opaque handle and returns AACOMM_OK (or a negative status on failure); aacomm_destroy() disconnects and frees it. One handle owns at most one controller connection. For concurrent connections, create multiple handles. Handles come from a table that never reuses a value, so a stale or forged handle resolves to AACOMM_BAD_HANDLE rather than undefined behavior.

The connect handshake

  1. (optional) aacomm_start_server(path, &result) — spawn or locate AACS. ""/NULL uses the default resolution (or an AACS that is already running); result is the ConnectResult.
  2. aacomm_test_connection(h, &conn, is_known_controller_type, &result) — probes the controller and, when is_known_controller_type == 0, writes the detected controller_type back into conn.
  3. aacomm_connect(h, &conn, &result) — consumes that controller_type. Passing a freshly zero-initialized struct straight to connect (skipping test_connection) yields result == AACOMM_RESULT_INVALID_CONTROLLER_TYPE — run test_connection first, or set controller_type yourself.

For firmware or FPGA download, call aacomm_download_firmware / aacomm_download_fpga directly — each opens its own connection (the handle must be disconnected) and uses neither aacomm_connect nor aacomm_connect_silent. aacomm_download_user_program is the exception: it downloads over the handle's already-connected session (connect first — it takes no aacomm_connection and rejects a disconnected handle). aacomm_connect_silent is for connecting to a controller in boot mode for direct messaging, where the identity/about handshake aacomm_connect performs is unavailable.

Fill aacomm_connection by zero-initializing then setting only your channel's fields — 0 means "library default" for everything except channel_type (always honored) and can_channel (0 is a valid CAN channel). The struct layout must match the header exactly.

Synchronous vs asynchronous messaging

  • aacomm_send_receive blocks for the reply, writes it into your buffer, and sets *is_error. Sync and async pipelines are independent — you may interleave them from any thread.
  • aacomm_send returns immediately; the optional aacomm_reply_cb fires exactly once — with the reply, or with is_error = 1 if the session tears down (disconnect / fatal) before the reply arrives. A consumer waiting on the callback never waits forever.

Strings: the two-call pattern

Output strings are UTF-8. The output functions (aacomm_last_error, aacomm_last_reply, aacomm_send_receive) take a buffer/buffer_len plus an int32_t* out_required: call with buffer = NULL, buffer_len = 0 to learn the required size (including the NUL) via *out_required, allocate, then call again. The copy is truncated to fit and always NUL-terminated, so if *out_required > buffer_len the text was truncated — for aacomm_send_receive the full reply is cached, so re-fetch it with aacomm_last_reply (which does not re-send the command). out_required may be NULL if you don't need the size.

Callbacks and threading

The callbacks — reply (aacomm_send), error, push, longop_started, longop_ended — are invoked on the library's firing thread, never on your calling thread. Keep them short and thread-safe: marshal work to your own thread/queue rather than blocking inside the callback. Each takes an opaque void* user_data that is passed straight through. Precise firing thread per callback:

Callback Set by Fires on Notes
reply passed to aacomm_send a dispatcher thread fires exactly once per accepted aacomm_send (reply, or is_error = 1 terminal error on teardown); the receiver thread never invokes it
error aacomm_set_error_callback the receiver thread, synchronously a slow handler stalls reply/push classification — off-load with your own queue
push aacomm_set_push_callback the thread pool ASCII push payload
longop_started / longop_ended the matching setter the firing thread bracket a busy window (reset/save/load)

The const char* passed to a callback is owned by the library and valid only for the duration of the call — copy it if you need it later; do not free it. Re-entrancy: do not call aacomm_send_receive from inside a callback — it fails fast with an in-band error reply instead of blocking (from a reply callback it is rejected outright; by the time the error callback fires the connection is already torn down, so it reports not-connected). Issue follow-up traffic from your own thread. Registering or clearing callbacks from inside a callback is allowed. A registered callback may fire until you clear it (pass a NULL function pointer) or call aacomm_destroy — destroy delivers pending reply callbacks terminally (is_error = 1), waits (bounded, ~2 s) for in-flight callbacks to return, and guarantees no callback fires after it returns, so callback state may be freed as soon as destroy returns.

Per-handle threading

A handle is single-threaded by contract: make calls on a given handle from one thread at a time (concurrent calls on different handles are fine, and callbacks arrive on library threads regardless). The recovery/two-call state — aacomm_last_reply after aacomm_send_receive, aacomm_record_result after aacomm_record, aacomm_last_error after any failure — is cached per handle, so a concurrent call on the same handle overwrites it between your two calls.

Timeouts

Every timeout_ms accepts 0 or a negative value as "use the family default":

Family timeout_ms > 0 0 / negative
aacomm_send_receive / aacomm_send per-call override the per-message default
aacomm_record wait-for-completion bound 10 000 ms
aacomm_download_firmware / _fpga / _user_program completion bound 180 000 ms (3 min)

Error handling

Every function returns an aacomm_status (0 == OK; -1/-2/-3 are NULL-arg / bad-handle / exception). On an AACOMM_EXCEPTION the detail text is available via aacomm_last_error(h, ...). The domain outcome of a connect/test/send is the ConnectResult written to the out_result parameter — a separate axis from the status (see Status / result codes).

Message-level errors are in-band: aacomm_send_receive returns AACOMM_OK with *is_error = 1 and the reply text carrying one of a closed prefix set — "ERR " (controller error), "BOOT ERR" (controller error in BOOT mode), "ERR Sync:" (client-side sync-pipeline error: Timeout / Session terminated / No reply / callback re-entry rejection), "PC Suite: ERR" (API-synthesized, e.g. PC Suite: ERR 4020 = not connected). Timeout semantics: a timeout that expires while the message is still queued behind a slower call returns ERR Sync: Timeout without sending the message and keeps the connection; a timeout after the message reached the wire returns the same text but disconnects the handle — subsequent calls report PC Suite: ERR 4020 until you reconnect.

The library never takes ownership of buffers you pass in, and the const char* it hands to callbacks is valid only for the duration of the call.

ABI versioning & stability

int32_t aacomm_abi_version(void);

The SDK carries two version numbers, for two different purposes:

  • Package version — the SemVer of the aacomm.* library / Agito.AAComm.Native NuGet, version-locked to the managed Agito.AAComm ($(AACommVersion); the native package is not co-published with managed releases — see the distribution note above). This is what you pin in a package reference; release history is in the SDK's CHANGELOG.md (shipped in the C/C++ archive).
  • aacomm_abi_version() — a soname-style breaking-generation number, the C-ABI contract. It is bumped only on a breaking change: a changed or removed export signature, a struct layout change, a callback-signature change, or changed status-code semantics. Additive changes — new exports, new enum values, new result codes — never bump it (they cannot break a compiled consumer). It returns its value directly (it cannot fail) and takes no handle; the same value is the AACOMM_ABI_VERSION macro in the generated aacomm_enums.h. Generation 1 is the first shipped ABI (pre-release increments carried no compatibility meaning and were reset).

Consumer rule — exact-match gate. Call aacomm_abi_version() once at load and reject a library whose value does not equal AACOMM_ABI_VERSION from the headers your binding was built against — coherent with the bump policy, because the number only moves when your binary genuinely cannot run. The bundled Python binding does this automatically; the committed include/aacomm.abi.txt records the exact export surface and the callback typedef signatures for that generation. Always build against the aacomm.h that ships with the library you load.

Compatibility. The native client, the native AACS daemon, and the language bindings ship together at one package version — run matching versions. aacomm_enums.h, aacomm.abi.txt, and the Python mirrors are generated from the C# source and CI diff-gated; aacomm.h itself is hand-maintained — the manifest diff is what forces it to be updated in review.

Lifecycle

int32_t aacomm_create(aacomm_handle* out_handle);

Allocates a client session and writes its opaque handle to *out_handle. Returns AACOMM_OK, or AACOMM_NULL_ARG if out_handle is NULL / AACOMM_EXCEPTION on internal failure. Each handle owns one AAComm client (and thus at most one controller connection). Free every handle with aacomm_destroy.

int32_t aacomm_destroy(aacomm_handle h);

Disconnects (best-effort) and frees the handle and its client. Returns AACOMM_OK, or AACOMM_BAD_HANDLE if h is unknown/already freed. After this call the handle and any callbacks registered on it are invalid; do not reuse it.

int32_t aacomm_is_connected(aacomm_handle h, int32_t* out_connected);

Writes 1/0 (open controller connection?) to *out_connected. Returns AACOMM_OK, AACOMM_NULL_ARG (NULL out-param) or AACOMM_BAD_HANDLE. Does not allocate; safe to poll. Because the bad-handle case is a distinct status, out_connected == 0 unambiguously means "not connected" (not "bad handle").

int32_t aacomm_last_error(aacomm_handle h, char* buffer, int32_t buffer_len, int32_t* out_required);

Copies the handle's most-recent error text (UTF-8, NUL-terminated) into buffer (two-call sizing; *out_required receives the required byte length including the NUL when non-NULL). Returns AACOMM_OK or AACOMM_BAD_HANDLE. The error text is set by the most recent operation that returned AACOMM_EXCEPTION on this handle.

Connection

int32_t aacomm_start_server(const char* exe_path, int32_t* out_result);

Spawns or locates AACS (the shared AAComm server process). Pass "" or NULL for default resolution (or to attach to an AACS already running); exe_path may be a UTF-8 path to a specific AACommServer executable. Writes the ConnectResult to *out_result (0 == AACS is up; AACS-resolution/start codes are values 35–43). Returns AACOMM_OK/AACOMM_NULL_ARG/AACOMM_EXCEPTION. Process-wide, not per-handle — call it once before connecting.

int32_t aacomm_test_connection(aacomm_handle h, aacomm_connection* conn, int32_t is_known_controller_type, int32_t* out_result);

Probes the controller described by conn (non-const: when is_known_controller_type == 0 it detects the controller type and writes it back into conn->controller_type so a subsequent aacomm_connect can consume it — see the connect handshake). Pass non-zero only when you have already set controller_type yourself. Writes the ConnectResult to *out_result. Returns a status (AACOMM_NULL_ARG if conn/out_result is NULL, AACOMM_BAD_HANDLE for a bad handle).

int32_t aacomm_connect(aacomm_handle h, const aacomm_connection* conn, int32_t* out_result);

Opens the controller connection, querying identity / about / firmware data. Requires conn->controller_type to be set (run aacomm_test_connection first, or set it yourself) — otherwise *out_result == AACOMM_RESULT_INVALID_CONTROLLER_TYPE (16). Writes the ConnectResult to *out_result.

int32_t aacomm_connect_silent(aacomm_handle h, const aacomm_connection* conn, int32_t* out_result);

Opens the connection without querying the controller for identity/about/firmware data (it only clears the RS-232 buffer on a serial channel) — the path for connecting to a controller in boot mode, where the normal identity handshake is not available. (Firmware download has its own export, aacomm_download_firmware, which manages its connection internally — don't connect first.) Writes the ConnectResult to *out_result.

int32_t aacomm_disconnect(aacomm_handle h);

Closes the controller connection for the handle (the handle stays valid and can reconnect). Returns AACOMM_OK, AACOMM_BAD_HANDLE, or AACOMM_EXCEPTION.

int32_t aacomm_close_server(aacomm_handle h, int32_t force);

Closes the AACS process this client is using. force != 0 requests an unconditional shutdown; 0 is a cooperative close. Returns AACOMM_OK, AACOMM_BAD_HANDLE, or AACOMM_EXCEPTION. Pair it with aacomm_start_server when your program owns the AACS lifecycle.

Synchronous messaging

int32_t aacomm_send_receive(aacomm_handle h, const char* command, int32_t timeout_ms,
                            char* reply_buf, int32_t reply_cap, int32_t* is_error, int32_t* out_required);

Sends command (UTF-8) and blocks until the reply arrives. Writes the reply text (UTF-8, truncated to fit and always NUL-terminated) into reply_buf/reply_cap, sets *is_error to 0/1 (the controller/transport error flag; also 1 on internal failure) when non-NULL, and writes the full reply byte length including the NUL to *out_required when non-NULL (so *out_required > reply_cap means it was truncated — re-fetch with aacomm_last_reply). timeout_ms > 0 overrides the message's default. Returns AACOMM_OK, AACOMM_NULL_ARG (NULL command), AACOMM_BAD_HANDLE, or AACOMM_EXCEPTION. Sync and async pipelines are independent; this may be interleaved with aacomm_send from any thread, but must not be called from inside a reply callback.

int32_t aacomm_last_reply(aacomm_handle h, char* buffer, int32_t buffer_len, int32_t* out_required);

Re-fetches the reply from the most recent aacomm_send_receive on this handle (two-call UTF-8, same sizing rule as aacomm_last_error) without sending the command again. Use it when a prior aacomm_send_receive buffer was too small.

Asynchronous messaging + events

int32_t aacomm_send(aacomm_handle h, const char* command, int32_t timeout_ms,
                    aacomm_reply_cb reply_cb, void* user_data);

Enqueues command (UTF-8) and returns immediately (AACOMM_OK on enqueue; AACOMM_NULL_ARG / AACOMM_BAD_HANDLE / AACOMM_EXCEPTION otherwise). If reply_cb is non-NULL it fires once when the reply arrives, as reply_cb(const char* reply, int32_t is_error, void* user_data); pass NULL to fire-and-forget. timeout_ms > 0 overrides the default. user_data is passed through verbatim.

int32_t aacomm_set_error_callback(aacomm_handle h, aacomm_error_cb cb, void* user_data);
int32_t aacomm_set_push_callback(aacomm_handle h, aacomm_push_cb cb, void* user_data);
int32_t aacomm_set_longop_started_callback(aacomm_handle h, aacomm_longop_started_cb cb, void* user_data);
int32_t aacomm_set_longop_ended_callback(aacomm_handle h, aacomm_longop_ended_cb cb, void* user_data);

Register (or, with a NULL cb, clear) a session-level event callback on the handle. Each returns AACOMM_OK or AACOMM_BAD_HANDLE. Only one callback of each kind is held per handle — a later registration replaces the earlier one. Callback signatures and firing threads are in Callbacks and threading; user_data is passed through verbatim to each invocation.

  • aacomm_error_cb — void cb(const char* error, void* user_data) — fatal comms error.
  • aacomm_push_cb — void cb(const char* message, void* user_data) — controller push message.
  • aacomm_longop_started_cb — void cb(int32_t op_type, void* user_data) — op_type is aacomm_long_operation_type.
  • aacomm_longop_ended_cb — void cb(int32_t op_type, int32_t error_code, void* user_data) — error_code 0 means success.

This surface is v0 and intentionally minimal — it will be extended as the SDK matures. Always build against the headers that ship with your library (the aacomm_connection layout in particular must match), and call aacomm_abi_version() to verify the loaded library matches the header you built against — the value is bumped on any breaking change.
