    Initialization and connection¶

    The whole life of a program's link to a controller: create the controller object → connect → use it → disconnect → release. In C# the controller is a MotionController; the static AAMotionAPI methods and the object's own methods do the same things, so pick one style. In C the controller is an aamotion_controller handle.

    What happens behind these steps is described in Connecting.

    Check the ABI version¶

    Returns the native library's ABI version, which changes only on an incompatible interface change. Compare it with AAMOTION_ABI_VERSION from the header at start-up; a difference means aamotion.h and aamotion.dll come from different SDK versions, so function arguments may not line up, and the program should stop.

    When to use it

    The first thing a C/C++ program does; it catches a header and a library from different SDKs right after an upgrade. Not needed in C#.

    Signatures

    // The breaking-generation number of this library's C ABI. It changes ONLY on a breaking change (signature, layout, callback or behaviour); additive changes never change it. At load time, require an EXACT match with AAMOTION_ABI_VERSION from aamotion_enums.h.
int32_t aamotion_abi_version(void);

    Returns

    The ABI version; equal to AAMOTION_ABI_VERSION in the header of the same SDK.

    Example

    if (aamotion_abi_version() != AAMOTION_ABI_VERSION)
{
    fprintf(stderr, "aamotion.h and the aamotion library are from different SDK versions\n");
    return NULL;
}
aamotion_controller h = aamotion_initialize(AAMOTION_CONTROLLER_TYPE_AGM800);
if (h == NULL)
{
    /* unknown controller type, or AACommServerNative could not be started (is it beside the library?) */
    fprintf(stderr, "initialize failed\n");
    return NULL;
}
    SDK comments (original)
    • aamotion_abi_version — The breaking-generation number of this library's C ABI. It changes ONLY on a breaking change (signature, layout, callback or behaviour); additive changes never change it. At load time, require an EXACT match with AAMOTION_ABI_VERSION from aamotion_enums.h.

    Create the controller object¶

    Creates the controller object for a controller model and makes sure the local AACommServer is running (starting it if needed). It does not connect yet. Use one object per controller; for several controllers create several objects.

    When to use it

    Once per controller per program; keep the object / handle until the program ends. Never initialize again for each operation.

    Signatures

    // AAMotionAPI
// Initialize the motion controller
// controllerType: The controller model (`ControllerType` / `AAMOTION_CONTROLLER_TYPE_*`). It must match the controller you connect to; connect checks it. See [Enums: Controller type](../reference/enums/ControllerType.md).
// Returns: Returns the MotionController instance of the corresponding type
static MotionController Initialize(ControllerType controllerType);

    // Creates a session for one controller of the given type and makes sure the shared AACommServer is running. May block a few seconds while the server starts; if the server can never start (missing sidecar, blocked port) the internal retries can block for MINUTES, so call it off any latency-sensitive thread. @param controllerType The controller model; an aamotion_controller_type_t value. @return The session handle, or NULL for an unknown controllerType or when the server could not be started or reached. A non-NULL handle means the server is up, so a later aamotion_connect failure is a connection problem, not an environment one.
// controllerType: The controller model (`ControllerType` / `AAMOTION_CONTROLLER_TYPE_*`). It must match the controller you connect to; connect checks it. See [Enums: Controller type](../reference/enums/ControllerType.md).
aamotion_controller aamotion_initialize(aamotion_controller_type_t controllerType);

    Parameters

    Parameter Type Description
    controllerType ControllerType / aamotion_controller_type_t The controller model (ControllerType / AAMOTION_CONTROLLER_TYPE_*). It must match the controller you connect to; connect checks it. See Enums: Controller type.

    Returns

    C#: the controller object. C: the controller handle, or NULL when the type is unknown or the server cannot be started.

    Notes

    • It can block for seconds while the server starts, and for minutes in the worst case when the server can never start. Do not call it on a GUI thread.
    • The C call returns NULL for only two reasons, an unknown type or a server that cannot start (AACommServerNative missing beside the library, port taken). A non-NULL handle means the server is up, so a later connect failure is a network or controller problem.
    • In C# an unknown type does not fail but creates an AGD301, and a server that cannot start is not reported (it gives up after about 3 s); call EnsureAACommServerRunning when you need to know.

    Example

    MotionController c = AAMotionAPI.Initialize(ControllerType.AGM800);
// c is ready to connect; the AACommServer has been started if it was not running

    if (aamotion_abi_version() != AAMOTION_ABI_VERSION)
{
    fprintf(stderr, "aamotion.h and the aamotion library are from different SDK versions\n");
    return NULL;
}
aamotion_controller h = aamotion_initialize(AAMOTION_CONTROLLER_TYPE_AGM800);
if (h == NULL)
{
    /* unknown controller type, or AACommServerNative could not be started (is it beside the library?) */
    fprintf(stderr, "initialize failed\n");
    return NULL;
}
    SDK comments (original)
    • Initialize(ControllerType) — Initialize the motion controller Returns: Returns the MotionController instance of the corresponding type
    • aamotion_initialize — Creates a session for one controller of the given type and makes sure the shared AACommServer is running. May block a few seconds while the server starts; if the server can never start (missing sidecar, blocked port) the internal retries can block for MINUTES, so call it off any latency-sensitive thread. @param controllerType The controller model; an aamotion_controller_type_t value. @return The session handle, or NULL for an unknown controllerType or when the server could not be started or reached. A non-NULL handle means the server is up, so a later aamotion_connect failure is a connection problem, not an environment one.

    Start AACommServer¶

    Makes sure AACommServer is running, starting it if it is not and doing nothing if it is. You rarely need it, since Initialize already does it; call it once before connecting to a simulator, which needs the server ready. OpenAACommServer(path) and EnsureAACommServerRunning(path) start a server executable at a path you give and report whether a server is serving the port.

    When to use it

    Before connecting to a simulator, or when the program chooses the server executable itself. Usually unnecessary before a real controller.

    Signatures

    // AAMotionAPI
// Start AACommServer
// controller: The controller object / handle
static void Init(MotionController controller);

// Ensures AACommServer is running. If already running, does nothing. Uses the internal default startup method. Every call checks the server's port, so a server that exited after an earlier call is started again.
static void OpenAACommServer();

// Checks if AACommServer is already running; if not, launches it from the specified executable path. Every call checks the server's port, so a server that exited after an earlier call is started again. Delegates to `AAComm.CommAPI.StartAACommServer` — the spawn contract lives there (headless args, its own standard streams, server working directory, socket-ready polling with a child-death probe).
// serverExePath: Absolute path of the AACommServer executable. With an empty path `EnsureAACommServerRunning` starts nothing and only reports whether a server is running.
// Returns: ConnectResult.Success if the server is serving its port; otherwise an error result.
static ConnectResult OpenAACommServer(string serverExePath);

// MotionController
// Opens the AACommServer.
void Init();

// Ensures an AACommServer is serving its port, starting `serverExePath` if none is, and reports whether one is serving when it returns. Readiness is the port, so a server of any build — `AACommServer` or `AACommServerNative` — counts, and a process that has not bound its port yet does not.
// serverExePath: Absolute path of the AACommServer executable. With an empty path `EnsureAACommServerRunning` starts nothing and only reports whether a server is running.
// Returns: True if an AACommServer is serving the port.
bool EnsureAACommServerRunning(string serverExePath);

    // Starts the shared AACommServer if it is not already running.
// controller: The controller object / handle
bool aamotion_init(aamotion_controller controller);

// Starts AACommServer unless it is already serving its port. Every call checks the port, so a server that exited after an earlier call is started again. @param serverExePath Full path to the server executable, or NULL for the default location. @return true when the server is serving its port. With NULL the default start cannot report a failure, so false then means only that the call itself failed.
// serverExePath: Absolute path of the AACommServer executable. With an empty path `EnsureAACommServerRunning` starts nothing and only reports whether a server is running.
bool aamotion_open_aacomm_server(const char* serverExePath);

    Parameters

    Parameter Type Description
    controller MotionController / aamotion_controller The controller object / handle
    serverExePath const char* / string Absolute path of the AACommServer executable. With an empty path EnsureAACommServerRunning starts nothing and only reports whether a server is running.

    Returns

    Init returns nothing (the C version returns success). OpenAACommServer(path) returns ConnectResult.Success when the server is serving; EnsureAACommServerRunning returns true when a server, of any build, is listening on the port.

    Example

    c.Init();   // start AACommServer if it is not running; does nothing if it is

// or start a specific server executable and know whether it is serving
bool serving = c.EnsureAACommServerRunning(@"C:\MyApp\aacommserver\AACommServer.exe");

    if (!aamotion_init(h))
    fprintf(stderr, "could not start AACommServer\n");
/* start AACommServer once per process; NULL = the default location */
if (!aamotion_open_aacomm_server(NULL))
    printf("starting the server failed\n");

    Connect to a controller¶

    Connects to a controller over Ethernet. During connect the SDK reads the model (checked against the one given to Initialize), the firmware version, the message table and User Units; the message table is cached per firmware, so the next connect to the same firmware is faster. The overload without an address connects to 172.1.1.101.

    Standalone demo: Connect and disconnect

    When to use it

    To connect to a real controller. With many commands and large replies, pass fastArk = false to turn immediate ACK on.

    Signatures

    // AAMotionAPI
// Connect to the motion controller, default IP is 172.1.1.101
// controller: The controller object / handle
// Returns: Returns true if connection is successful, otherwise false
static bool Connect(MotionController controller);

// Connect to the motion controller with specified IP
// controller: The controller object / handle
// deviceAddress: The controller's IP address, such as `"172.1.1.101"`. An invalid IP returns false at once.
// Returns: Returns true if connection is successful, otherwise false
static bool Connect(MotionController controller, string deviceAddress);

// controller: The controller object / handle
// deviceAddress: The controller's IP address, such as `"172.1.1.101"`. An invalid IP returns false at once.
// fastArk: The name is the reverse of its effect: `true` = PC-side TCP immediate ACK **off**; `false` = on. With many commands and large replies, turning it on speeds things up markedly; see [fastArk](../concepts/connecting.md#fastark).
static bool Connect(MotionController controller, string deviceAddress, bool fastArk);

// Connect to the motion controller with specified IP and auto-reconnect option
// controller: The controller object / handle
// deviceAddress: The controller's IP address, such as `"172.1.1.101"`. An invalid IP returns false at once.
// fastArk: The name is the reverse of its effect: `true` = PC-side TCP immediate ACK **off**; `false` = on. With many commands and large replies, turning it on speeds things up markedly; see [fastArk](../concepts/connecting.md#fastark).
// enableAutoReconnect: Only recorded; **nothing reconnects automatically today**. Call `TryReconnect` yourself.
// Returns: Returns true if connection is successful, otherwise false
static bool Connect(MotionController controller, string deviceAddress, bool fastArk, bool enableAutoReconnect);

// Connect to the motion controller with specified IP, port, and auto-reconnect option
// controller: The controller object / handle
// deviceAddress: The controller's IP address, such as `"172.1.1.101"`. An invalid IP returns false at once.
// port: The controller's Ethernet port; 50000 by default.
// noAck: Same as `fastArk`: true leaves immediate ACK off (default), false turns it on.
// enableAutoReconnect: Only recorded; **nothing reconnects automatically today**. Call `TryReconnect` yourself.
// Returns: Returns true if connection is successful, otherwise false
static bool Connect(MotionController controller, string deviceAddress, int port, bool noAck = true, bool enableAutoReconnect = false);

// MotionController
// Connects to the controller using an IP address.
// deviceAddress: The controller's IP address, such as `"172.1.1.101"`. An invalid IP returns false at once.
// noAck: Same as `fastArk`: true leaves immediate ACK off (default), false turns it on.
// enableAutoReconnect: Only recorded; **nothing reconnects automatically today**. Call `TryReconnect` yourself.
// Returns: True if connection is successful; otherwise false.
bool Connect(string deviceAddress, bool noAck = true, bool enableAutoReconnect = false);

// Connects to the controller using an IP address and port.
// deviceAddress: The controller's IP address, such as `"172.1.1.101"`. An invalid IP returns false at once.
// port: The controller's Ethernet port; 50000 by default.
// noAck: Same as `fastArk`: true leaves immediate ACK off (default), false turns it on.
// enableAutoReconnect: Only recorded; **nothing reconnects automatically today**. Call `TryReconnect` yourself.
// Returns: True if connection is successful; otherwise false.
bool Connect(string deviceAddress, int port, bool noAck = true, bool enableAutoReconnect = false);

    // Connects the session to a controller over Ethernet, serial or CAN. @param deviceAddress The controller's address, e.g. "172.1.1.101". @param fastArk Fast acknowledge mode. @param enableAutoReconnect Recorded but currently has no effect: nothing reconnects on its own; call aamotion_try_reconnect. @return true when connected.
// controller: The controller object / handle
// deviceAddress: The controller's IP address, such as `"172.1.1.101"`. An invalid IP returns false at once.
// fastArk: The name is the reverse of its effect: `true` = PC-side TCP immediate ACK **off**; `false` = on. With many commands and large replies, turning it on speeds things up markedly; see [fastArk](../concepts/connecting.md#fastark).
// enableAutoReconnect: Only recorded; **nothing reconnects automatically today**. Call `TryReconnect` yourself.
bool aamotion_connect(aamotion_controller controller, const char* deviceAddress, bool fastArk, bool enableAutoReconnect);

    Parameters

    Parameter Type Description
    controller MotionController / aamotion_controller The controller object / handle
    deviceAddress const char* / string The controller's IP address, such as "172.1.1.101". An invalid IP returns false at once.
    fastArk bool The name is the reverse of its effect: true = PC-side TCP immediate ACK off; false = on. With many commands and large replies, turning it on speeds things up markedly; see fastArk.
    enableAutoReconnect bool Only recorded; nothing reconnects automatically today. Call TryReconnect yourself.
    port int The controller's Ethernet port; 50000 by default.
    noAck bool Same as fastArk: true leaves immediate ACK off (default), false turns it on.

    Returns

    true on success; false on failure, without throwing. The reason is in the error callback and the logs.

    Notes

    • The Ethernet connect timeout is 10 s. Connect on a background thread in a GUI program.
    • When the network is fine but connect returns false, the usual cause is a model different from the one given to Initialize.
    • Do not connect an object that is already connected; to change the address, Disconnect first.

    Example

    bool ok = AAMotionAPI.Connect(c, "172.1.1.101");
if (!ok)
{
    Console.WriteLine("Connect failed: check IP, cable, subnet and the AACommServer log");
    return false;
}

// with PC-side TCP immediate ACK enabled (third argument false)
// bool ok2 = AAMotionAPI.Connect(c, "172.1.1.101", false, false);

    /* third argument false: PC-side TCP immediate ACK ON */
bool ok = aamotion_connect(h, "172.1.1.101", false, false);
if (!ok)
    fprintf(stderr, "connect failed: check IP, cable, subnet and the AACommServer log\n");

    • Connect(MotionController, string) — Connect to the motion controller with specified IP Returns: Returns true if connection is successful, otherwise false
    • Connect(MotionController, string, bool, bool) — Connect to the motion controller with specified IP and auto-reconnect option Returns: Returns true if connection is successful, otherwise false
    • Connect(MotionController, string, int, bool, bool) — Connect to the motion controller with specified IP, port, and auto-reconnect option Returns: Returns true if connection is successful, otherwise false
    • Connect(string, bool, bool) — Connects to the controller using an IP address. Returns: True if connection is successful; otherwise false.
    • Connect(string, int, bool, bool) — Connects to the controller using an IP address and port. Returns: True if connection is successful; otherwise false.
    • aamotion_connect — Connects the session to a controller over Ethernet, serial or CAN. @param deviceAddress The controller's address, e.g. "172.1.1.101". @param fastArk Fast acknowledge mode. @param enableAutoReconnect Recorded but currently has no effect: nothing reconnects on its own; call aamotion_try_reconnect. @return true when connected.

    Connect to the simulator¶

    Starts the firmware simulator firmware_sim.exe and connects to it. The server runs each session in a new temporary folder, %TEMP%\aasim-<random>\, and deletes it on disconnect, so parameters saved on the simulator are not kept. See Simulator.

    When to use it

    Developing and testing without hardware, or reproducing a problem in automated tests.

    Signatures

    // AAMotionAPI
// Connect to a locally spawned firmware simulation (`AAComm.Shared.ChannelType.Simulation`).
// controller: The controller object / handle
// simExePath: **Absolute path** of `firmware_sim.exe` (required). A relative path returns false, because the server starts the simulator from its own folder. `starter.par` must sit beside it.
// Returns: Returns true if connection is successful, otherwise false
static bool ConnectSimulation(MotionController controller, string simExePath);

// Connect to a locally spawned firmware simulation (`AAComm.Shared.ChannelType.Simulation`).
// controller: The controller object / handle
// simExePath: **Absolute path** of `firmware_sim.exe` (required). A relative path returns false, because the server starts the simulator from its own folder. `starter.par` must sit beside it.
// simProduct: Optional product name (such as `"AGM800"`, `"AGD301orAGC301"`). Giving one declares the model and skips probing; a simulator of another model fails the connect. Empty / NULL: detected after connecting.
// simVersion: Optional simulator firmware version label; empty / NULL for the default.
// simMotorProfile: Optional motor / encoder profile text (key=value); empty / NULL uses the generic default motor.
// enableAutoReconnect: Recorded only; no effect on a simulator.
// Returns: Returns true if connection is successful, otherwise false
static bool ConnectSimulation(MotionController controller, string simExePath, string simProduct, string simVersion, string simMotorProfile = "", bool enableAutoReconnect = false);

// MotionController
// Connects to a locally spawned firmware simulation over the managed `AAComm.Shared.ChannelType.Simulation` channel.
// simExePath: **Absolute path** of `firmware_sim.exe` (required). A relative path returns false, because the server starts the simulator from its own folder. `starter.par` must sit beside it.
// simProduct: Optional product name (such as `"AGM800"`, `"AGD301orAGC301"`). Giving one declares the model and skips probing; a simulator of another model fails the connect. Empty / NULL: detected after connecting.
// simVersion: Optional simulator firmware version label; empty / NULL for the default.
// simMotorProfile: Optional motor / encoder profile text (key=value); empty / NULL uses the generic default motor.
// enableAutoReconnect: Recorded only; no effect on a simulator.
// Returns: `true` when the server spawned the sim and the connect succeeded; otherwise `false`.
bool ConnectSimulation(string simExePath, string simProduct = "", string simVersion = "", string simMotorProfile = "", bool enableAutoReconnect = false);

    // Connects the session to a locally spawned firmware simulation instead of a real controller. AACommServer must already be up. To reopen a simulation, call aamotion_disconnect (which frees the handle), then a NEW aamotion_initialize, then this; not aamotion_try_reconnect, and not this alone on an open link, where it returns false. @param simExePath Absolute path to firmware_sim.exe (REQUIRED; the SDK does not ship it). A relative path returns false, since the server starts the simulator from its own directory. @param simProduct Optional product name (NULL = default). A catalogued name such as "AGM800" also declares the controller type, and a simulator that reports another type returns false. @param simVersion Optional firmware version (NULL = default). @param simMotorProfile Optional motor profile (NULL = default).
// controller: The controller object / handle
// simExePath: **Absolute path** of `firmware_sim.exe` (required). A relative path returns false, because the server starts the simulator from its own folder. `starter.par` must sit beside it.
// simProduct: Optional product name (such as `"AGM800"`, `"AGD301orAGC301"`). Giving one declares the model and skips probing; a simulator of another model fails the connect. Empty / NULL: detected after connecting.
// simVersion: Optional simulator firmware version label; empty / NULL for the default.
// simMotorProfile: Optional motor / encoder profile text (key=value); empty / NULL uses the generic default motor.
bool aamotion_connect_simulation(aamotion_controller controller, const char* simExePath, const char* simProduct, const char* simVersion, const char* simMotorProfile);

    Parameters

    Parameter Type Description
    controller MotionController / aamotion_controller The controller object / handle
    simExePath const char* / string Absolute path of firmware_sim.exe (required). A relative path returns false, because the server starts the simulator from its own folder. starter.par must sit beside it.
    simProduct const char* / string Optional product name (such as "AGM800", "AGD301orAGC301"). Giving one declares the model and skips probing; a simulator of another model fails the connect. Empty / NULL: detected after connecting.
    simVersion const char* / string Optional simulator firmware version label; empty / NULL for the default.
    simMotorProfile const char* / string Optional motor / encoder profile text (key=value); empty / NULL uses the generic default motor.
    enableAutoReconnect bool Recorded only; no effect on a simulator.

    Returns

    true when the simulator started and the connect succeeded; otherwise false.

    Notes

    • The server must already be running (in C# call Init() first).
    • The connect timeout is 20 s.
    • To reopen a simulator, neither TryReconnect nor a second call on a connected object works (it returns false). C#：Disconnect, then ConnectSimulation. C：aamotion_disconnect (frees the handle) → a new aamotion_initialize → aamotion_connect_simulation.
    • The SDK does not ship firmware_sim.exe; download the simulator package from the Agito-Releases firmware releases and unpack all of it.

    Example

    c.Init();   // ConnectSimulation needs the server already running
bool ok = AAMotionAPI.ConnectSimulation(c, @"D:\sim\AGM800\firmware_sim.exe");

// declare the product so no discovery probe runs
// bool ok2 = AAMotionAPI.ConnectSimulation(c, @"D:\sim\AGM800\firmware_sim.exe", "AGM800", null);

    aamotion_disconnect(h);                                   /* frees h */
h = aamotion_initialize(AAMOTION_CONTROLLER_TYPE_AGM800);   /* a new handle */
if (h && !aamotion_connect_simulation(h, "D:\\sim\\AGM800\\firmware_sim.exe", "AGM800", NULL, NULL))
    fprintf(stderr, "simulator did not reopen\n");
    SDK comments (original)
    • ConnectSimulation(MotionController, string) — Connect to a locally spawned firmware simulation (AAComm.Shared.ChannelType.Simulation). Returns: Returns true if connection is successful, otherwise false
    • ConnectSimulation(MotionController, string, string, string, string, bool) — Connect to a locally spawned firmware simulation (AAComm.Shared.ChannelType.Simulation). Returns: Returns true if connection is successful, otherwise false
    • ConnectSimulation(string, string, string, string, bool) — Connects to a locally spawned firmware simulation over the managed AAComm.Shared.ChannelType.Simulation channel. Returns: true when the server spawned the sim and the connect succeeded; otherwise false. AACommServer must already be running (MotionController.Init). On success it launches simExePath, configures the motor, and bridges loopback; on MotionController.Disconnect it reaps the child process. MotionController.TryReconnect is Ethernet-only and cannot recover a simulation link: to reopen one, call MotionController.Disconnect first and then this method. This method does not tear down a link it finds open, and the connect short-circuits on one, so calling it alone on a wedged session returns false without reopening anything — though MotionController.LastKnownAddress and MotionController.AutoReconnectEnabled are recorded before the attempt, so a failed call still updates them.
    • aamotion_connect_simulation — Connects the session to a locally spawned firmware simulation instead of a real controller. AACommServer must already be up. To reopen a simulation, call aamotion_disconnect (which frees the handle), then a NEW aamotion_initialize, then this; not aamotion_try_reconnect, and not this alone on an open link, where it returns false. @param simExePath Absolute path to firmware_sim.exe (REQUIRED; the SDK does not ship it). A relative path returns false, since the server starts the simulator from its own directory. @param simProduct Optional product name (NULL = default). A catalogued name such as "AGM800" also declares the controller type, and a simulator that reports another type returns false. @param simVersion Optional firmware version (NULL = default). @param simMotorProfile Optional motor profile (NULL = default).

    Check that the controller is reachable and answering¶

    Two checks that answer different questions:

    • CheckConnection / aamotion_check_connection pings the controller's network address (ICMP) to see whether it can be reached. Simulator, serial and CAN links have no IP address; they are not pinged and report the SDK's own connection state.
    • ProbeConnection / aamotion_probe_connection sends one command (a live read of the controller's Time, never through the fast read cache) and waits for the reply, proving that the controller itself is answering right now. It takes the same path as every read and write and works on Ethernet, serial, CAN and simulation. It reports the round trip, why the controller did not answer (Enums: Connection probe failure), and whether the controller restarted since the previous successful probe (its Time went down).

    Both only report; neither reconnects. IsConnected says only whether the SDK still holds the connection and replaces neither.

    // a background health check: never on the UI thread, never in a tight loop

{
    await Task.Delay(2000);
    bool reachable = await Task.Run(() => AAMotionAPI.CheckConnection(c));

    // one command round trip: is the controller itself answering?
    ConnectionProbeResult probe = await Task.Run(() => AAMotionAPI.ProbeConnection(c));
    if (probe.IsAlive && probe.ControllerRestarted)
        Console.WriteLine("The controller restarted since the last probe");
    else if (!probe.IsAlive)
        Console.WriteLine($"No answer ({probe.Failure}): {probe.Message}");

    if (!reachable || !AAMotionAPI.IsConnected(c))
    {
        bool back = await Task.Run(() => AAMotionAPI.TryReconnect(c));
        Console.WriteLine(back ? "Reconnected" : "Controller still unreachable");
    }
}

}

    Scan the network for controllers¶

    Finds controllers on a subnet. It lists every responding address through ARP (from all local Ethernet adapters), then tests each one for an Agito controller. ScanControllerDetailed also returns each controller's connection data.

    Standalone demo: Scan the network

    When to use it

    On site when the controller's IP is unknown, or to let the user pick a controller from a list at start-up.

    Signatures

    // AAMotionAPI
// Scan for available controllers on the network and return their IP addresses. Uses ARP-based discovery (via `AAComm.Services.ARPTools.GetSubnetActiveIPs`) which scans from all local Ethernet NICs on the target subnet, then validates each responder with TestConnection.
// fastScan: Required. false / 0 staggers the ARP requests 50 ms apart (about 13 s for a whole subnet); true / non-zero sends them back to back. Fast scanning is safe only when every controller on the subnet is an AGM800 or runs firmware 5.3.0 or later: an older drive can fault on the burst.

// startIP: The last octet to start from; 1 by default.

    Shut down AACommServer¶

    Disconnects this controller, then asks the shared AACommServer to exit. The server ignores the request while it has other clients (PCSuite, say). You rarely need it, since the server exits by itself after its last client leaves.

    When to use it

    When no program on this PC needs the server any more and it must close now (before installing a new version, say). Not needed normally.

    Signatures

    // AAMotionAPI
// Shutdown AACommServer
// controller: The controller object / handle
static void Shutdown(MotionController controller);

// MotionController
// Closes the AACommServer.
void Shutdown();

// Closes the AAComm server.
void CloseAACommServer();

    // Asks the shared AACommServer to exit; it exits only when this is its last client. This is the only call that tears the server down: aamotion_release and aamotion_disconnect free this session only.
// controller: The controller object / handle
bool aamotion_shutdown(aamotion_controller controller);

    Parameters

    Parameter Type Description
    controller MotionController / aamotion_controller The controller object / handle

    Returns

    The C version returns whether the call succeeded.

    Notes

    • In C this is the only call that affects the server process; aamotion_disconnect / aamotion_release free only this handle's resources. Still call aamotion_disconnect or aamotion_release afterwards to free the handle.

    Example

    // disconnects c, then asks the shared AACommServer to exit;
// the server ignores the request while another program still uses it
AAMotionAPI.Shutdown(c);

    aamotion_shutdown(h);     /* the server exits only if this is its last client */
aamotion_disconnect(h);   /* frees h */

    Release the controller object¶

    Releases every resource the controller object holds, its communication channel included, without closing the shared AACommServer. Do not use the object / handle afterwards.

    When to use it

    Releasing resources at exit. In C, disconnect already frees the handle; calling release afterwards is safe.

    Signatures

    // AAMotionAPI
// Releases all resources used by the controller, including communication channels. After calling this method, the controller instance should not be used.
// controller: The controller object / handle
static void Dispose(MotionController controller);

// MotionController
// Releases resources used by the controller. Does not shut down the shared AACommServer — call `MotionController.Shutdown` explicitly for that.
void Dispose();

    // Frees the session and its resources. Other sessions and the shared AACommServer are not affected. The handle is invalid afterwards; a NULL handle is ignored.
// controller: The controller object / handle
void aamotion_release(aamotion_controller controller);

    Parameters

    Parameter Type Description
    controller MotionController / aamotion_controller The controller object / handle

    Notes

    • In C, calling aamotion_release after aamotion_disconnect is safe; it does not free twice.

    Example

    AAMotionAPI.Dispose(c);   // releases this controller's resources; do not use c afterwards

    aamotion_release(h);      /* frees h without touching the server; safe after aamotion_disconnect */
