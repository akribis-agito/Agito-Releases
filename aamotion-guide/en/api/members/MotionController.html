    ConfigureDataLogger¶

    string ConfigureDataLogger(MotionController.DataLoggerConfiguration config)

    Set up the recorder with ConfigureDataLogger, then start it with StartDataRecording. Use GetDataRecordingStatus to inspect the state or WaitForDataRecordingToEnd to wait until it ends. Upload once the capture is complete.

    See the PCSuite DataLogger controls and parameters.

    Status Meaning
    0 No valid capture
    1 Filling the pre-trigger buffer
    2 Pre-trigger buffer full, waiting for the trigger
    3 Trigger detected, capture in progress
    4 Capture completed normally
    5 Stopped during capture
    6 Stopped before the trigger
    C# upload method When to use it
    UploadDataLoggerData Transfers everything at once and holds the link. Use for small transfers or firmware without packetized upload.
    UploadDataLoggerDataNonblocking Other commands can interleave between packets. The caller waits for upload completion or timeout.
    StartUploadDataLoggerDataNonblocking Transfers packets in the background and reports the result through a callback. Use when the caller needs to continue immediately.

    During acquisition, query the total with GetDataLoggerTotalDataCount and the controller's incremental count with ReadDataLoggerIncrementalData(out int dataCount). The overload returns a count and error text. Upload methods supply the waveform values.

    Step-by-step recording and upload

    SDK summary: Configures a data recording session; MotionController.StartDataRecording starts it.

    Parameter Type Direction Default Description
    config MotionController.DataLoggerConfiguration input by value required The configuration

    Return type: string

    Returns: Error string if failed, empty string on success

    The string-returning methods return an empty string on success and the error otherwise; StartUploadDataLoggerDataNonblocking returns true when started.

    RecordData¶

    string RecordData(MotionController.DataLoggerConfiguration config, out MotionController.DataLoggerResult result, bool forceTrigger = false, uint timeoutMs = 10000)

    Starts a recording from the configuration, waits for the trigger and the end, uploads, and returns each parameter's data and the time axis. The C version keeps the result in the handle; read it with _info, _vector_info, _vector_values and _time.

    Trigger types (RecTrigTyp):

    Value Fires when
    0 immediately
    1 / 2 / 3 / 4 the source is greater than / equal to / not equal to / less than the value
    5 / 6 the source rises above / falls below the value
    7 only by hand (ForceDataLoggerTrigger)
    8 the source differs from its value at the start
    9 / 10 the source is inside / outside (Value, MaxValue)
    11 / 12 the source enters / leaves (Value, MaxValue)

    Record in one call

    SDK summary: Convenience method to perform a complete recording cycle: configure, start, wait, and upload.

    Parameter Type Direction Default Description
    config MotionController.DataLoggerConfiguration input by value required The configuration: ParamsToRecord (such as "APos", "AVel[1]"), DurationSec, GapMs, TriggerPosition (the pre-trigger percentage, 20 by default), Trigger (null records at once)
    result MotionController.DataLoggerResult out required The result: Vectors (each parameter's name, CAN code and values), TimeSec (the time axis), RecGap, RecLength
    forceTrigger bool input by value false Force the trigger right after starting
    timeoutMs uint input by value 10000 The timeout for the recording to end, ms

    Return type: string

    Returns: Error string if failed, empty string on success

    C# RecordData returns an empty string on success and the error otherwise; the C version returns true on success.

    EventTableClient CreateEventTableClient(char axis)

    A standard table event (EventType = 2) triggers at unevenly spaced part features. Disarm first, then write EventTable positions in travel order.     Central-i verified tables¶

    The AAMotion .NET factory c.CreateEventTableClient('A') binds to the current connection and axis. Check verified-table support (Identity[62] mask 0x200), a compatible remote drive image, a commissioned encoder and event source, and LockEventStat = 1.

    1. LoadAsync uploads and reads back the definition and waits for controller-confirmed Ready. Then call ArmAsync. If it returns Armed, call WaitForCompletionAsync to confirm completion. Short sequences can complete before the host sees Running.

    CheckConnection¶

    bool CheckConnection()

    Two checks that answer different questions:

    • CheckConnection / aamotion_check_connection pings the controller's network address (ICMP) to see whether it can be reached. Simulator, serial and CAN links have no IP address; they are not pinged and report the SDK's own connection state.
    • ProbeConnection / aamotion_probe_connection sends one command (a live read of the controller's Time, never through the fast read cache) and waits for the reply, proving that the controller itself is answering right now. It takes the same path as every read and write and works on Ethernet, serial, CAN and simulation. It reports the round trip, why the controller did not answer (Enums: Connection probe failure), and whether the controller restarted since the previous successful probe (its Time went down).

    Both only report; neither reconnects. IsConnected says only whether the SDK still holds the connection and replaces neither.

    Check that the controller is reachable and answering

    SDK summary: Actively probes physical reachability via ICMP ping and returns the result. Unlike MotionController.IsConnected, this always sends a probe and can block for up to ~1 second — call it deliberately (a background timer, a manual health check), never from a binding or a property-style hot path. Two independent probes are sent; either succeeding counts as reachable, so a single blocked or rate-limited ICMP packet is not mistaken for a dead link. For a connection made over a non-IP channel (Simulation, serial, CAN), or before any address is known, ICMP has nothing to probe and this reports the logical state instead — the same value MotionController.IsConnected would return. This never disconnects or reconnects anything by itself. Call MotionController.TryReconnect to recover a link this reports as down. A reachable address does not prove the controller answers commands; MotionController.ProbeConnection does.

    Parameters: none.

    Return type: bool

    CheckConnection: true when reachable; false when not connected or not answering the ping.

    C# ProbeConnection: a ConnectionProbeResult with IsAlive, Failure, RoundTripMs, Message, ControllerTime, ControllerRestarted and Timestamp (UTC). It throws only for a timeoutMs out of range; AAMotionAPI.ProbeConnection with a null controller returns NotConnected.

    C aamotion_probe_connection: true when the probe ran, with the outcome in *failure; false, nothing written, for a bad handle or timeoutMs, or a NULL failure.

    ProbeConnection¶

    ConnectionProbeResult ProbeConnection(int? timeoutMs = null)

    Two checks that answer different questions:

    • CheckConnection / aamotion_check_connection pings the controller's network address (ICMP) to see whether it can be reached. Simulator, serial and CAN links have no IP address; they are not pinged and report the SDK's own connection state.
    • ProbeConnection / aamotion_probe_connection sends one command (a live read of the controller's Time, never through the fast read cache) and waits for the reply, proving that the controller itself is answering right now. It takes the same path as every read and write and works on Ethernet, serial, CAN and simulation. It reports the round trip, why the controller did not answer (Enums: Connection probe failure), and whether the controller restarted since the previous successful probe (its Time went down).

    Both only report; neither reconnects. IsConnected says only whether the SDK still holds the connection and replaces neither.

    Check that the controller is reachable and answering

    SDK summary: Sends one command to the controller and waits for its reply, to tell whether the controller is answering right now — the same path every read and write takes. The command reads Time (seconds since power-on) live, never through the fast read cache, and works on every channel: Ethernet, serial, CAN and simulation. Use it from a dedicated thread, as a heartbeat or before deciding to reconnect. Unlike MotionController.IsConnected, which only reports whether the SDK still holds the connection, and MotionController.CheckConnection, which pings the network address, this proves the controller itself answers, says why it did not, and notices a controller restart. A timeout on the wire tears the connection down , as any command timeout does: the server closes the controller's channel for every client on it. Keep timeoutMs above the longest reply the controller can take while busy. A probe that times out still queued behind other commands was never sent and leaves the connection up; MotionController.IsConnected tells the two apart. The probe never reconnects: when it reports the link down, call MotionController.TryReconnect on Ethernet, or MotionController.Disconnect and ConnectSimulation on a simulation. A probe that is sent and fails raises MotionController.ErrorOccurred and MotionController.ErrorReported like any other command; one refused because the link is already down raises neither. Concurrent probes on one controller run one at a time.

    Parameter Type Direction Default Description
    timeoutMs int? input by value null Milliseconds to wait for the reply, 10–60000. C#: null (the default) uses the current default timeout, and a value out of range throws ArgumentOutOfRangeException. C: 0 uses the default timeout, and a value out of range returns false.

    Return type: ConnectionProbeResult

    Returns: Whether the controller answered, the round-trip time, the controller's Time, whether it restarted since the previous successful probe, and the reason for a failure.

    CheckConnection: true when reachable; false when not connected or not answering the ping.

    C# ProbeConnection: a ConnectionProbeResult with IsAlive, Failure, RoundTripMs, Message, ControllerTime, ControllerRestarted and Timestamp (UTC). It throws only for a timeoutMs out of range; AAMotionAPI.ProbeConnection with a null controller returns NotConnected.

    C aamotion_probe_connection: true when the probe ran, with the outcome in *failure; false, nothing written, for a bad handle or timeoutMs, or a NULL failure.

    T:System.ArgumentOutOfRangeException: timeoutMs is below 10 or above 60000.

    UseUserUnits¶

    bool UseUserUnits { get; set; }

    SDK summary: Gets or sets whether this controller expresses values in the connected controller's Global User Units. Set it to false to keep every read and write in raw controller counts — the escape hatch for an integration written against a counts-based API. Default true. The setting survives connect and reconnect, so it can be configured before connecting: the communication layer clears its own opt-out on every successful connect, and this controller re-applies the value last assigned here once the connect succeeds. Instance-wide, not call-wide — it forwards to AAComm.CommAPI.SkipUserUnits, so two controllers sharing one AAComm.CommAPI share the setting. To bypass the scaling for a single message, use AAComm.Services.AACommMessage.SkipUserUnits instead. What is read back is what the communication layer will actually do, so a direct write to AAComm.CommAPI.SkipUserUnits is visible here — but only a value assigned through this property is remembered, and only that is re-applied at the next connect. Opting out does not unlock raw User Units configuration writes: a direct assignment to a *UnitFct or *UnitUnt parameter stays rejected either way.

    Access: get; set;

    Value type: bool
