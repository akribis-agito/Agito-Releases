FastReadCacheRefreshIntervalMs

When FastReadCache is enabled, this interval controls how often data is refreshed from the controller. Default: 1ms

public static int FastReadCacheRefreshIntervalMs { get; set; }

Property Value

int

FastReadEnabled

Turns the fast read cache on: every registered keyword is refreshed with one bulk query every FastReadCacheRefreshIntervalMs, MotionStat and InTargetStat last, and reading a registered keyword answers from the cache instead of the controller. Default: false (disabled for backward compatibility).

public static bool FastReadEnabled { get; set; }

Property Value

bool

Remarks

Set it before connecting: on connect the cache registers MotionStat, InTargetStat, MotorOn, ConFlt, Pos, PosRef, LimitsStat, MotionReason and Force of axes A, B and C, each only where the controller has it; register anything else with RegisterCacheKeywords. While it is false AAMotion reads every value from the controller, as it always has.

HighResolutionTimer

Holds Windows at a 1 ms timer resolution while any controller is connected. Default: false. Takes effect at once, connected or not; on other operating systems it does nothing.

public static bool HighResolutionTimer { get; set; }

Property Value

bool

Remarks

At the default 15.6 ms resolution every Thread.Sleep, timer and wait in the process rounds up to a multiple of 15.6 ms: a caller's Sleep(5) takes about 15.6 ms, so an axis in target after 18 ms is seen at 31.2 or 46.8 ms. With the switch on, Sleep(5) takes about 6 ms. AAMotion calls timeBeginPeriod(1) when the first controller connects and timeEndPeriod(1) when the last one disconnects or is disposed, and opts the process out of the Windows 11 power throttling that otherwise ignores the 1 ms request while its window is minimized or hidden. It is off by default because it changes timing for the whole process and costs some power, which matters on a laptop.

InTargetStatRefreshIntervalMs

How often, in milliseconds, the fast read cache reads InTargetStat of an axis that is moving, from Begin until the axis reads 4 (in target). Only the moving axes are read: one axis with <axis>InTargetStat, the reply the controller answers fastest (about 0.4–0.7 ms); several with one bulk. Default: 1.

public static int InTargetStatRefreshIntervalMs { get; set; }

Property Value

int

Remarks

Applies only while FastReadEnabled is on. The poll also stops for an axis that has stood outside the in-target window for more than 2 s; a read that fails waits 1 ms before the next.

MoveStartConfirmMs

The longest time, in milliseconds, after Begin that the fast read cache waits to see a motion start before it answers MotionStat and InTargetStat again. Default: 5.

public static int MoveStartConfirmMs { get; set; }

Property Value

int

Remarks

Right after Begin the controller can still report the state before the motion, and a cached InTargetStat of 4 would read as the new motion already finished. Until a reading taken after Begin shows the motion has started (InTargetStat other than 4, or MotionStat other than 0), the cache does not answer either keyword for that axis and the read goes to the controller. A move to the position the axis already holds never leaves the in-target window, so after this time the cache answers again. Applies only while FastReadEnabled is on.
