A command the controller refused, or answered with a reply the SDK could not read as a value.

It is raised by the members that answer with the value itself and so have nowhere to report a failure — the typed properties, GetValue(AxisRef, eKeyword, int) — where a 0 is indistinguishable from the controller genuinely reporting 0. TryRead(eKeyword, out double), TryReadArray(eKeyword, int, out double) and TryGetValue(AxisRef, eKeyword, out double, int) report the same failure as false and never throw. Either way the failed read is recorded in LastReadError and counted by ReadFailures.

A typed property set the controller refuses raises it as well, with Command carrying the assignment exactly as sent (ASpeed=1000) — a dropped write leaves the next read answering the old value, with nothing at the call site to say so. A failed write is deliberately not recorded in LastReadError and not counted by ReadFailures: both are the read record, by name and by their own contract, so a consumer reading them keeps being told about reads and nothing else. There is no TrySet — catch this, or subscribe to ErrorOccurred, which is raised for the refusal as before.
