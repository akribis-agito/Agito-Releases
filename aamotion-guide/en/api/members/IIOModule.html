    DOutClearBit¶

    bool DOutClearBit(int index)

    Sets, clears or toggles one digital output, and reads back the state of a bit. A write changes only that output.

    Write digital outputs

    SDK summary: Clear the specified digital output bit

    Parameter Type Direction Default Description
    index int input by value required The output number, from 1

    Return type: bool

    Returns: Returns true if the command is sent successfully, otherwise false

    Writes return true on success. GetDOutPort returns 0 or 1; the C version also returns 0 on failure.

    GetDOutPort¶

    int GetDOutPort(int bit)

    Sets, clears or toggles one digital output, and reads back the state of a bit. A write changes only that output.

    Write digital outputs

    SDK summary: Gets the current state of a specific digital output bit

    Parameter Type Direction Default Description
    bit int input by value required The register bit, from 0 (output n is bit n − 1)

    Return type: int

    Returns: State of the specified bit (0 = Off, 1 = On).It is also necessary to refer to IIOModule.DInLog

    Writes return true on success. GetDOutPort returns 0 or 1; the C version also returns 0 on failure.

    GetDInPort¶

    int GetDInPort(int bit)

    Reads one digital input bit. To test several inputs, read the whole DInPort register once and mask it; one round trip instead of several.

    Read digital inputs

    SDK summary: Gets the current state of a specific digital input bit

    Parameter Type Direction Default Description
    bit int input by value required The register bit, from 0

    Return type: int

    Returns: State of the specified bit (0 = Off, 1 = On).It is also necessary to refer to IIOModule.DOutLog

    0 or 1. The C version also returns 0 on failure; when that matters, read ADInPort with a raw command and check the result.

    AADynamicValueArray AInPort { get; }

    SDK summary: Read-only array containing processed and raw values of analog input ports. The first half: processed values (filtered, offset, deadband, gain applied) for each channel; The second half: raw input values for each channel (unprocessed). - Old firmware (int type): Integer values representing raw ADC counts. - New firmware (float type): Float values representing actual voltage/processed values. Each element is a double, whatever the controller's parameter type. , , ,

    int DOutLog { get; set; }

    SDK summary: Digital output logic inversion control. Each bit corresponds to an output point: 0 - normal logic (DOutPort=1 outputs "On", 0 outputs "Off"), 1 - inverted logic (1 outputs "Off", 0 outputs "On"). Note: The 0th bit (LSB) of DOutLog corresponds to output 1. , ,

    Keyword, units and value contract

    Access: get; set;

    Value type: int

    DOutMode¶

    AAValueArray<double> DOutMode { get; }

    SDK summary: Digital output mode configuration array. Each element defines the special function of the corresponding output point. Value and function: 0 - Normal output (controlled by DOutPort) 1 - Dedicated hardware function (not used) 2 - Servo enable (reflects MotorOn status) 3 - In motion (reflects MotionStat status) 4 - Accelerating (reflects MotionStat acceleration bit, only valid in built-in analyzer mode) 5 - Decelerating (reflects MotionStat deceleration bit, only valid in built-in analyzer mode) 6 - Constant speed (reflects MotionStat constant speed bit, only valid in built-in analyzer mode) 7 - Motion end (not used) 8 - Target reached (reflects InTargetStat=4) 9 - Fault/alarm (reflects ConFlt status) 10 - Last motion warning (not used) 11 - Last motion saturation (not used) 12 - RLS/FLS active (reflects LimitsStat status) 13 - Out of travel (RevPLim, FwdPLim) 14 - Regeneration active 15 - Dynamic brake active 16 - Motor brake active (can be used with DInMode[i]=13) If multiple outputs are assigned the same special function, the output with the higher number has priority. , , ,

    Keyword, units and value contract

    Access: get;

    Value type: AAValueArray<double>

    AInDB¶

    AADynamicValueArray AInDB { get; }

    SDK summary: Analog input deadband (unit: mV). If the input voltage is between (-AInDB) and AInDB, the reading is 0; If it exceeds AInDB, the reading is (actual voltage - AInDB); If it is below (-AInDB), the reading is (actual voltage + AInDB). - Old firmware (int type): Integer deadband values in millivolts. - New firmware (float type): Float deadband values in millivolts. Each element is a double, whatever the controller's parameter type. , , ,

    Keyword, units and value contract

    Access: get;

    Value type: AADynamicValueArray

    AOutGain¶

    AAValueArray<double> AOutGain { get; }

    SDK summary: Analog output gain, a plain multiplier: AOutGain[i] scales the i-th analog output together with the parameter selected by AOutMode. Reported by firmware with float analog IO. Firmware without it reports IIOModule.AOutShifts at the same CAN code instead — a different parameter, not another name for this one — and on such a controller reading or writing an output, AOutGain[i] with i from 1, raises System.IndexOutOfRangeException before anything is sent. , ,

    Keyword, units and value contract

    Access: get;

    Value type: AAValueArray<double>

    AOutShifts¶

    AAValueArray<double> AOutShifts { get; }

    SDK summary: Analog output shift exponent: the i-th analog output is scaled by 2^AOutShifts[i], so a negative value divides and a positive one multiplies. Reported by firmware without float analog IO. Firmware with it reports IIOModule.AOutGain at the same CAN code instead, which carries a plain multiplier rather than an exponent — the two are not interchangeable, and 2 here means x4 where 2 there means x2. On a controller that reports AOutGain reading or writing an output, AOutShifts[i] with i from 1, raises System.IndexOutOfRangeException before anything is sent. , ,

    Keyword, units and value contract

    Access: get;

    Value type: AAValueArray<double>
