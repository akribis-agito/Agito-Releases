Parameter type converter - handles type conversion for controller parameters.

Core functionality:

  • The value slot is a double and holds the parameter's value as the caller sees it, including any User Units scaling AAComm has applied to the reply
  • Replies are read as decimal numbers and writes are rendered back with the same invariant wire text, so a scaled integral parameter keeps its fraction in both directions
  • A write carries the display value whole; AAComm's transmit seam divides it by the User Units factor and rounds a firmware-integral parameter in controller counts, so rounding happens once, below the scaling, on every transport
  • long: read with a separate command rather than from the slot; the controller's 64-bit parameters stay inside +/-2^51, which a double holds exactly
  • Type detection comes from XML metadata or the cache; use ToInt32Register(double) for bit arithmetic on a register-shaped parameter

ConvertStringToRawValue(eKeyword, string)

Convert a controller reply to the internal value representation. Every reply is read as a decimal number: AAComm hands back the User-Units product of an integral parameter without rounding, so an integer-only parse turns a scaled reply into 0. A reply that is not a finite number resolves to 0 — it has no numeric meaning, and the frameworks disagree both on whether an overflowing literal parses at all and on what a non-finite double narrows to.

ToInt32Register(double)

The controller's 32-bit two's-complement view of a slot value, for bit arithmetic on a register-shaped parameter such as a digital-output port or a status word. A value outside int wraps modulo 2^32 — the bits the controller itself holds — rather than taking the runtime's unspecified out-of-range (int) conversion, which saturates on .NET 10 and yields MinValue on .NET Framework and .NET 8. Non-finite values, which have no bit pattern to fold, resolve to 0.
