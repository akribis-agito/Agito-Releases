    SlowLogger (slow recording)¶

    The slow logger is for long recordings: the controller puts the chosen parameters into a FIFO every LoggerGap, and the PC uploads periodically. It samples slower than the high-speed recorder but can run indefinitely (a whole day of temperatures or following error, say). What happens when the FIFO is full is set by LoggerFullMod, and lost packets count in LoggerLostPackets. Each keyword is explained under LoggerParams.

    Configure and upload¶

    ConfigureSlowLogger sets the sample gap, the FIFO-full handling and the parameters in one call; the SDK turns the parameter names into the CAN codes the controller wants in LoggerParams[]. LoggerUpload() returns the controller's raw reply; LoggerUpload(the same parameters) resolves it against the configured parameters, scaled by User Units, and returns a LoggerDataContainer.

    Standalone demo: Log slowly for 2 s

    When to use it

    Long monitoring (hours to days): trends of temperature, current, following error.

    Signatures

    // MotionController
// Convenience helper to configure slow logger parameters in one call.
// loggerGap: The sample gap (`LoggerGap`); above 0
// loggerFullMode: The FIFO-full handling (`LoggerFullMod`); 0 by default
// parameterSpecifications: The parameters, such as `"APos"`, `"AVel[1]"`, or `SlowLoggerParameter` objects or CAN codes. Arrays need an index and scalars take none
void ConfigureSlowLogger(int loggerGap, int loggerFullMode = 0, params object[] parameterSpecifications);

// Uploads slow logger data from the controller.
// Returns: Response string from log upload containing the data packets.
string LoggerUpload();

// Uploads the logger data and resolves it against the parameters the caller configured — the same specifications `MotionController.ConfigureSlowLogger` took, in the same order — so every value comes back resolved and scaled the way every other read does. AAMotion keeps no record of the configuration; the caller supplies it. A `null` specification is skipped, as `MotionController.ConfigureSlowLogger` skips it. An error reply raises `MotionController.ErrorOccurred` and yields no packets.
// parameterSpecifications: The parameters, such as `"APos"`, `"AVel[1]"`, or `SlowLoggerParameter` objects or CAN codes. Arrays need an index and scalars take none
LoggerDataContainer LoggerUpload(params object[] parameterSpecifications);

    // Samples chosen parameters continuously and pushes packets to the PC without a trigger. Upload often enough to keep the controller's FIFO from filling. The int getters return 0 on ANY failure. Configures the logger in one call. @param gap Sampling gap (ALoggerGap), > 0. @param fullMode What a full FIFO does (ALoggerFullMod): 0 pause, 1 overwrite the oldest data. @param paramNames paramCount names to record, e.g. "APos", "AVel[2]". NULL or paramCount 0 sets gap and fullMode only and leaves the recorded parameters alone.
// controller: The controller object / handle
// gap: The sample gap
// fullMode: The FIFO-full handling
// paramNames: C: the parameter names; NULL sets only the gap and mode
// paramCount: The number of parameters
bool aamotion_configure_slow_logger(aamotion_controller controller, int gap, int fullMode, const char** paramNames, int paramCount);

// Fetches the packets waiting on the controller into response: "count,t1,p1,p2,...,t2,p1,p2,...,0" - the packet count, then per packet its timestamp and one value per configured parameter in configured order, then a 0 end marker. @return false for a controller error (the error callback has it) or an empty reply.
// controller: The controller object / handle
// response: C: the buffer for the raw data
// responseSize: The buffer size
bool aamotion_logger_upload(aamotion_controller controller, char* response, int responseSize);

    Parameters

    Parameter Type Description
    loggerGap int The sample gap (LoggerGap); above 0
    loggerFullMode int The FIFO-full handling (LoggerFullMod); 0 by default
    parameterSpecifications object[] The parameters, such as "APos", "AVel[1]", or SlowLoggerParameter objects or CAN codes. Arrays need an index and scalars take none
    controller aamotion_controller The controller object / handle
    gap int The sample gap
    fullMode int The FIFO-full handling
    paramNames const char** C: the parameter names; NULL sets only the gap and mode
    paramCount int The number of parameters
    response char* C: the buffer for the raw data
    responseSize int The buffer size

    Returns

    C# LoggerUpload() returns the raw text and the overload with parameters the resolved data; the C version returns true on success.

    Notes

    • The C# ConfigureSlowLogger stops the recorder and replaces the channel table. It has up to 40 one-based slots in groups of five. Check whether PCSuite or another client is using the recorder before reconfiguring.
    • Each LoggerUpload takes only complete packets that fit the current reply and releases their FIFO space. Use one collecting client. A zero-packet reply can be temporary.
    • Setting LoggerOn = 0 stops sampling and leaves buffered data available for upload. Read the remaining packets after stopping when you need the tail of the capture.
    • Supply exactly the configured parameters, axes, indices, and order to the parsed overload. It can return an empty result on a communication error. Check ErrorOccurred.

    Example

    c.ConfigureSlowLogger(10, 0, "APos", "AVel[1]", "BPos");
try
{
    c.LoggerOn = 1;
    System.Threading.Thread.Sleep(100);
    Console.WriteLine(c.LoggerUpload());
}
finally
{
    c.LoggerOn = 0;
}

    const char* params[] = { "APos", "AVel[1]", "BPos" };
aamotion_configure_slow_logger(h, 100, 0, params, 3);
aamotion_set_logger_on(h, 1);
/* ... */
char* reply = malloc(1 << 20);
if (aamotion_logger_upload(h, reply, 1 << 20))
    printf("%zu bytes of raw logger data\n", strlen(reply));
printf("lost packets: %d\n", aamotion_get_logger_lost_packets(h));
aamotion_set_logger_on(h, 0);
free(reply);

    On / off and status¶

    The C interface has a read / write function for each slow-logger keyword; in C# use the controller object's properties: c.LoggerOn, c.LoggerGap, c.LoggerFullMod, c.LoggerParams[i], c.LoggerStatus[i], c.LoggerAbout[i], c.LoggerFreeSpace, c.LoggerState, c.LoggerPushedPackets, c.LoggerLostPackets.

    Standalone demo: Read the logger state

    When to use it

    Controlling the slow logger and reading its state from C; in C# use the matching properties.

    Parameters

    Parameter Type Description
    controller aamotion_controller The controller handle
    on int 1 starts logging, 0 stops
    gap int The sample gap
    mode int The FIFO-full handling
    index int The array index, from 1
    value int The value to write

    Returns

    Reads return the value, or 0 on failure (indistinguishable from a real 0); writes return true on success.

    Notes

    • LoggerState is 0 when off, 1 when recording, and 2 when paused because the FIFO is full.
    • LoggerFreeSpace counts slots. Compare it with the packet size in LoggerStatus[1] to see if there is room for another packet.
    • If LoggerLostPackets keeps rising, upload more frequently, increase LoggerGap, or reduce the number of channels. Use the counter to detect loss and packet headers to track spacing between packets.

    Configuration and periodic upload examples¶

    These snippets use a connected MotionController c. Choose one configuration form. Set LoggerOn = 1 after configuration to start sampling.

    Sample interval and FIFO¶

    One unit of LoggerGap spans 16 controller sample periods. With a controller period of about 61 µs, gaps of 1, 10 and 100 correspond to about 1 ms, 9.76 ms and 97.6 ms. Set the host upload cadence separately from the controller sample interval.

    LoggerFullMod When the FIFO fills Effect
    0 Pause writes until uploads free space Preserves queued data, with possible gaps during the pause
    1 Overwrite the oldest data Prioritizes recent samples

    Configure using CAN codes¶

    Use GetKeywordCANCode to resolve the axis and any array index into the controller's code.

    int aPos = c.GetKeywordCANCode(eKeyword.Pos, AxisRef.A);
int aVel = c.GetKeywordCANCode(eKeyword.Vel, AxisRef.A, 1);
c.ConfigureSlowLogger(10, 0, aPos, aVel);

    Configure using typed parameters¶

    Supply the axis, keyword, and any required array index.

    var aPos = new MotionController.SlowLoggerParameter(
    AxisRef.A, eKeyword.Pos);
var bVel = new MotionController.SlowLoggerParameter(
    AxisRef.B, eKeyword.Vel, 1);
c.ConfigureSlowLogger(10, 0, aPos, bVel);

    Upload periodically and save a CSV¶

    This example makes 40 uploads spaced by a 50 ms delay. Choose a polling cadence for the channel count, sample rate, and link speed. Check the lost-packet counter and available space when adjusting it. The example stops acquisition at the end.

    object[] channels = { "APos", "AVel[1]", "BPos" };
c.ConfigureSlowLogger(10, 0, channels);
using (var csv = System.IO.File.CreateText("slow-logger.csv"))
{
    csv.WriteLine("packet_id,APos,AVel[1],BPos");
    try
    {
        c.LoggerOn = 1;
        int previousLost = c.LoggerLostPackets;
        for (int i = 0; i < 40; i++)
        {
            System.Threading.Thread.Sleep(50);
            var data = c.LoggerUpload(channels);
            foreach (var packet in data.Packets)
                csv.WriteLine(FormattableString.Invariant(
                    $"{packet.Id},{packet.Values[0]},{packet.Values[1]},{packet.Values[2]}"));
            int lost = c.LoggerLostPackets;
            if (lost != previousLost)
                Console.WriteLine($"Lost packets: {lost}");
            previousLost = lost;
        }
    }
    finally
    {
        c.LoggerOn = 0;
    }
}

    Interpret the packet header¶

    For two channels, the raw reply 2,160,1200,35,320,1250,37,0 contains two packets. The first header is 160 with channel values 1200 and 35. The second header is 320 with channel values 1250 and 37. The final 0 is the end marker.

    The parser exposes PacketCount, Packets, and LastPacketId. The header carries a packet ID or a controller sample count, depending on whether the controller supports DataLoggerByTime. A packet ID normally increments by one. When the header counts controller periods, a gap of 10 gives 160 periods between successive packets, about 9.76 ms at a 61 µs controller period.
