    Initialize¶

    static MotionController Initialize(ControllerType controllerType)

    Creates the controller object for a controller model and makes sure the local AACommServer is running (starting it if needed). It does not connect yet. Use one object per controller; for several controllers create several objects.

    Create the controller object

    SDK summary: Initialize the motion controller

    Parameter Type Direction Default Description
    controllerType ControllerType input by value required The controller model (ControllerType / AAMOTION_CONTROLLER_TYPE_*). It must match the controller you connect to; connect checks it. See Enums: Controller type.

    Return type: MotionController

    Returns: Returns the MotionController instance of the corresponding type

    C#: the controller object. C: the controller handle, or NULL when the type is unknown or the server cannot be started.

    OpenAACommServer¶

    static void OpenAACommServer()

    Makes sure AACommServer is running, starting it if it is not and doing nothing if it is. You rarely need it, since Initialize already does it; call it once before connecting to a simulator, which needs the server ready. OpenAACommServer(path) and EnsureAACommServerRunning(path) start a server executable at a path you give and report whether a server is serving the port.

    Start AACommServer

    SDK summary: Ensures AACommServer is running. If already running, does nothing. Uses the internal default startup method. Every call checks the server's port, so a server that exited after an earlier call is started again.

    Parameters: none.

    Return type: void

    Init returns nothing (the C version returns success). OpenAACommServer(path) returns ConnectResult.Success when the server is serving; EnsureAACommServerRunning returns true when a server, of any build, is listening on the port.

    OpenAACommServer¶

    static ConnectResult OpenAACommServer(string serverExePath)

    Makes sure AACommServer is running, starting it if it is not and doing nothing if it is. You rarely need it, since Initialize already does it; call it once before connecting to a simulator, which needs the server ready. OpenAACommServer(path) and EnsureAACommServerRunning(path) start a server executable at a path you give and report whether a server is serving the port.

    Start AACommServer

    SDK summary: Checks if AACommServer is already running; if not, launches it from the specified executable path. Every call checks the server's port, so a server that exited after an earlier call is started again. Delegates to AAComm.CommAPI.StartAACommServer — the spawn contract lives there (headless args, its own standard streams, server working directory, socket-ready polling with a child-death probe).

    Parameter Type Direction Default Description
    serverExePath string input by value required Absolute path of the AACommServer executable. With an empty path EnsureAACommServerRunning starts nothing and only reports whether a server is running.

    Return type: ConnectResult

    Returns: ConnectResult.Success if the server is serving its port; otherwise an error result.

    Init returns nothing (the C version returns success). OpenAACommServer(path) returns ConnectResult.Success when the server is serving; EnsureAACommServerRunning returns true when a server, of any build, is listening on the port.

    Connect¶

    static bool Connect(MotionController controller)

    Connects to a controller over Ethernet. During connect the SDK reads the model (checked against the one given to Initialize), the firmware version, the message table and User Units; the message table is cached per firmware, so the next connect to the same firmware is faster. The overload without an address connects to 172.1.1.101.

    Connect to a controller

    SDK summary: Connect to the motion controller, default IP is 172.1.1.101

    Parameter Type Direction Default Description
    controller MotionController input by value required The controller object / handle

    Return type: bool

    Returns: Returns true if connection is successful, otherwise false

    true on success; false on failure, without throwing. The reason is in the error callback and the logs.

    ConnectSimulation¶

    Starts the firmware simulator firmware_sim.exe and connects to it. The server runs each session in a new temporary folder, %TEMP%\aasim-<random>\, and deletes it on disconnect, so parameters saved on the simulator are not kept. See Simulator.

    SDK summary: Connect to a locally spawned firmware simulation (AAComm.Shared.ChannelType.Simulation).

    Parameter Type Direction Default Description

    Return type: bool

    Returns: Returns true if connection is successful, otherwise false

    true when the simulator started and the connect succeeded; otherwise false.

    Disconnect¶

    static bool Disconnect(MotionController controller)

    Disconnects from the controller. For a simulator, the simulator process ends and its temporary folder is deleted. AACommServer keeps running, since other programs may use it; it exits by itself after its last client leaves.

    Disconnect

    SDK summary: Disconnect from the motion controller

    Parameter Type Direction Default Description
    controller MotionController input by value required The controller object / handle

    Return type: bool

    Returns: Return "ture" if the connection is successfully disconnected; otherwise, return "false"

    true when disconnected.

    IsConnected¶

    static bool IsConnected(MotionController controller)

    Reads the locally kept link state. It sends nothing and never blocks, so it is fine to poll (a status light in a UI, say). It does not prove the controller is reachable; with the cable pulled, the link can still read as connected.

    Is it connected

    SDK summary: Check if the motion controller is currently connected. Cheap, non-blocking — a plain read of the comm layer's own logical state, not an active reachability probe.

    Parameter Type Direction Default Description
    controller MotionController input by value required The controller object / handle

    Return type: bool

    Returns: Returns true if connected, false if disconnected

    true when connected.

    • CheckConnection / aamotion_check_connection pings the controller's network address (ICMP) to see whether it can be reached. Simulator, serial and CAN links have no IP address; they are not pinged and report the SDK's own connection state.

    GearBegin¶

    static bool GearBegin(MotionController controller, AxisRef axis, AAMotionAPI.GearMotionConfig config)

    Makes an axis follow a master parameter at the ratio RatioNumerator / RatioDenominator (C: ratioNumerator / ratioDenominator), writing the whole configuration and starting the motion in one call. The configuration is the C# AAMotionAPI.GearMotionConfig or the C aamotion_gear_config:

    Field Meaning
    Master / master The parameter followed, named with its axis prefix: "BPos" (B's encoder), "APosRef" (A's position command), "AAuxPos"; required
    RatioNumerator, RatioDenominator The ratio (written to MasterFact / MasterFactDen); 65536 / 65536 is 1:1, within the ranges the controller gives the parameters. Firmware without MasterFactDen divides by 65536 and takes only 65536 as the denominator
    Filter / filter The input filter in 64ths (MasterFilt), 1–64; 64 passes the master unfiltered, a smaller value filters more slowly. Direct gearing only
    MasterModRev / masterModRev The master's modulus: the master's own ModRev when it has one, 0 for none
    MotionMode / motionMode 5 direct: the geared master is the position command; 6 indirect: it is the profiler's target, so the axis's speed, acceleration, deceleration and jerk limit the motion

    It writes GearMaster, MasterFact, MasterFactDen (when the firmware has it), MasterModRev (when the firmware has it), MasterFilt (direct gearing only) and MotionMode, then sends Begin. Stop it with Stop / aamotion_stop.

    See the PCSuite gearing controls and parameters.

    PvajWriteHeader¶

    static void PvajWriteHeader(MotionController controller, AxisRef axis, int length, int gap, PvajPositionMode mode)

    When the host already has position, velocity, acceleration and jerk for every trajectory point, PVAJ motion makes the axis follow that list (MotionMode 22 for one axis, 23 for a member of a multi-axis group). PVAJ needs an AGM800 with firmware 5.3.0 or later. Support is a property of the controller, not of an axis: a controller whose message table carries PVAJList supports it on every motion axis. Check with PvajSupported / aamotion_pvaj_supported first; without it, the other PVAJ calls refuse before sending anything, with an error that names the missing feature.

    The normal order of calls:

    1. PvajWriteHeader: the point count (1 to MaxPvajPoints / AAMOTION_PVAJ_MAX_POINTS, 8192), the gap (1 to MaxPvajGap / AAMOTION_PVAJ_MAX_GAP, 32 base sample periods; above 1 the controller interpolates between the points with a quintic spline) and the position mode (Enums: PVAJ position mode).
    2. PvajWritePoint: one point at a time, from point 1. Every value must be finite.
    3. PvajValidate, normally the full check (Enums: PVAJ validation mode). After an edit to the list, validate again before the next arm; a trajectory snapshot already executing runs to its end.
    4. PvajArm. The axis disarms itself when the motion ends, so arm again before every motion.
    5. PvajBegin: sets MotionMode (22, or 23 with groupMember true) and starts the motion.
    6. PvajGetStatus: the state (Enums: PVAJ state), the point being executed and the points left. It always reads the controller live, never the fast read cache.

    ISingleAxis also exposes the keywords as properties: PVAJList, PVAJValidate, PVAJArm, PVAJStatus, PVAJPosTol and PVAJVelTol. The keyword formats and the multi-axis group behaviour are in PVAJList and PVAJStatus.

    See the PCSuite PVAJ control mapping and the PVAJ cookbook page.

    LockSrcZeroSupported¶

    static bool LockSrcZeroSupported(MotionController controller, AxisRef axisRef)

    Use a latch signal, normally the encoder index, as zero, optionally after a fast coarse search and before a slow latch search:

    Function First stage
    HomeToIndex none: a slow latch search straight away
    HomeToLimitThenIndex a fast search for the limit switch
    HomeToHardStopThenIndex a fast move into the mechanical stop, detected by a position error above hardStopThreshold

    EventCorrect¶

    static bool EventCorrect(MotionController controller, AxisRef axis)

    A standard table event (EventType = 2) triggers at unevenly spaced part features. Disarm first, then write EventTable positions in travel order. Set each output selection, pulse width, and the first and last indexes. Arm before the first trigger position. Use EventCorrect when the setup calls for corrected coordinates.

    Central-i verified tables¶

    The AAMotion .NET factory c.CreateEventTableClient('A') binds to the current connection and axis. Check verified-table support (Identity[62] mask 0x200), a compatible remote drive image, a commissioned encoder and event source, and LockEventStat = 1.

    1. LoadAsync uploads and reads back the definition and waits for controller-confirmed Ready. Then call ArmAsync. If it returns Armed, call WaitForCompletionAsync to confirm completion. Short sequences can complete before the host sees Running.
    2. After normal completion, call AbortAsync and confirm Aborted, then acknowledge the release to Empty. If the controller has retained an error, inspect that occurrence and use the corresponding AcknowledgeAsync overload.
    3. Cancellation or disposal ends the host operation. Confirm the controller state separately. Disconnect invalidates the old Ready result. RecoverAsync can confirm an abort only on the original live connection when takeover is allowed. Reconnecting requires checking the controller state before further action.

    static List<string> ScanController(bool fastScan, string subnet = null, int startIP = 1, int endIP = 254, int port = 50000)

    Scan the network for controllers

    SDK summary: Scan for available controllers on the network and return their IP addresses. Uses ARP-based discovery (via AAComm.Services.ARPTools.GetSubnetActiveIPs) which scans from all local Ethernet NICs on the target subnet, then validates each responder with TestConnection.

    Parameter Type Direction Default Description

    Central-i verified tables¶

    The AAMotion .NET factory c.CreateEventTableClient('A') binds to the current connection and axis. Check verified-table support (Identity[62] mask 0x200), a compatible remote drive image, a commissioned encoder and event source, and LockEventStat = 1.

    UploadParameters¶

    static void UploadParameters(MotionController controller, string filePath, Action<int> onProgress = null, Action<ParamHandlingSummary, string> onDone = null)

    The same as PCSuite's parameter upload / download. Upload reads every controller parameter and saves it, with a header (product, firmware / FPGA version, date, checksum), to a .par file. Download reads a .par file, validates it against the connected controller, writes each parameter, and optionally runs CalcFilters and Save to keep it in flash. Ethernet links use bulk commands (50 per packet). AAComm runs the transfer: the two C# methods return at once and report through callbacks, the completion callback receiving AAComm's ParamHandlingSummary (namespace AAComm.Extensions); the C functions block until the transfer ends. An uploaded file's header line reads // AAComm version: with AAComm's version.

    Upload and download parameter files

    SDK summary: Asynchronously reads all controller parameters and saves them to a .par file (controller disk -> local file). Follows the PCSuite "Parameters Upload" convention: queries every supported parameter, writes them with header (product type, firmware/FPGA version, date, file checksum) to a plain ASCII .par file. A parameter the controller refuses is left out of the file, named in a // Not uploaded: header line and in AAComm.Extensions.ParamHandlingSummary.Rejections; an empty reply fails the upload and writes no file. Ethernet connections use bulk messages (up to 50 per packet); other channels send one by one. The call is non-blocking; subscribe to the callbacks to be notified of progress and completion.

    Return type: void
