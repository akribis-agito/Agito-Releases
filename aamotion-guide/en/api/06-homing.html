    Homing¶

    Homing finds the axis's zero. Every homing function only starts the homing sequence in the controller and returns at once; the controller runs it, and the program polls IsHomed (that is HomingStat == 100) for completion. A negative HomingStat is a failure; each value is in Enums: Homing status.

    The controller's homing sequence is a table HomingDef[] of up to 20 steps with 10 parameters each: the first is the step type (find a limit, find the index, hit a hard stop, …), the others speed, acceleration, emergency deceleration, timeout and so on. The functions below fill the table for common cases and start it; or configure homing in PCSuite's homing tool and just call Home(c, axis).

    Method Function Use it when
    The sequence configured in the controller Home(c, axis) homing is set up in PCSuite
    Limit / index / limit + index Home(c, axis, isHomeToLimit, isHomeToIndex, …) the common case
    Hard stop HomeToHardStop no limit switches, a mechanical end stop
    Index only, limit + index, hard stop + index, stuck + index HomeToIndex and others you choose the lock source and direction
    Sequence from a file Home(c, axis, filePath) the sequence ships with the product's configuration

    Home with the configured sequence¶

    Three overloads:

    • 'Home(c, axis) starts the sequence already configured in the controller (AHomingOn=1).'
    • 'Home(c, axis, isHomeToLimit, isHomeToIndex, …) builds the sequence from its arguments: a limit only, the index only, or a limit then the index; the position found plus homeoffset becomes zero.'
    • 'Home(c, axis, filePath) writes the HomingDef[n]=value lines of a text file to the controller and starts. Lines starting with // are comments.'

    The axis must be motor-on (and commutated, for a synchronous motor) before homing.

    Check homing is done¶

    Reads HomingStat live (never through the FastReadCache) and returns true when it is 100. Poll it while homing runs, and also check whether HomingStat turned negative, which is a failure you need not wait out.

    Standalone demo: Homing state

    When to use it

    Polling after starting homing, or confirming zero is valid before moving.

    Signatures

    // AAMotionAPI
// Check if the axis is homed
// controller: The controller object / handle
// axis: One axis
// Returns: Returns true if homed, otherwise false
static bool IsHomed(MotionController controller, AxisRef axis);

// ISingleAxis
// Check if the axis has completed homing.
// Returns: Returns true if the axis has completed homing, otherwise false.
bool IsHomed();

    // @return true when the axis has completed homing.
// controller: The controller object / handle
// axis: One axis
bool aamotion_is_homed(aamotion_controller controller, int axis);

    Parameters

    Parameter Type Description
    controller MotionController / aamotion_controller The controller object / handle
    axis AxisRef / int One axis

    Returns

    true once homed.

    Notes

    • Track HomingStep and HomingStat while waiting. Status 0 means no homing since power-up or reset, a positive in-process status identifies the current step, and 100 indicates success.
    • Status -2 means a step timed out. Check that step's search direction, input, and timeout. Status -3 means the motor was unexpectedly disabled. Read ConFlt for the cause. Status -4 means the actual stop reason differed from what the step expected. Check the limit or latch signal used by that step.

    Example

    DateTime deadline = DateTime.UtcNow.AddMilliseconds(timeoutMs);
while (DateTime.UtcNow < deadline)
{
    if (AAMotionAPI.IsHomed(c, axis))
        return true;                                   // HomingStat == 100
    int stat = (int)c.GetValue(axis, eKeyword.HomingStat);
    if (stat < 0)
    {
        Console.WriteLine("homing failed: " + EnumPropertyHelper.GetHomingStatDes(stat));
        return false;
    }
    Thread.Sleep(100);
}
return false;

    static bool wait_homed(aamotion_controller h, int axis, int timeout_ms)
{
    for (int waited = 0; waited < timeout_ms; waited += 100)
    {
        if (aamotion_is_homed(h, axis))
            return true;                                   /* HomingStat == 100 */
        double stat;
        if (aamotion_get_value(h, axis, AAMOTION_KEYWORD_HOMING_STAT, 0, &stat) && stat < 0)
        {
            char text[256];
            aamotion_get_homing_stat_des((int)stat, text, sizeof text);
            fprintf(stderr, "homing failed: %s\n", text);
            return false;
        }
        sleep_ms(100);
    }
    return false;
}

    Home to a hard stop¶

    Without limit switches, the axis moves slowly until it presses against the mechanical end stop; a position error above threshold marks the stop, and that position plus homeoffset becomes zero.

    Standalone demo: Hard-stop homing

    When to use it

    Axes without limit switches but with a mechanical end stop.

    Index homing¶

    Use a latch signal, normally the encoder index, as zero, optionally after a fast coarse search and before a slow latch search:

    Function First stage
    HomeToIndex none: a slow latch search straight away
    HomeToLimitThenIndex a fast search for the limit switch
    HomeToHardStopThenIndex a fast move into the mechanical stop, detected by a position error above hardStopThreshold
    HomeToHardStopByStuckThenIndex a fast move into the mechanical stop, detected by motor stuck: velocity below stuckVel with current above stuckCurr for stuckTimeMs

    Each fills HomingDef[], starts the controller's homing sequence and returns; poll IsHomed for completion (see the chapter introduction). lockSource 0 selects the main encoder index (it needs LockSrcZeroSupported to return true; otherwise C# throws NotSupportedException).

    See the PCSuite homing controls and parameters.

    Standalone demo: Index homing

    When to use it

    When zero must repeat very precisely: a coarse search for a limit or hard stop, then a fine search for the encoder index. Without limit switches use one of the hard-stop methods, the detection the PCSuite homing page was commissioned with.

// ISingleAxis
// Simplified homing via hardware index signal: Motor On (30 s) → Configure Lock (30 s) → Jog to Index → Move to Lock → Disable Lock (30 s) → Wait (3 s dwell) → Set Position (30 s) → End. Direction logic: - `direction = 1` (Positive): Jog to index at `+slowSpeed`, move to lock at `+slowSpeed`. - `direction = -1` (Negative): Jog to index at `-slowSpeed`, move to lock at `-slowSpeed`. Emergency deceleration = `accel × 10`. Motion step timeouts are user-defined via `timeoutMs` (default 15000 ms). The motor-on, configure-lock, disable-lock and set-position steps carry a fixed 30 s step timeout, written as `30 × CurrentLoopSampleRate` servo samples: it bounds how long the controller's homing state machine waits for motor-on phasing, for the Lock hardware configuration, and for the background loop to apply the new position. The wait step is a fixed 3 s dwell (`3 × CurrentLoopSampleRate` samples), a step duration rather than a timeout.

    Returns

    The C# homing calls return nothing and throw on a bad argument (an ArgumentOutOfRangeException, for example, or NotSupportedException for lockSource 0 on a controller without it). The C homing calls return true when the sequence was written and started without error, and false for a bad argument or a refused write.

    LockSrcZeroSupported returns true when the controller can latch on the main encoder index (from its feature bit, Identity[62] mask 0x10).

    Notes

    • HomingDef is not scaled by User Units: every speed, acceleration and threshold is in controller units (counts, counts/s, counts/s², mA), even on an axis with User Units on.
    • In the two-stage methods, direction selects the initial search direction toward the limit or hard stop; the slow latch search then moves the opposite way. Pass positive speeds, accelerations and thresholds.
    • Check LockSrcZeroSupported before using the main encoder index. If it returns false, check which latch sources the hardware and firmware support before configuring homing.
    • Both hard-stop detections press the motor against the mechanical stop. Verify a first run at low speed with a conservative current threshold.

    Homing sequence from a file¶

    Home(c, axis, filePath) / aamotion_home_from_file write the HomingDef[n]=value lines of a text file to the controller, then start homing. It suits shipping the sequence with the machine configuration: tune homing in PCSuite, then copy the HomingDef elements into the file. Lines with an out-of-range index or a bad format are skipped.

    When to use it

    Shipping the homing sequence with the machine configuration instead of hard-coding it.

    Example

    // homing.txt: one HomingDef element per line ("HomingDef[1]=1", "HomingDef[2]=5000", ...); "//" starts a comment
AAMotionAPI.Home(c, AxisRef.A, @"C:\MyApp\homing.txt");

    if (!aamotion_home_from_file(h, AAMOTION_AXIS_REF_A, "C:\\MyApp\\homing.txt"))
    fprintf(stderr, "could not read the homing file or start homing\n");

    Read and write the homing table by step¶

    Every 10 elements of HomingDef[] are one step. a.GetHomingDefStep(n) returns a view of step n (from 1, up to 20): Type is the step type and Param1…Param9 its parameters; reading and writing them reads and writes the matching HomingDef elements, so you never compute indexes.
