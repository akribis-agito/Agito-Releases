ErrLog 

Gets the error log array. ErrLog[1] stores the error code, ErrLog[2] stores the error occurrence time (seconds since last power on).


Subsequent errors are stored in higher index positions. When more than 32 errors occur, old errors will be overwritten starting from index 1.


Error code format: Lower 24 bits are the error code, higher 8 bits indicate the related axis (0-no specific axis, 1-axis A, 2-axis B, etc.). 


When higher 8 bits are greater than 16, it indicates a user program error (17-thread 1, 18-thread 2, etc.). 


For detailed error codes, please refer to the ErrLog manual.

LoggerUpload()

Uploads slow logger data from the controller.

public string LoggerUpload()

Returns

string

Response string from log upload containing the data packets.

Remarks

Data Format:

The response string contains comma-separated integer values with the following structure:

  • First value: Number of data packets in this upload response
  • For each data packet (repeated):
    • Controller timestamp (in units of loggerGap * 16)
    • Parameter values (in the order configured by LoggerParams)
  • Last value: Always 0 (indicates end of data)

Timestamp Calculation:

The timestamp represents the sample time relative to when logging started.

Formula: timestamp = packetIndex * loggerGap * 16

Examples:

  • If loggerGap = 1: packet 0 = 0*1*16 = 0, packet 1 = 1*1*16 = 16, packet 2 = 2*1*16 = 32
  • If loggerGap = 10: packet 0 = 0*10*16 = 0, packet 1 = 1*10*16 = 160, packet 2 = 2*10*16 = 320

Example Response (loggerGap = 10, 4 parameters configured):

"3,160,62149,80,10,10240,320,62246,76,20,10240,480,62344,76,24,10240,0"

This means:

  • 3 data packets
  • Packet 1: timestamp=160, params=[62149, 80, 10, 10240]
  • Packet 2: timestamp=320, params=[62246, 76, 20, 10240]
  • Packet 3: timestamp=480, params=[62344, 76, 24, 10240]
  • End marker: 0

UploadDataLoggerDataNonblocking(out DataLoggerResult, Action<int>, int)

Non-blocking upload: Uploads recorded data using the RecUploadNext protocol. Unlike UploadDataLoggerData(out DataLoggerResult), this method does not block the communication channel, instead receiving data in sequential packets, allowing other commands to be interleaved. Suitable for multi-controller parallel upload scenarios, greatly improving overall throughput.
