UseUserUnits 

Gets or sets whether this controller expresses values in the connected controller's Global
User Units. Set it to <code>false</code> to keep every read and write in raw controller counts —
the escape hatch for an integration written against a counts-based API. Default <code>true</code>.


The setting survives connect and reconnect, so it can be configured before connecting: the
communication layer clears its own opt-out on every successful connect, and this controller
re-applies the value last assigned here once the connect succeeds.


Instance-wide, not call-wide — it forwards to <xref href="AAComm.CommAPI.SkipUserUnits" data-throw-if-not-resolved="false"></xref>, so two
controllers sharing one <xref href="AAComm.CommAPI" data-throw-if-not-resolved="false"></xref> share the setting. To bypass the scaling for
a single message, use <xref href="AAComm.Services.AACommMessage.SkipUserUnits" data-throw-if-not-resolved="false"></xref> instead.


What is read back is what the communication layer will actually do, so a direct write to
<xref href="AAComm.CommAPI.SkipUserUnits" data-throw-if-not-resolved="false"></xref> is visible here — but only a value assigned through
this property is remembered, and only that is re-applied at the next connect.


Opting out does not unlock raw User Units configuration writes: a direct assignment to a
<code>*UnitFct</code> or <code>*UnitUnt</code> parameter stays rejected either way.

public bool UseUserUnits { get; set; }

CheckConnection() 

Actively probes physical reachability via ICMP ping and returns the result. Unlike
<xref href="AAMotion.MotionController.IsConnected" data-throw-if-not-resolved="false"></xref>, this always sends a probe and can block for up to ~1 second — call
it deliberately (a background timer, a manual health check), never from a binding or a
property-style hot path.


Two independent probes are sent; either succeeding counts as reachable, so a single blocked
or rate-limited ICMP packet is not mistaken for a dead link.


For a connection made over a non-IP channel (Simulation, serial, CAN), or before any address is
known, ICMP has nothing to probe and this reports the logical state instead — the same value
<xref href="AAMotion.MotionController.IsConnected" data-throw-if-not-resolved="false"></xref> would return.


This never disconnects or reconnects anything by itself. Call <xref href="AAMotion.MotionController.TryReconnect(System.String%2cSystem.Boolean)" data-throw-if-not-resolved="false"></xref> to
recover a link this reports as down.

public bool CheckConnection()

ConnectSimulation(string, string, string, string, bool)

Connects to a locally spawned firmware simulation over the managed AAComm.Shared.ChannelType.Simulation channel.

public bool ConnectSimulation(string simExePath, string simProduct = "", string simVersion = "", string simMotorProfile = "", bool enableAutoReconnect = false)

Parameters

simExePath string

Absolute path to firmware_sim.exe. The SDK does not ship this binary — the caller must supply a path to an installed or bundled copy (for example under a PCSuite Simulations/<product>/<version>/ folder). A sibling sim.info is not read by this API.

simProduct string

Optional catalog product key (e.g. AGM800, AGD301). A name the catalog resolves also declares the controller type, so the connect verifies it against the sim rather than first discovering it with a probe that spawns a whole sim child of its own — and a declared type the sim disagrees with fails the connect. A name the catalog does not resolve leaves the type to that probe, as omitting it does — among them the ControllerType member names AGD155EC, AGD101EC, AGD156EC and AGM800EC, since this takes the catalog spelling (AGD155-EC) rather than the enum's.

simVersion string

Optional firmware-sim version label (e.g. 5.0.0).

simMotorProfile string

Optional motor/encoder profile (flat key=value text passed to the sim's --motor); empty uses the bundled generic default.

enableAutoReconnect bool

Recorded on AutoReconnectEnabled, and inert on a simulation link: TryReconnect(string, bool) cannot recover one (see the remarks).

Returns

bool

true when the server spawned the sim and the connect succeeded; otherwise false.

Remarks

AACommServer must already be running (Init()). On success it launches simExePath, configures the motor, and bridges loopback; on Disconnect() it reaps the child process. TryReconnect(string, bool) is Ethernet-only and cannot recover a simulation link: to reopen one, call Disconnect() first and then this method. This method does not tear down a link it finds open, and the connect short-circuits on one, so calling it alone on a wedged session returns false without reopening anything — though LastKnownAddress and AutoReconnectEnabled are recorded before the attempt, so a failed call still updates them.

GetValue(AxisRef, eKeyword, int)

The value keyword holds on axis, read through the controller, in the units that axis reads it in — GetUserUnits(AxisRef, eKeyword) says which, and answers counts when nothing scales it. index 0 reads a scalar parameter; 1 and up read one element of an array parameter, in the parameter's own indexing — an array parameter has no reading at 0, and a scalar one none at 1. LoggerUpload()

Uploads slow logger data from the controller.

public string LoggerUpload()

Returns

string

Response string from log upload containing the data packets.

Remarks

Raw: the controller's reply text exactly as received — no float resolution and no User Units scaling. For resolved, scaled values call LoggerUpload(params object[]) with the specifications given to ConfigureSlowLogger(int, int, params object[]).

Data Format:

The response string contains comma-separated integer values with the following structure:

  • First value: Number of data packets in this upload response
  • For each data packet (repeated):
    • Controller timestamp (in units of loggerGap * 16)
    • Parameter values (in the order configured by LoggerParams)
  • Last value: Always 0 (indicates end of data)

Timestamp Calculation:

The timestamp represents the sample time relative to when logging started.

Formula: timestamp = packetIndex * loggerGap * 16

Examples:

  • If loggerGap = 1: packet 0 = 0*1*16 = 0, packet 1 = 1*1*16 = 16, packet 2 = 2*1*16 = 32
  • If loggerGap = 10: packet 0 = 0*10*16 = 0, packet 1 = 1*10*16 = 160, packet 2 = 2*10*16 = 320

Example Response (loggerGap = 10, 4 parameters configured):

"3,160,62149,80,10,10240,320,62246,76,20,10240,480,62344,76,24,10240,0"

This means:

  • 3 data packets
  • Packet 1: timestamp=160, params=[62149, 80, 10, 10240]
  • Packet 2: timestamp=320, params=[62246, 76, 20, 10240]
  • Packet 3: timestamp=480, params=[62344, 76, 24, 10240]
  • End marker: 0

LoggerUpload(params object[])

Uploads the logger data and resolves it against the parameters the caller configured — the same specifications ConfigureSlowLogger(int, int, params object[]) took, in the same order — so every value comes back resolved and scaled the way every other read does. AAMotion keeps no record of the configuration; the caller supplies it. A null specification is skipped, as ConfigureSlowLogger(int, int, params object[]) skips it. An error reply raises ErrorOccurred and yields no packets.

public LoggerDataContainer LoggerUpload(params object[] parameterSpecifications)

Parameters

parameterSpecifications object[]

Returns

LoggerDataContainer

Exceptions

ArgumentException

A specification names no parameter this controller knows — a shape outside the three forms, or a CAN code missing from its message list, which ConfigureSlowLogger(int, int, params object[]) writes unchecked. Raised through ErrorOccurred first; nothing is sent.

FormatException

The reply does not carry one value per specification — the caller passed a different count than it configured — or a value cannot be decoded; also a name whose index is malformed (no closing ], a non-numeric index), from the same parser ConfigureSlowLogger(int, int, params object[]) uses.

UserProgramPrintReceived

Raised once per formatted line from a user-program printf push (FW v5+, AGM800 Ethernet). Each UserProgramPrintMessage carries wire fields plus Console-friendly Timestamp and DisplayText. Other push sources are ignored. Delivery is on a background thread (same as AAComm push). Adding the first handler while connected queries ATime once for the wall-clock boot; the same query runs on connect when a handler is already subscribed. A successful TryReconnect(string, bool) that rebuilt the link reopens delivery and re-queries ATime when a handler is still subscribed; the already-connected short-circuit only reactivates delivery.
