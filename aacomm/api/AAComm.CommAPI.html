An API for handling communication with the AACommServer executable.


The API provides low-level send/receive capabilities + special functionality.


All *synchronous* functions are mutually-locking, and should not be called from multiple threads


Proper work-flow: (see usage details at every function description)


0. subscribe to events: Long operations: <xref href="AAComm.CommAPI.OnLongOperationStarted" data-throw-if-not-resolved="false"></xref> / <xref href="AAComm.CommAPI.OnLongOperationEnded" data-throw-if-not-resolved="false"></xref>, General Error: <xref href="AAComm.CommAPI.OnCommsError" data-throw-if-not-resolved="false"></xref>, Push: <xref href="AAComm.CommAPI.OnPushMessageReceived" data-throw-if-not-resolved="false"></xref> (TBD)


1. <xref href="AAComm.CommAPI.StartAACommServer(System.String)" data-throw-if-not-resolved="false"></xref><p></p>

2. <xref href="AAComm.CommAPI.TestConnection(AAComm.Services.ConnectionData%2cSystem.Boolean)" data-throw-if-not-resolved="false"></xref> (not mandatory, can be used to determine <xref href="AAComm.Services.ConnectionData.ControllerType" data-throw-if-not-resolved="false"></xref>)


3. <xref href="AAComm.CommAPI.Connect(AAComm.Services.ConnectionData%2cSystem.Boolean)" data-throw-if-not-resolved="false"></xref><p></p>

4. <xref href="AAComm.CommAPI.Send(AAComm.Services.AACommMessage)" data-throw-if-not-resolved="false"></xref> and/or <xref href="AAComm.CommAPI.SendReceive(AAComm.Services.AACommMessage)" data-throw-if-not-resolved="false"></xref> (both safe from any thread, in any combination — independent FIFO pipelines for ordinary messages)


5. <xref href="AAComm.CommAPI.Disconnect" data-throw-if-not-resolved="false"></xref><p></p>

6. <xref href="AAComm.CommAPI.CloseAACommServer(System.Boolean)" data-throw-if-not-resolved="false"></xref> (not mandatory)

Re-reads the full User Units configuration (per-axis enable + every group's scaling factor and
units name) from the controller and refreshes the in-memory scaling cache.

OnCommsError

Fatal communication error. If AACommServer was closed unexpectedly the string is AACommServerNotRunning. Suppressed only when a SendReceive(AACommMessage) was in flight AND no concurrent async Send(AACommMessage) was in flight (sync caller observes via the SR return; mixed-mode fatals still fire). Invoked synchronously on the transport receiver thread — off-load long work via Task.Run. Do NOT call API functions from the handler; no Disconnect needed after.

public event Action<string> OnCommsError

Event Type

Action<string>

OnLongOperationEnded 

Fired when a long controller operation (Reset, Save, Load, SaveUser, EventCorrect) ends.


Parameters: <xref href="AAComm.Shared.LongOperationType" data-throw-if-not-resolved="false"></xref> identifying the operation, and the controller error
code — <code>0</code> means no error (the operation succeeded); a non-zero value is the controller
error code (e.g. <code>22</code> = "motor on"), or an unresolved-error sentinel when the operation
ended without a parseable reply (e.g. session teardown).


Fired only if the matching <xref href="AAComm.CommAPI.OnLongOperationStarted" data-throw-if-not-resolved="false"></xref> fired: a long op whose reply
lands within the start-grace window raises neither edge (see <xref href="AAComm.CommAPI.OnLongOperationStarted" data-throw-if-not-resolved="false"></xref>).


Do NOT call API functions while handling.


Event is invoked in a new Task.


Event NOT invoked if <xref href="AAComm.CommAPI.SendReceive(AAComm.Services.AACommMessage)" data-throw-if-not-resolved="false"></xref> method is used.


For Reset: NOT invoked if the Reset reply was an error, if reconnecting after reset failed, or if the API was disconnected while in reset progress.

public event Action<LongOperationType, int> OnLongOperationEnded

Event Type

Action<LongOperationType, int>

OnLongOperationStarted 

Fired when a long controller operation (Reset, Save, Load, SaveUser, EventCorrect) begins.


Parameter: <xref href="AAComm.Shared.LongOperationType" data-throw-if-not-resolved="false"></xref> identifying the operation.


For Save/Load/SaveUser/EventCorrect: NOT fired when the controller replies within a short
start-grace window — such a reply means the op was not long-running (e.g. an immediate ERR 22
rejecting a flash Save while the motor is on), and the reply surfaces its own result; the
matching <xref href="AAComm.CommAPI.OnLongOperationEnded" data-throw-if-not-resolved="false"></xref> is suppressed too.


Do NOT call API functions while handling.


Event is invoked in a new Task.


Event NOT invoked if <xref href="AAComm.CommAPI.SendReceive(AAComm.Services.AACommMessage)" data-throw-if-not-resolved="false"></xref> method is used.

OnPushMessageReceived

Raised when an unsolicited "push" message is received from the controller. The event delivers a parsed AACommPushMsgBase instance (created by AACommPushMsgBase.Parse) and is invoked on a background Task to avoid blocking the receiver thread. Handlers should be aware that multiple push messages may be received in quick succession, so code re-entry and thread-safety should be considered.

public event Action<AACommPushMsgBase> OnPushMessageReceived

Event Type

Action<AACommPushMsgBase>

OnUserUnitsEnabledChanged

Raised after the controller confirms (OK reply) a per-axis User Units enable/disable change, regardless of the path that sent it (API, Terminal, …). Fires only on an actual transition. The cache behind GetUserUnitsEnabled(char) is updated synchronously on the receiver thread before this fires, so handlers should re-read it rather than rely on event ordering. Invoked on a background Task (like OnPushMessageReceived); consider re-entrancy and thread-safety. Args: (axis, isEnabled).
