    Repetitive, two-speed and sine motion¶

    Variations on the point-to-point move:

    Motion Function MotionMode Use
    Repetitive MoveAbsRepetitive and others 2 burn-in, run-in, repeatability tests
    Two-speed MoveAbsTwoSpeed and others 1 + SpeedChgOn fast approach, slow arrival (pressing, alignment)
    Sine PTP SinePtpBegin 20 / 21 sinusoidal acceleration, less shock
    Change in motion SinePtpCommit, CommitMotion — new target or speed while moving, applied to several axes together
    PVAJ PvajWriteHeader … PvajBegin 22 / 23 follow a host-computed list of position, velocity, acceleration and jerk points
    Electronic gearing GearBegin 5 / 6 follow a master parameter at a fixed ratio

    Measure command return and arrival with the sample and verify the actual controller state.

    PVAJ trajectory motion¶

    When the host already has position, velocity, acceleration and jerk for every trajectory point, PVAJ motion makes the axis follow that list (MotionMode 22 for one axis, 23 for a member of a multi-axis group). PVAJ needs an AGM800 with firmware 5.3.0 or later. Support is a property of the controller, not of an axis: a controller whose message table carries PVAJList supports it on every motion axis. Check with PvajSupported / aamotion_pvaj_supported first; without it, the other PVAJ calls refuse before sending anything, with an error that names the missing feature.

    The normal order of calls:

    1. PvajWriteHeader: the point count (1 to MaxPvajPoints / AAMOTION_PVAJ_MAX_POINTS, 8192), the gap (1 to MaxPvajGap / AAMOTION_PVAJ_MAX_GAP, 32 base sample periods; above 1 the controller interpolates between the points with a quintic spline) and the position mode (Enums: PVAJ position mode).
    2. PvajWritePoint: one point at a time, from point 1. Every value must be finite.
    3. PvajValidate, normally the full check (Enums: PVAJ validation mode). After an edit to the list, validate again before the next arm; a trajectory snapshot already executing runs to its end.
    4. PvajArm. The axis disarms itself when the motion ends, so arm again before every motion.
    5. PvajBegin: sets MotionMode (22, or 23 with groupMember true) and starts the motion.
    6. PvajGetStatus: the state (Enums: PVAJ state), the point being executed and the points left. It always reads the controller live, never the fast read cache.

    ISingleAxis also exposes the keywords as properties: PVAJList, PVAJValidate, PVAJArm, PVAJStatus, PVAJPosTol and PVAJVelTol. The keyword formats and the multi-axis group behaviour are in PVAJList and PVAJStatus.

    See the PCSuite PVAJ control mapping and the PVAJ cookbook page.

    When to use it

    When the host plans the trajectory (from CAD or measurement data, say), gives velocity, acceleration and jerk for every point and needs the controller to follow it as given. Point-to-point and Sine PTP moves let the controller plan the profile and need no PVAJ.

    Returns

    C#:

    • PvajSupported: true when the controller has PVAJList.
    • PvajWriteHeader, PvajWritePoint: nothing. A value out of range or not finite throws ArgumentOutOfRangeException and writes nothing; a controller without PVAJ is reported on ErrorOccurred, then throws NotSupportedException; a write the controller refuses throws ControllerCommandException.
    • PvajValidate: true when the list is validated afterwards; otherwise false, with what failed on ErrorOccurred, such as 393 (position out of range) or 396 (position continuity). A refusal or a controller without PVAJ also returns false. A mode other than 1, 2 or 3 throws ArgumentOutOfRangeException.
    • PvajIsValidated: true when PVAJStatus[1] is 1 or more (validated, armed or executing).
    • PvajArm: true when accepted; false when unsupported or refused.
    • PvajGetStatus: the state, with the point index and the points left in the out parameters. Throws NotSupportedException on a controller without PVAJ.
    • PvajBegin: true when the motion started; false when unsupported or when Begin is refused, with the refusal on ErrorOccurred: 400 for an unarmed axis, 401 / 402 for a group. A refused MotionMode write throws ControllerCommandException.

    C: each function returns true on success and false for a value out of range or not finite, a controller without PVAJ, or a refusal; the error callback names the last two. aamotion_pvaj_write_header writes nothing when it returns false. aamotion_pvaj_validate returns true only when the list is validated afterwards (ERR 393–395 out of range, 396 / 397 position / velocity continuity).

    Notes

    • The list is written one value per round trip, about 32,000 round trips for 8192 points. Allow for that time with long lists.
    • When validation fails, check ranges, the continuity between neighbouring points and the units. The list is in counts.
    • Before Begin, make sure the axis is enabled, idle and commanded by nothing else; afterwards read back the final position and MotionReason.

    Example

    // points[k - 1] = { position, velocity, acceleration, jerk } in counts, counts/s, /s², /s³
if (!AAMotionAPI.PvajSupported(c))
    return;                         // needs an AGM800 with firmware 5.3.0 or later
AAMotionAPI.PvajArm(c, AxisRef.A, false);
AAMotionAPI.PvajWriteHeader(c, AxisRef.A, points.Length, 1, PvajPositionMode.Absolute);
for (int k = 1; k <= points.Length; k++)
{
    double[] p = points[k - 1];
    AAMotionAPI.PvajWritePoint(c, AxisRef.A, k, p[0], p[1], p[2], p[3]);
}
if (!AAMotionAPI.PvajValidate(c, AxisRef.A, PvajValidationMode.Full)
    || !AAMotionAPI.PvajArm(c, AxisRef.A)
    || !AAMotionAPI.PvajBegin(c, AxisRef.A))
    return;                         // the reason is on ErrorOccurred

for (int attempt = 0; attempt < 300; attempt++)
{
    PvajState state = AAMotionAPI.PvajGetStatus(c, AxisRef.A, out int index, out int left);
    if (state != PvajState.Executing && left == 0)
        break;                      // ended: check the position and MotionReason
    Thread.Sleep(100);
}

    /* points in counts, counts/s, counts/s^2, counts/s^3; count 1..AAMOTION_PVAJ_MAX_POINTS */
const int a = AAMOTION_AXIS_REF_A;
if (!aamotion_pvaj_supported(h))
    return 1;                      /* needs an AGM800 with firmware 5.3.0 or later */
if (!aamotion_pvaj_arm(h, a, false) ||
    !aamotion_pvaj_write_header(h, a, count, 1, AAMOTION_PVAJ_POSITION_ABSOLUTE))
    return 2;
for (int k = 1; k <= count; k++)
{
    const pvaj_point* p = &points[k - 1];
    if (!aamotion_pvaj_write_point(h, a, k, p->p, p->v, p->a, p->j))
        return 2;
}
if (!aamotion_pvaj_validate(h, a, AAMOTION_PVAJ_VALIDATE_FULL) ||
    !aamotion_pvaj_arm(h, a, true) ||
    !aamotion_pvaj_begin(h, a, false))
    return 3;                      /* the error callback names the refusal */

int state = 0, index = 0, left = 0;
for (int attempt = 0; attempt < 300; attempt++)
{
    if (!aamotion_pvaj_get_status(h, a, &state, &index, &left))
        return 4;
    if (state != AAMOTION_PVAJ_STATE_EXECUTING && left == 0)
        return 0;                  /* ended: check the position and MotionReason */
    sleep_ms(100);
}
aamotion_stop(h, a);
return 5;

    Electronic gearing¶

    Makes an axis follow a master parameter at the ratio RatioNumerator / RatioDenominator (C: ratioNumerator / ratioDenominator), writing the whole configuration and starting the motion in one call. The configuration is the C# AAMotionAPI.GearMotionConfig or the C aamotion_gear_config:

    Field Meaning
    Master / master The parameter followed, named with its axis prefix: "BPos" (B's encoder), "APosRef" (A's position command), "AAuxPos"; required
    RatioNumerator, RatioDenominator The ratio (written to MasterFact / MasterFactDen); 65536 / 65536 is 1:1, within the ranges the controller gives the parameters. Firmware without MasterFactDen divides by 65536 and takes only 65536 as the denominator
    Filter / filter The input filter in 64ths (MasterFilt), 1–64; 64 passes the master unfiltered, a smaller value filters more slowly. Direct gearing only
    MasterModRev / masterModRev The master's modulus: the master's own ModRev when it has one, 0 for none
    MotionMode / motionMode 5 direct: the geared master is the position command; 6 indirect: it is the profiler's target, so the axis's speed, acceleration, deceleration and jerk limit the motion

    It writes GearMaster, MasterFact, MasterFactDen (when the firmware has it), MasterModRev (when the firmware has it), MasterFilt (direct gearing only) and MotionMode, then sends Begin. Stop it with Stop / aamotion_stop.

    See the PCSuite gearing controls and parameters.

    When to use it

    One axis following another axis or signal at a fixed ratio. When the follower position must vary along the master travel by a curve, use ECAM instead.

    MotionMode = (int)MotionMode.GearDirect,
};

{

}

    Console.WriteLine("write refused, earlier writes stay: " + ex.Command);

    Repetitive motion¶

    Repetitive point-to-point motion uses MotionMode = 2 and dwells for msDwellTime milliseconds between strokes. Abs sets the first absolute target and Rel sets the first displacement. The ordinary overloads use the existing RptMode and RptCycles. Mode 0 alternates between the starting position and the target. Mode 1 adds the same displacement at each step. Use MoveAbsRepetitiveCycle to select bidirectional mode and bound the stroke count. StopRep stops after the current stroke.

    Two-speed motion¶

    Moves at speed1, then continues at speed2 from the change position to the target. The controller switches as the axis crosses the change position (SpeedChgOn, SpeedChgPos, SpeedChgNew), so the moment is exact and independent of communication delays. In the Abs forms the change point is an absolute position, in the Rel forms a distance from the start.

    Sine point-to-point¶

    Point-to-point motion on a sinusoidal acceleration profile (MotionMode = 20 single, 21 repetitive); the acceleration changes smoothly, with less shock than a trapezoid. SinePtpBegin writes every parameter of a SinePtpMotionConfig to the axis and starts; SinePtpCommit writes new parameters during the motion and applies them at once (MotionMode cannot change in motion, so a commit leaves it). The C interface has no such functions; write the parameters with raw commands and send ABegin / ACommitMotion.

    When to use it

    Vibration-sensitive loads (precision stages, long cantilevers) that need a smoothly changing acceleration.

    Change several axes in one step¶

    Write the new Sine PTP parameters to each axis first, then one CommitMotion(A | B …). The controller validates and recalculates every axis's profile in the same control cycle, so they all change together. If any axis in the mask is not in a Sine PTP motion, the whole commit is refused. It sends ACommitMotion=<axis mask>.

The controller validates the new profile within 16 control cycles (about 1 ms) and then joins the two profiles; position and velocity stay continuous across the splice, acceleration does not. Every kinematic parameter is read as one complete set describing the new motion, so write PreCruiseSpd = 0 to drop a pre-cruise phase the new motion no longer needs. A non-zero RelTrgt is measured from where the axis is at the splice, not from where the motion began. The controller's command names the axes it commits by mask, so this sends ACommitMotion=<this axis's bit>; MotionController.CommitMotion(AxisRef) commits several axes in one synchronised step. Returns: Returns true if the controller accepted the commit, otherwise false. A rejection is reported through MotionController.ErrorOccurred, for example error 48 (the axis is not in a Sine PTP motion), 387 (the motion ends before the splice could happen) or 388 (the recalculation did not finish in time).
    • aamotion_commit_motion — Commits the Sine PTP parameters already written to every axis in a mask in one synchronised step: the controller validates them all and splices every new profile on together. @param axes A mask of AAMOTION_AXIS_REF_* bits; the whole commit is refused when any of them is not in a Sine PTP motion.
